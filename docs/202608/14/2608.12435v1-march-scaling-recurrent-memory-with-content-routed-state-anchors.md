## 摘要
Transformer 的强大长上下文检索能力很大程度上归功于其随上下文长度增长的令牌级记忆。然而，这种灵活性在训练期间会带来二次方的计算复杂度，并在自回归推理期间导致键值缓存线性增长。递归替代方案通过将整个历史压缩为固定大小的状态来实现高效解码，但在召回密集型任务上往往表现不佳，因为较早的关联通常会被后续更新覆盖，仅保留最新的上下文信息。本文中，我们介绍了跨上下文历史的记忆锚点路由（MARCH），这是一种网络架构，可有效扩展状态空间模型的维度超越固定大小，同时保持长序列上的计算效率。MARCH 周期性地将累积的递归状态检查点缓存为状态锚点，并将每个锚点与一个紧凑的、内容条件的锚点键关联。这使得 MARCH 能够维护一个可随上下文长度增长的记忆库，在历史分辨率和记忆成本之间提供可控的权衡。在每个令牌处，MARCH 生成一个锚点查询，以关注所有因果可用的状态锚点，并将输出计算为对所有历史锚点沿当前状态的注意力式聚合。我们表明，经过标准预训练后，MARCH 在常识推理、LongBench 和上下文检索方面持续优于多种线性注意力变体。这些结果表明，内容路由的状态缓存显著增强了递归长程记忆，同时保留了其原生计算路径。

## Abstract
Transformers owe much of their strong long-context retrieval capability to a token-level memory that grows with context length. This flexibility, however, incurs a quadratic computation complexity during training and a key--value cache that grows linearly during autoregressive inference. Recurrent alternatives offer efficient decoding by compressing the entire history into a fixed-size state, but often underperform on recall-intensive tasks since earlier associations usually get overwritten by subsequent updates, and only the most recent contextual information is retained. In this paper, we introduce Memory-Anchor Routing across Context History (MARCH), a network architecture that effectively scales state-space models beyond a fixed-size dimension, while maintaining computational efficiency over long-sequences. MARCH periodically caches cumulative recurrent-state checkpoints as state anchors and associates each anchor with a compact, content-conditioned anchor key. This lets MARCH maintain a memory bank, which can grow as context length increases, providing a controllable trade-off between historical resolution and memory cost. At each token, MARCH produces an anchor query to attend all causally available state anchors, and the output is calculated as an attention-style aggregation over all historical anchors along the current state. We show that after standard pretraining, MARCH consistently outperforms multiple linear attention variants across commonsense reasoning, LongBench, and in-context retrieval. These results demonstrate that content-routed state caching substantially strengthens recurrent long-range memory while preserving its native computation path.

- **核心矛盾**：Transformer 和递归模型在长上下文建模中呈现出根本性的权衡。
  - **Transformer**：凭借随上下文长度增长的 token 级 KV 缓存，拥有强大的长上下文检索能力；但训练时计算复杂度为 O(T²)，推理时 KV 缓存线性增长，成本高昂。
  - **递归模型**（如线性注意力、状态空间模型）：将整个历史压缩为固定大小的状态，实现常数级内存的循环解码；但固定状态容量导致早期关联易被后续更新的信息覆盖，长程召回能力显著弱于 Transformer。
- **关键瓶颈**：递归模型采用“单状态”压缩，所有历史信息共享一个不断演化的状态矩阵，一旦旧的关联被遗忘或修改，模型无法从最新状态中恢复这些信息。
- **已有改进方向及其局限**：
  - *容量扩展*：增大单个状态矩阵的维度（如多分区状态），但仍受限于固定的状态空间维度。
  - *时间扩展*：保留多个历史状态版本（如 Log-Linear Attention），但**如何为历史检查点构建上下文相关的表示以实现高效、依赖查询的检索**仍未被充分探索。
- **MARCH 的定位**：在不修改底层递归机制的前提下，通过周期性地保存递归状态快照，并利用内容路由机制实现对这些历史状态的**选择性检索**，从而突破固定状态瓶颈，让记忆库随上下文长度增长。

## 2. 提出的方法论：核心思想与关键技术细节

### 2.1 核心思想
- **状态锚点（State Anchors）**：MARCH 周期性缓存累积递归状态的检查点（checkpoint），生成一组随上下文增长的状态锚点。每个锚点对应一个紧凑的、内容有条件的锚点键。
- **内容路由（Content Routing）**：每个 token 生成路由查询，对所有因果可见的状态锚点进行注意力式加权聚合，将历史状态读入当前输出。
- **设计哲学**：保留原始递归路径，通过**残差融合**添加历史检索分支，不干扰底层状态更新。

### 2.2 关键技术细节

**（1）连续递归状态锚定**
- **锚点放置策略**：设定边界序列 B = {b₁, ..., b_M}，在每个文本边界之后插入一个共享的可学习锚点嵌入 ξ 的实例。文本位置照常更新递归状态，锚点位置不修改状态，只读取对齐的状态检查点并提供路由元数据。
- **状态检查点**：在边界 b_m 处，将当前累积状态 S_bm 快照为锚点 A^(m,ℓ)（第 ℓ 层）。由于递归在锚点边界之间不重置，这些锚点编码的是到 b_m 为止的**累计历史**，而非仅当前片段。
- **内容条件锚点元数据**：锚点位置读入对齐的状态检查点，输出沿着标准输出投影和残差路径传播，使下一层的锚点表示依赖于对应状态的内容；这一跨层构造让路由键携带锚点状态的真实内容信息。

**（2）内容路由的历史读取**
- **路由查询与键**：文本 token 的归一化隐藏状态投影为路由查询 ρ_t = W_R x_t；每个锚点有一个路由键 κ_m = W_K u_m。锚点位置和文本位置共享同一投影矩阵（token 位置直接投影键和查询）。
- **因果可见性**：只对位置在当前 token 之前的锚点进行路由。
- **空路由（Null Option）**：增加一个可学习的空选项 ∅，其负载固定为零（A^(∅)=0），允许模型在**当前递归状态足够时抑制历史分支**。
- **求值过程**：
  - 计算路由 logit：s_t,∅ = w_∅^⊤ x_t + b_∅（空选项），s_t,m = ρ_t^⊤ κ_m（可见锚点）。
  - 使用 softmax 得到路由概率 π_t,j。
  - 输出 = 当前状态读出 + Σ π_t,j · A^(j) · q_t（历史聚合读出）。
- **残差融合**：历史读出作为辅助残差分支加到当前状态读出上，保留原生递归路径。

**（3）稀疏路由变体**
- 支持 Top-K 路由：仅聚合得分最高的 K 个可见锚点，显著降低聚合成本，与分层稀疏注意力方法有天然联系。

**（4）硬件高效实现**
- 采用类似 FlashAttention 的 I/O 感知融合策略：生产-读取两阶段计算，联合分块查询和锚点，在线 softmax，流式归约，避免物化稠密路由矩阵和逐锚点候选读出张量。

## 6. 主要结论与发现

- **一致提升**：MARCH 在常识推理（平均 41.5 vs GDN 的 40.1）、LongBench（14.9 vs 11.9，+25%）、上下文检索（23.3 vs 20.5，+14%）上均一致优于 GDN 和 Log-Linear GDN 基线。
- **NIAH 显著增强**：在 24 个任务-长度组合中，MARCH 在 19 个组合上超越更强的递归基线，5 个持平。在 32K 长度外推场景下，MARCH 在全部 6 个任务上取得最优结果，而 Transformer 和 Log-Linear GDN 全部归零。
- **多文档 QA 突出**：2WikiMultihopQA 相对提升 32%，MuSiQue 提升 45%，表明内容路由机制对需要跨文档关联检索的任务特别有效。
- **效率可控**：Top-4 稀疏路由在 128K 上下文下将训练吞吐量提升超 2 倍，核心运行时间降低约一个数量级，且性能几乎不损失（常识和检索任务）。
- **关键机制验证**：
  - 空路由选项去除后所有指标下降，说明“可绕过历史”的能力对整体性能至关重要；
  - 分块大小提供可控的精度-效率权衡，C=512 为最佳平衡点；
  - 路由维度 d_r=64 是精度与泛化能力的最佳折中。

## 7. 优点

- **理念简洁而有效**：不修改底层递归更新，只通过“周期性快照 + 内容路由读取”两个操作扩展记忆系统，改动代价低且易于落地。
- **内容路由优于索引路由**：锚点键跨层依赖锚点状态的实际内容，而非仅依赖时间位置，使得检索更具语义针对性。
- **原生可扩展性**：由于路由机制是内容相关的（而非索引相关），MARCH 天然支持长度外推——增加上下文长度只是增加锚点数量，不需要新的路由参数。
- **双分支保真设计**：残差融合保留了原始递归路径，历史检索作为辅助分支，模型可以自行决定何时需要历史记忆（通过空路由），避免强制检索的负面效果。
- **硬件友好**：I/O 感知融合内核支持高效实现，稀疏路由进一步提供效率-精度的灵活调节。
- **全面系统的实验验证**：从多维度基准到消融实验，覆盖了方法有效性和设计选择的各个层面。

## 8. 不足与局限

- **固定间隔锚定策略**：周期性均匀的锚点设置不感知状态变化的非均匀性——在状态稳定区域可能产生冗余锚点，而在状态剧烈变化区域可能分辨率不足。论文提出自适应锚定作为未来方向。
- **训练成本增加**：MARCH 相比原生 GDN 有额外的路由和读取开销，虽然通过稀疏化缓解，但在较短序列上仍不如原生 GDN 高效。
- **内存需求**：锚点缓存随上下文线性增长，原始固定状态空间模型的常数级内存优势被削弱。
- **仅验证学术规模**：实验限于约 700M 参数规模，未在 10B+ 或更大规模上验证；大规模预训练的适用性仍需进一步探索。
- **骨干模型单一**：主要实验基于 Gated DeltaNet，未展示 MARCH 在其它递归骨干（如 Mamba、RWKV、线性注意力）上的通用性。
- **部分长上下文任务仍有差距**：在 LongBench 和上下文检索上虽显著优于递归基线，但与 Transformer 的绝对分数仍有差距（如 LongBench Avg 14.9 vs Transformer 13.8/15.4 持平或略优，但上下文检索 23.3 vs Transformer 33.2）。
- **推理效率未详细评估**：论文聚焦训练效率，对自回归解码时锚点检索的额外成本未做深入分析。
