## 摘要
近期关于检索增强生成（RAG）的优化研究利用块级KV缓存重用来避免处理冗长的检索上下文以提高效率，但粗粒度块中仍存在大量信息冗余和噪声。本文通过提出CoinRAG（面向长上下文RAG的上下文信息碎片KV缓存重用），在低预填充延迟约束下优化帕累托前沿，同时最大化准确性。其名称隐喻地反映了我们的核心机制：就像将小代币（或“硬币”）组合成更大价值一样，CoinRAG组合式地重用离线计算的细粒度碎片缓存，以更语义相关且紧凑的方式高效形成学习到的上下文表示。具体来说，CoinRAG不进行全块编码，而是通过两阶段检索识别检索块中与查询相关的语义单元，并将它们的切片KV表示与块级上下文无缝组装。在LongBench多跳问答任务上的广泛评估表明，CoinRAG显著降低了运营成本，并在标准快速预填充延迟预算下，以新的帕累托前沿和平均5.3%的答案质量（F1）相对提升优于其他基线。

## Abstract
Recent optimization studies on Retrieval-Augmented Generation (RAG) have exploited chunk-level KV cache reuse to avoid processing long retrieved contexts for higher efficiency, while significant information redundancy and noise still remain in the coarse-grained chunks. This paper optimizes the Pareto frontier under low prefill latency constraints while maximizing accuracy by proposing CoinRAG (Contextualized Information Nugget KV Cache Reuse for Long-Context RAG). The name metaphorically reflects our core mechanism: much like assembling small tokens (or "coins") to accumulate a larger value, CoinRAG compositionally reuses offline-computed, fine-grained nugget caches to form a learned contextual representation efficiently in a more semantically relevant but compact manner. Specifically, instead of full-chunk encoding, CoinRAG identifies query-relevant semantic units within retrieved chunks through two-stage retrieval and seamlessly assembles their sliced KV representations with a chunk-level context. Extensive evaluations on LongBench multi-hop question answering tasks demonstrate that CoinRAG significantly reduces operational costs and outperforms the other baselines with a new Pareto frontier and an average 5.3% relative improvement in answer quality (F1) under a standard fast prefill latency budget.

### 一、核心问题与整体含义（研究动机与背景）

- **核心问题**：传统 RAG 在推理时需要在线编码大量检索到的文档块，导致极高的预填充（prefill）延迟，难以满足实际 Web 服务对 P99 延迟低于 100ms 的 SLA（服务水平协议）要求。为此，已有研究提出**块级 KV 缓存重用**（如 TurboRAG 等），将文档块预先编码、离线存储，在线推理时直接加载复用。但**块级粒度仍然过粗**：一个块中往往只有少数句子与查询相关，其余大量内容属于冗余或噪声，不仅浪费计算和内存资源，还会稀释注意力、降低答案质量。
- **研究目标**：在严格的低延迟预算约束下（P99 TTFT ≤ 100ms）最大化 RAG 的答案准确率，即构建一条更优的**准确率-效率帕累托前沿（Pareto frontier）**。
- **核心思想**：像用“硬币”凑成更大面额一样，**将粗粒度的块细化为多个细粒度“信息碎片”（nugget）**，离线提取并缓存这些碎片的 KV 表示；在线推理时，仅动态选择与查询最相关的碎片，将其组合成紧凑的上下文前缀，从而同时实现高质量和高效率。

### 二、方法论：核心思想与关键技术细节

CoinRAG 的完整流程分为**离线阶段**和**在线推理阶段**，具体包含四个核心技术组件：

1. **离线信息碎片提取（Offline Nugget Extraction）**
   - 将每篇文档切分为 512 token 的块（chunk），对每个块调用 LLM（GPT-4o-mini）提取候选信息碎片。
   - 每个碎片必须是原文中的**连续文本片段**，用其在原始块中的**起止 token 索引**表示，从而保证碎片可以精确定位到预计算 KV 缓存中的对应位置。
   - 提取采用三阶段匹配策略（Algorithm 1）：**A. 精确匹配**（碎片为原文子串直接采用）→ **B. 模糊匹配**（对 LLM 输出有细微改写的情况，在原文中寻找长度相近的窗口，计算相似度，超过阈值 τ=0.7 则接受）→ **C. 放弃**（相似度过低则丢弃该候选）。

2. **两阶段在线检索（Two-Stage Online Retrieval）**
   - **第一阶段（块级检索）**：使用稠密检索器（BGE-M3）从大规模语料库中取回 top-kc 个候选块。
   - **第二阶段（碎片级检索）**：仅在这 kc 个块内的预提取碎片集合中，基于碎片嵌入与查询的相似度排序，筛选出 top-k 个最相关的信息碎片。
   - 两阶段设计显著缩小了候选池规模，提高了检索精度。

3. **上下文化 KV 缓存组合与位置对齐（Contextualized KV Cache Composition with Position Alignment）**
   - 每个块在离线时被完整编码一次，其 KV 缓存被存储。在线时，利用碎片的 token 边界索引**直接切片（slice）**出对应位置的 KV 表示。
   - **关键优势**：这种切片得到的碎片 KV 表示保留了该碎片在原始完整块中的上下文语义（因为编码时碎片能看到块内前文），这与把碎片文本单独编码（隔离编码）有本质区别。
   - 由于不同碎片来自不同的块、位于不同的原始位置，其 RoPE 位置编码互不兼容。CoinRAG 采用**位置旋转算子 Rot(C; Δ)** 进行位置偏移对齐：
     - 块内保持原始 token 顺序，按检索排序将碎片连续拼接；
     - 第 i 个碎片的位置偏移量 Δᵢ 动态计算为：Δᵢ = |p| + Σⱼ<ᵢ (eⱼ − sⱼ + 1)，其中 |p| 为系统提示长度；
     - 通过这种**保序、连续的位置对齐策略**，上下文总长度被压缩到最小（跳过了未检索到的中间文本），降低 KV 缓存内存占用并加速解码。

4. **碎片感知微调（Nugget-Aware Fine-tuning）**
   - LLM 训练时面对的是连续文本，而推理时 CoinRAG 输入的是拼接的、非连续的碎片缓存，存在**训练-推理结构差距**。
   - 为解决这一问题，CoinRAG 在训练阶段**复现在线推理的碎片提取和组合流程**：在包含真实答案和干扰文档的训练集上，动态构造 top-k 碎片的前缀上下文缓存，然后以标准交叉熵损失训练模型生成答案。
   - 微调使用 LoRA/QLoRA 风格的低资源适配方案（8-bit Paged AdamW、梯度检查点等），并非全参数训练。

### 三、实验设计

- **实验数据集**：使用 LongBench 中三个**多文档、多跳问答（Multi-hop QA）**基准：
  - **HotpotQA**：需要跨文档推理和实体消歧；
  - **2WikiMQA**：涉及维基百科的多跳事实推理；
  - **MuSiQue**：需要多跳、多文档的信息合成。
- **评估指标**：
  - **准确率指标**：token-level F1-score（在约束模型输出简洁答案的提示词下，能可靠反映语义正确性）；
  - **效率指标**：TTFT（Time-to-First-Token）预填充延迟（均值与 P99）、预填充上下文 token 长度（作为 KV 缓存内存占用的直接代理）。
- **对比基线**（覆盖三类 RAG 范式）：
  - **Standard RAG**：完全在线编码检索块；
  - **CacheBlend**：块级 KV 缓存重用 + 选择性重新计算部分 token 以恢复跨块注意力；
  - **TurboRAG**：典型块级 KV 缓存重用（与 Block-attention 设计几乎相同）；
  - **KVLink**：在块内插入可训练链接 token 恢复跨块自注意力。
- **实验设置**：
  - 检索器为 BGE-M3，生成模型为 Qwen2-7B-Instruct；
  - 对每个方法扫描不同的检索块数 kc（及碎片数 k）绘制准确率-延迟帕累托曲线；
  - CacheBlend 额外扫描重算比例 r ∈ {0.0–1.0}；
  - 对 TurboRAG、KVLink 和 CoinRAG 使用相同数据、相同 epoch 数（1 epoch，277,280 个训练实例）进行微调以公平比较。

### 六、主要结论与发现

1. **低延迟预算下的显著优势**：在 P99 TTFT ≤ 100ms 的标准快速延迟预算下，CoinRAG 在三个数据集上的 F1 分别比最强基线 TurboRAG 提升 4.7%、0.5% 和 14.6%，**平均提升 5.3%（41.7 vs. 39.6）**，同时上下文长度缩短 1.84 倍。
2. **放宽延迟限制仍有竞争力**：去掉延迟限制后，CoinRAG 在 3 个数据集中 2 个仍优于所有基线，平均 F1 提升 5.2%（42.7 vs. 40.6），且上下文长度比 TurboRAG 短 6.8 倍。
3. **碎片级细粒度过滤的价值**：缩小上下文虽然牺牲了一部分跨块交互能力，但去除噪声和无关上下文带来的收益**在平均意义上超过了损失**，在低延迟预算下尤其显著。
4. **消融实验关键结论**：
   - 上下文化 KV 切片比隔离碎片编码的峰值 F1 高 3.9–6.3 分，说明保留块级上下文语义至关重要；
   - 两阶段检索比一阶段检索相对提升 9.6%–17.5%，且所选碎片更少、延迟更低；
   - 位置对齐在紧预算（P99 ≤ 75ms）下收益最大（F1 提升 3.0%–8.5%），预算放宽后与不对齐相当；
   - 碎片感知微调带来显著提升（+6.3 至 +11.3 分），有效弥合了非连续拼接结构带来的训练-推理差距。

### 七、优点

- **新颖的细粒度缓存重用范式**：突破了以往块级 KV 缓存重用的粗粒度限制，提出“离线提取 → 在线切片组合”的信息碎片级方案，**在 token 级粒度上实现了上下文压缩**；
- **兼顾质量与效率**：在降低预填充延迟和内存占用的同时提升答案质量，构建了更优的 Pareto 前沿，对实际 SLA 约束下的 RAG 服务有直接应用价值；
- **上下文语义保持**：通过 KV 切片而非隔离重编码，在压缩表示的同时保留了文档级上下文信息，这一设计被消融实验验证为关键贡献；
- **系统化的训练-推理对齐**：碎片感知微调针对拼接连贯性缺口进行校准，体现了对工程细节的深入考虑；
- **实验方法论扎实**：使用 Pareto 曲线评估而非单一配置对比，更全面地刻画了方法在不同预算约束下的表现；对训练配置进行了公平性控制（相同数据、相同 epoch）。

### 八、不足与局限

- **离线成本与存储开销**：预编码 KV 缓存需要大量磁盘存储（数百 GB 级），且引入非平凡的离线计算成本（LLM 提取 API 费用、微调 GPU 时间），虽然是一次性成本，但大规模语料上仍可能构成部署障碍。
- **模型强耦合**：预计算缓存与具体模型检查点绑定，更换或升级骨干模型需要**完全重新编码整个语料库**，限制了模型迭代的灵活性。
- **受检索召回上限约束**：答案质量受限于块级和碎片级检索的召回率，若两阶段检索未能命中关键证据碎片，即使有再好的上下文组合也无法生成正确答案。
- **缺乏跨块注意力**：不同块来源的碎片在编码时无法相互注意（与 TurboRAG 类方法相同的固有限制），在需要跨文档深层语义交互的复杂推理场景中可能损失部分推理能力。
- **实验覆盖有限**：仅验证了 3 个多跳 QA 数据集，未覆盖单跳 QA、对话式 QA、多轮交互等场景；未考虑查询间共享文档的 KV 缓存重用（作者明确说明这是未来工作方向）。
- **安全性未深入探讨**：论文仅提及检索文档可能包含恶意注入的提示词攻击，但没有系统的安全性分析和防御实验。
