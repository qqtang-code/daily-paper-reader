## 摘要
键值（KV）缓存是长上下文大语言模型推理中的主要内存瓶颈。现有方法从两个对立方向入手：逐出方法永久丢弃令牌，一旦被丢弃的令牌后来被证明是关键的，性能就会下降；而量化方法以低精度保留所有令牌，但压缩有限。我们提出AnchorKV，一种压缩方案，在不丢弃任何单个令牌的情况下将缓存缩小20倍。AnchorKV使用一组精确保存的锚点来表示缓存，通过每个令牌与最相似锚点的关系来表达其他所有令牌，并且仅精化那些近似对模型输出影响最大的令牌。AnchorKV在不同模型和数据集上始终保持准确性，在70B规模下保留了完整缓存得分的99%，同时以极低的成本保留整个上下文。

## Abstract
The key-value (KV) cache is the primary memory bottleneck in long-context LLM inference. Existing approaches attack it from opposite ends: eviction methods permanently discard tokens, degrading performance whenever a discarded token later proves essential, while quantization methods retain all tokens at low precision but offer limited compression. We propose AnchorKV, a compression scheme that shrinks the cache by $20\times$ without discarding a single token. AnchorKV represents the cache using a small set of anchors stored exactly, expresses every other token through its most similar anchor, and refines only those whose approximation most affects the model's output. AnchorKV consistently preserves accuracy across models and datasets, retaining 99% of the full-cache score at the 70B scale, while keeping the entire context at a fraction of its cost.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题定义**：在长上下文大语言模型推理中，KV缓存是主要的内存瓶颈。缓存随上下文长度和批大小线性增长，且在每一步解码时被完整读取。例如，在128K上下文下，单个Llama-3.1-8B请求的bf16缓存占16 GiB，与模型权重相当。缓存容量决定了设备能承载的并发请求数和生成速度。
- **现有方法的两难**：
  - **逐出（Eviction）方法**：如SnapKV、PyramidKV、AdaKV等，通过注意力分数等指标保留部分token、丢弃其余token。压缩率可极高，但决策在查询到来前做出，一旦被丢弃的token后来被证明是关键信息，性能会严重下降。这是该技术路线的主要失败模式（论文在第4.2节的per-task结果中证实这一点）。
  - **量化（Quantization）方法**：如TurboQuant，保留全部token但用更少比特表示。不丢失可达性，但准确性随比特数降低而下降，压缩率被限制在约5x，远达不到逐出方法的水平。
- **核心矛盾**：需要一种既能激进压缩、又不丢失任何token的方法。

## 2. 方法论：核心思想、关键技术细节

### 核心思想

- 在预填充阶段结束时，为每个KV头选取少量锚点（anchors）精确保存；每个其他token表示为与自身最相似锚点的缩放副本（投影系数），只需存储锚点索引和一个标量系数；
- 在给定字节预算下，为对注意力输出误差影响最大的位置额外存储量化残差；
- 不丢弃任何token位置，保证所有tokens都参与softmax计算，压缩后的缓存是精确缓存的扰动（perturbation）而非截断（truncation）。

### 关键技术细节

1. **锚点-残差表示**：
   - 锚点子集 A 精确保存，每个非锚点token分配至余弦相似度最高的锚点，并通过投影系数 γi = ⟨xi, xₐ(i)⟩ / ∥xₐ(i)∥² 和残差 ri = xi − γi xₐ(i) 表示；
   - 有残差的token重建为：x̂i = x̃i + r̃i（x̃i为投影，r̃i为量化残差）；
   - 键和值各自独立应用该表示，但共享相同锚点位置。

2. **残差量化**：
   - 2比特/坐标量化，先施加随机 Hadamard 变换分散能量（随机旋转），再用 per-token absmax 缩放和四电平 Lloyd-Max 码本量化；
   - 每个残差编码需要约 D/4 字节加1字节缩放。

3. **锚点选择**：
   - 保留最后的 W 个位置（recency window，同时充当观察查询）；
   - 其余锚点中 70%（ρ=0.7）按 SnapKV 式注意力分数选取（在宽度κ=7的核上池化），30%（1−ρ）从上下文均匀随机采样，以改善方向覆盖；
   - 键的投影在 RoPE 之前进行，因为旋转会降低方向相似度；评分使用 post-RoPE 键以反映真实注意力；解码时再将存储的键旋转。

4. **注意力输出感知的残差评分**：
   - 通过一阶泰勒展开推导出残差对注意力输出的近似影响：密钥误差通过注意力权重变化影响输出（受 Vt − y 调制），值误差直接影响输出；
   - 在不相干假设下，误差分解为逐 token 可加项，用 W(Hq/H) 个观察查询估计每个位置的效用 uKt 和 uVt；
   - 效用最高的位置优先获得残差；键和值各获得约一半残差预算，但跨头统一分配。

5. **字节预算与存储布局**：
   - 用户只需设置一个参数 θ（保留比例），精确的字节核算（式9）将预算转化为每层可存储的残差数；
   - 锚点以bf16存储，每层张量包括锚点键值、锚点位置、锚点索引、系数、残差掩码/前缀计数/头部偏移、位置ID、残差码与尺度等（Table 1 逐项列出并计入字节公式）；
   - 推理时直接解码压缩表示：FlashAttention式分块内核逐块重建键值并消费，永不物化稠密缓存。

- **主结果**：在9个模型-基准组合中，AnchorKV在10x和20x压缩率下全部为最高分；20x下得分超过所有逐出基线在10x下的得分 —— 即用一半内存可获得同等准确率。
- **随规模改善**：RULER-32K在20x时，Llama-8B/24B/70B分别保留FullKV得分的93.5%/95.3%/99.3%；70B下压缩缓存得分94.4，未压缩95.0 —— 模型越大，压缩损失越小，而缓存在大模型上最贵。
- **逐任务鲁棒性**：8B模型20x时，AnchorKV平均保留93%（6 vs 其他基线63/67/60）；在需抗干扰检索（cwe、single_3、multikey_3）任务上，超过最强基线45–88个百分点，从不超过16%的谷底提升至60%以上。
- **Needle测试**：5x压缩下AnchorKV平均0.94 vs 未压缩0.99；最强逐出基线AdaKV仅0.18。
- **效率**：20x目标下解码峰值内存降低约19x；长上下文（96K–128K）解码延迟达到与全缓存持平甚至略快（2–3%）；64K下并发请求容量翻倍，吞吐量提升1.26x。
- **理论保证**：论文给出输出误差界（式17），证明值误差是注意力加权均值型、键误差是极值型，且每个未修复token的键误差由其自身残差范数控制；同时证明保留全部token是上界更优的扰动而不是截断。

## 7. 优点

- **方法层面**：
  - 核心优势是“不丢任何token”：缓存变为精确缓存的扰动而非截断，从原理上避免了逐出方法的不可逆决策风险；
  - 锚点残差表示兼顾压缩率与保真度：每个token有独立系数，不会因共享表示而失去softmax可分性；
  - 残差分配直接以注意力输出误差为优化目标（一阶近似），而非仅凭注意力分数或残差范数等单一信号；
  - 仅预填充末尾运行一次压缩，注意力计算本身不改变，对模型是即插即用、无需训练/校准；
  - 用户仅需设一个旋钮（θ），工程部署友好；
  - 预RoPE键投影 + 解码时旋转的设计有理论依据（正交变换保持范数）且经实验验证；
  - 存储布局和字节公式逐项透明，可精确控制内存占用。
- **实证层面**：
  - 跨3种模型规模（8B/24B/70B）、3类基准、4种压缩率、逐任务级报告；
  - 消融实验系统且公平（等预算、只变一个变量、多个压缩率观察趋势）；
  - 对基线控制公平（KVPress框架、每层字节匹配）；
  - 效率分析详细，覆盖预填充开销、延迟、吞吐、并发等多维度，不回避开销。

## 8. 不足与局限

- **计算开销**：压缩在预填充末尾需进行一次全缓存扫描和效用估计，预填充增加约12–30%时间（32K时1.30x，128K时1.12x）。
- **生成的token不压缩**：解码产生的新token以bf16追加到精确窗口，随输出变长，实际压缩率从20x逐渐下降（60步后约19.3x）。论文说明了这一点，但未对生成token本身提供压缩机制。
- **残差预算有限时仍有退化**：最长上下文+浅层位置的needle检索（128K且深度最浅）出现部分失败，说明极早期token的覆盖仍需改善。
- **TurboQuant复现注水风险**：论文使用了社区复现版本而非官方实现（官方当时无公开代码），并修改了通道分配（保留top-k通道fp16），可能影响对比的严格性；但作者对此有充分交代和合理性解释。
- **未与混合方案对比**：未比较“逐出+主存离载/检索”类方法（如InfLLM/QUEST），这些方法也能实现高压缩率并还原被逐出的token，但需传输开销、且完整缓存仍占用主存。
- **批量维度**：实验均在batch size 1下评估离线指标；实际服务场景的调度需通过自行实现的Triton内核支持，尚未见到与vLLM等工业系统的集成验证。
- **理论假设的局限性**：效用推导依赖“不相干假设”（per-token残差零均值独立），理论错误界对键误差仅给出最坏情况控制，实践中需要依赖锚选择的覆盖质量（论文中也承认这一点）。
