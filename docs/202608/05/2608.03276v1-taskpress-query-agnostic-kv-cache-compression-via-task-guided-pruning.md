## 摘要
长上下文推理中，大语言模型受到键值缓存随序列长度线性增长的制约。尽管剪枝提供了一种缓解手段，但现有方法通常确定查询特定的词元重要性，无法在未见查询间复用。相反，我们提出TaskPress，一个任务引导、查询无关的KV缓存驱逐框架。TaskPress不针对单个查询优化缓存，而是基于高层任务引导构建可复用的记忆表示。该引导在预填充阶段充当元查询，在下游查询发出之前过滤不相关词元。此外，TaskPress利用量化缩放因子作为零成本信号来检测有影响的表示离群值，为词元重要性提供高效代理。在多项长上下文输入任务上的实验表明，TaskPress能够高效地创建跨多样查询的紧凑且可复用的缓存。

## Abstract
Long-context inference with large language models is constrained by the linear growth of the key-value cache to sequence length. While pruning offers mitigation, prevailing methods determine query-specific token importance that cannot be reused across unseen queries. In contrast, we introduce TaskPress, a framework for task-guided, query-agnostic KV cache eviction. Instead of optimizing the cache for a single query, TaskPress constructs a reusable memory representation conditioned on a high-level task guide. The guide functions as a meta-query during prefill to filter irrelevant tokens before downstream queries are issued. In addition, TaskPress leverages quantization scale factors as a zero-cost signal for detecting influential representation outliers, providing an efficient proxy for token importance. Experiments on conducted on various tasks with long context input demonstrate that TaskPress efficiently creates a compact, reusable cache across diverse queries.

## 1. 核心问题与整体含义（研究动机与背景）

- **问题背景**：大语言模型在长上下文推理场景中，Transformer 需要缓存中间 Key 和 Value 表示（即 KV Cache），其内存开销随序列长度**线性增长**，严重制约了吞吐量并导致内存饱和。典型的 KV 缓存大小甚至可超过模型权重本身。
- **现有方案的局限**：
  - **量化方法**（如 int4 KV cache）能降低单位存储成本，但不改变缓存长度随序列增长的基本趋势。
  - **KV 缓存剪枝方法**（如 SnapKV、PyramidKV、Quest 等）虽可显著压缩缓存，但大多依赖解码阶段的注意力动态计算 token 重要性，属于**查询依赖**（query-dependent）方法——压缩后的缓存**无法复用于新的查询**，在多轮或多查询场景下被迫反复进行昂贵的 prefill。
  - **上下文重建方法**（如 KVZip）虽实现查询无关，但需要将提示长度加倍进行重建，prefill 阶段引入严重的二次方计算开销（约 O(L²c)）。
- **核心难题**：如何设计一种**查询无关（query-agnostic）**的 KV 缓存压缩策略，既能高效复用压缩缓存，又不引入显著开销。
- **核心思想**：论文提出将 KV 剪枝从"查询时"（query-time）解耦到"任务时"（task-time），利用一个高层**任务指南（Task Guide）**作为"元查询"来引导缓存压缩。任务指南以更广阔的语义范围覆盖未来可能出现的多种查询，从而构造一个可复用的、任务级别的压缩记忆。TaskPress 还巧妙地将 KV 量化中**已计算好的缩放因子**作为零成本的离群值检测信号，用于衡量 Value 的重要性，进一步提升了压缩质量。

## 2. 方法论

### 2.1 核心思想

TaskPress 用任务描述（Task Guide）作为稳定的元查询，在 prefill 阶段对上下文进行重要性评估并驱逐不重要的 token，随后任务指南的 KV 被立即丢弃。下游任意查询均可复用此压缩缓存，实现查询无关的缓存压缩。

### 2.2 关键技术细节

1. **任务引导的 Key 重要性（Task-Guided Key Importance）**
   - 将任务指南（长度 Lt）拼接至上下文（长度 Lc）后执行 prefill，但任务指南的 KV 在 prefill 结束后立即丢弃。
   - 截取任务指南与上下文之间的注意力矩阵 A ∈ R^(Lt×Lc)，对任务维度求和并通过 1D 平均池化（核大小为 K）捕获局部依赖，得到 token i 的 Key 重要性分数：

     skey(i) = (1/K) · Σ_{k=-⌊K/2⌋}^{⌊K/2⌋} Σ_{j=1}^{Lt} A_{j,i+k}

   - 该得分只衡量 Key 的结构可检索性，不衡量 Value 的信息密度。

2. **量化缩放因子作为 Value 重要性（Quantization Scale as Value Importance）**
   - 自注意力是注意力的加权和与 Value 相乘，Value 向量本身的幅度同样是 token 重要性的关键指标。
   - 假设采用 per-token 量化（如 KIVI），缩放因子 γi = max(|vi|) / (2^(b−1) − 1)，其随 Value 最大绝对幅度单调递增。
   - 由于 bit-width b 恒定，γi 可直接作为 value outlier 得分：svalue(i) = γi。
   - 关键优势是**零成本**：量化已是高效 LLM 服务的标配，γi 已存在于内存中，无需额外计算。

3. **KV 综合重要性得分**
   - 最终得分按元素级乘积融合两个信号：**si = skey(i) · svalue(i)**
   - 乘法交互要求 token 同时满足两个条件：既要在任务对齐的注意力空间中**结构可检索**（高 Key 分），又要**语义信息丰富**（高 Value 离群分）。
   - 选取综合得分最高的 I 个索引集合作为压缩后的 KV 缓存。

4. **任务指南的构造**
   - **零样本初始化（已知任务）**：直接使用现成 LLM（如 Gemini）生成任务描述的简短摘要（2–3 句话），已展现强基线性能。
   - **进化式任务指南发现（未知任务）**：针对目标不可预定义的动态任务，从少量校准查询集 Dcal 中推断用户意图，通过进化算法（Algorithm 1）迭代优化：
     - 初始化：从校准查询生成 N 个初始候选指南；
     - 每一代：在 Dcal 上评估并按任务准确率保留 Top-K 候选，再通过 LLM mutator 进行变异与交叉，生成 N 个新候选；
     - 返回最终最优指南 T*。
   - 该过程离线进行，约 25.2 分钟完成（50 个校准样本）。

## 6. 主要结论与发现

1. **任务指南作为元查询有效**：即使仅使用零样本任务指南，TaskPress 也超越多数查询无关和依赖方法，LongBench 平均分在 LLaMA-3.1-8B 上于 50%/75% 驱逐率下均最高（46.42 / 43.08）。
2. **查询无关性与可复用性验证**：在 RULER 上 75% 驱逐率下 TaskPress 平均分（68.4）大幅领先 SnapKV（42.8）、PyramidKV（39.2）、ExpectedAttention（44.1）与 KVZip（62.2）。在 NarrativeQA/QMSum 上，TaskPress 与 query-dependent 的 SnapKV 性能相当或更好（75% 驱逐率下）。
3. **零成本 Value 离群信号有效**：量化缩放因子与 Value norm 强相关（r ≈ 0.79），与注意力基本正交（r ≈ 0.06），两者互补融合带来最优性能。
4. **进化发现任务指南可行**：完全未知任务下从查询集中进化出的指南性能接近甚至超过人工零样本指南；对已知指南进化微调可进一步提升准确率（最高 +3.08）。
5. **效率显著**：驱逐复杂度为 O(Lt·Lc)（相比 KVZip 的 O(L²c)），驱逐延迟提升 80×；75% 驱逐率下 TPOT 降低 35%、吞吐量提升 53%，prefill TTFT 仅增加 1.2%（64-token 指南）；多查询环境中端到端性能优于两种查询依赖权衡策略。
6. **鲁棒性良好**：任务指南对源模型（Gemini/Claude/ChatGPT）、措辞/改写变化稳健（标准差 < 1.3）；中等长度的指南效果最佳。

## 7. 优点

- **视角新颖**：首次将 KV 压缩从 query-time 解耦到 task-time，实现真正查询无关且低开销的压缩，填补了现有 query-dependent 与 context reconstruction 方法之间的空白。
- **零成本信号设计巧妙**：复用量化管线中已有的缩放因子作为 Value 离群值代理，既无需额外计算，又提供了与注意力正交的有效信息，是工程实践中的高性价比方案。
- **完整的任务指南构造方案**：兼顾已知任务（零样本 LLM 生成）与未知任务（进化搜索）两种部署场景，实用性强。
- **实验严谨且全面**：两个主流长上下文 benchmark（LongBench/RULER）、三种模型规模（8B/32B）、两种量化模拟（全精度/int4）、多种压缩率（50%/75%/16× 总压缩）、多维消融实验相互印证；对注意力稀释（MK-2/3）等失败案例进行了深入分析而非回避。
- **效率收益量化清晰**：从头到尾的实测——驱逐延迟、TTFT、TPOT、吞吐量、峰值内存、多查询端到端延迟——系统展示了实际收益。

## 8. 不足与局限

- **任务范围依赖**：TaskPress 在一个任务域内是查询无关的，但**仍是任务依赖的**。若用户查询严重偏离任务指南定义的语义范围，压缩缓存可能无法提供所需上下文。
- **注意力稀释敏感**：在人工构造的"needle-inside-needles"高密度场景（RULER MK-2/3）中性能显著退化。由于 softmax 归一化，目标 token 过多时注意力被分散导致误驱逐。虽然论文论证了此类密度在真实场景少见，并在附录中展示了在中等 needle 密度下性能稳健，但该弱点仍是结构性局限。
- **依赖量化统计**：离群值检测依赖预计算量化缩放因子；在 FP16/BF16 全精度场景中需在线计算 max|vi|（64K 上下文约增加 0.26 秒，约 2.7% 开销），虽微不足道但打破了"零成本"的绝对性。
- **RULER MK-2/3 表现不佳**：即使在 50% 驱逐率下（50.0/7.2），也不及 KVZip（99.8/78.4），是任务指南注意力稀释导致的具体弱点。
- **校准集来源**：进化式任务指南发现借用了测试集数据（50 个校准样本专门从测试集抽取后排除），实际部署中可能缺乏如此高质量的校准资源。
- **任务指南质量依赖外部 LLM**：初始化和变异依赖闭源 LLM（如 Gemini）API，引入外部依赖与潜在偏差；虽然在消融中显示了鲁棒性，但未系统评估不同来源模型的影响深度。
- **缺少真实多轮对话场景验证**：虽然分析了多查询收益，但基准实验（LongBench/RULER）本质上是单轮-多查询模拟，真实对话中的任务漂移、上下文演化等尚未在动态长会话中验证。
