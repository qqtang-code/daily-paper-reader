## 摘要
查询无关的KV缓存驱逐技术会一次性压缩上下文，并将得到的缓存复用于任意未来的查询，但在严格的预算下性能可能会崩溃。现有方法主要改进保留哪些原始KV对。我们引入了RestoreKV，它在相同的总KV预算下，用学习到的恢复来补充这种基于选择的公式。我们的关键见解是，尽管通过驱逐丢失的信息是上下文特定的，但生成其紧凑补全的机制可以在不同上下文之间共享。在上下文预填充后，少量恢复token在单次LoRA适配的传递中关注完整的KV缓存，生成一个紧凑的、上下文条件的恢复缓存。基础的重要性评分器和驱逐规则保持不变，适配器在后续所有查询和解码中均被禁用。RestoreKV通过冻结的全缓存模型的参数高效自蒸馏进行训练，仅优化0.4%的参数，且无需针对特定任务的调优。在四个骨干网络和四个长上下文基准上，RestoreKV大幅减少了压缩引起的性能下降。在Qwen3-4B上，它在五种基础驱逐方法的60个配对、预算匹配的设置中改善了59个；在5%的预算下，它在RULER-4K上将KVzip从38.2提高到73.2。应用于KVzip+时，RestoreKV在KVPress基准上以16倍压缩达到86.4的RULER准确率，同时在32K上下文评估中增加了不到0.5%的一次性缓存构建开销。我们的项目页面可在 https://paper.pnu-cvsp.com/RestoreKV/ 获取。

## Abstract
Query-agnostic KV cache eviction compresses a context once and reuses the resulting cache for arbitrary future queries, but performance can collapse under tight budgets. Existing methods primarily improve which original KV pairs are retained. We introduce RestoreKV, which complements this selection-based formulation with learned restoration under the same total KV budget. Our key insight is that, although the information lost through eviction is context-specific, the mechanism for generating its compact complement can be shared across contexts. After context prefill, a few restore tokens attend to the full KV cache in a single LoRA-adapted pass, generating a compact, context-conditioned restore cache. The base importance scorer and eviction rule remain unchanged, and the adapters are disabled for all subsequent queries and decoding. RestoreKV is trained through parameter-efficient self-distillation from the frozen full-cache model, optimizing only $0.4\%$ of the parameters and requiring no task-specific tuning. Across four backbones and four long-context benchmarks, RestoreKV substantially reduces compression-induced degradation. On Qwen3-4B, it improves 59 of 60 paired, budget-matched settings across five base eviction methods; at a $5\%$ budget, it raises KVzip from $38.2$ to $73.2$ on RULER-4K. Applied to KVzip+, RestoreKV reaches $86.4$ RULER accuracy at $16\times$ compression on the KVPress Benchmark, while adding less than $0.5\%$ one-time cache-construction overhead in a 32K-context evaluation. Our project page is available at https://paper.pnu-cvsp.com/RestoreKV/

# RestoreKV 论文详细总结

## 1. 论文的核心问题与整体含义

**研究动机与背景：**

- **问题背景**：大语言模型的长上下文推理严重依赖 KV 缓存，但其内存开销随序列长度线性增长。KV 缓存驱逐（KV cache eviction）通过在推理前保留少量 KV 对来降低成本。
- **关键概念**：查询无关驱逐（query-agnostic eviction）是一种特殊的压缩范式——上下文只需压缩一次，缓存可复用于任意未来的查询，无需预先知道查询内容。
- **现有局限**：该领域现有方法（如 KVzip、KVzip+、ContrastKV 等）本质上都属于**基于选择的压缩**——即想方设法选出"更好的"原始 KV 对子集来保留。但无论选择策略多好，在极低预算（如保留 5%）下，被丢弃的信息根本无法仅靠"选择"来挽回，导致性能急剧崩溃。
- **核心洞见**：虽然被驱逐丢失的信息是**上下文特定的**，但生成其"紧凑补偿"（compact complement）的**机制**可以在不同上下文之间共享。
- **论文定位**：RestoreKV 提出一个互补的视角——不仅学习"保留哪些 KV 对"，还学习一个共享的恢复机制，以生成紧凑、上下文条件的恢复缓存来补充保留的上下文缓存，在**相同总 KV 预算**下大幅缩小与全缓存性能的差距。

## 2. 论文提出的方法论

**核心思想：**

- 在上下文预填充后、驱逐执行前，用少量（默认 8 个）可学习的恢复 token（restore tokens）通过一次 LoRA 适配的前向传播，关注完整的 KV 缓存，生成一个紧凑的、上下文条件化的"恢复缓存"（restore cache）。
- 恢复缓存与基础驱逐器保留的上下文 KV 对共同构成最终缓存，**总预算不变**。

**关键技术细节：**

- **恢复缓存生成**：8 个恢复 token 的嵌入 E ∈ R^{n×d} 作为可学习参数，在上下文位置 T+1 到 T+n 处处理，因果访问完整 KV 缓存 C。通过 LoRA 适配（秩 r_LoRA=8，缩放因子 α=16）的注意力前向传播，每个 token 在每层每个 KV 头产生一个 KV 对，共产生 |C_res| = nLH 个 KV 对。
- **预算匹配**：RestoreKV 预留 B 个总预算槽位中的 nLH 个给恢复缓存，剩下的 B−nLH 个由基础驱逐器填充，保证总预算严格不变：|C̃| = (B−nLH) + nLH = B。
- **保留基础组件**：基础重要性评分器和驱逐规则完全不变，仅改变缓存构成。
- **推理阶段零开销**：LoRA 只在恢复缓存生成时启用，之后所有查询处理和解码均使用原始冻结骨干，不增加任何推断期计算。
- **训练目标**：通过从冻结的全缓存教师模型进行参数高效自蒸馏。使用同一上下文和查询，学生模型（使用预算匹配后的缓存）匹配教师模型（使用全缓存）的回答 token 分布，最小化对称 KL 散度。

**核心公式（文字说明）**：
- 总 KV 预算：B = ⌊rTLH⌋（r 为预算比率，T 为上下文长度，L 为层数，H 为 KV 头数）
- 保留缓存：C′ = Evict(C, s, B)
- 恢复缓存生成：C_res = Restore_{θ,ϕ}(E | C)
- LoRA 更新：ΔW = (α/r_LoRA)·B_ϕ A_ϕ
- 最终缓存：C̃ = Concat(Evict(C, s, B−nLH), C_res)
- 蒸馏损失：L_distill = (1/2M)·Σ_i [KL(p_full^i ‖ p_res^i) + KL(p_res^i ‖ p_full^i)]
- 训练预算采样：r ∼ U(0.025, 0.25)

## 6. 论文的主要结论与发现

1. **RestoreKV 在紧预算下大幅缩小与全缓存的性能差距**：在 Qwen3-4B、5% 预算下，RULER-4K 准确率将 KVzip 从 38.2 提升到 73.2（+35.0 点）；KVzip+ 从 51.6 提升到 70.7。
2. **通用兼容性**：对 5 种不同的驱逐方法（重建型、范数加权型、对比型、窗口型、重击者型）均有效，验证了其作为即插即用模块的通用性。
3. **注意力侧适配是主要收益来源**：固定嵌入 + LoRA 适配达到 71.9（恢复 96% 的全配置收益），而仅学习嵌入只达 42.1，证明恢复主要来自注意力侧生成上下文条件化缓存的能力，而非嵌入记忆。
4. **全上下文条件化具有补充价值**：从完整 KV 缓存（驱逐前）生成比从已驱逐缓存生成高出 8.8 点（73.2 vs 64.4）。
5. **上下文注意力恢复**：RestoreKV 将最终查询 token 对非注意力汇集的上下文 KV 对平均注意力质量从 0.56% 恢复到 1.30%，所有层级均高于 0.1% 阈值。
6. **开销可忽略**：32K 上下文中仅增加 0.03–0.04 秒（<0.5%）压缩时间和 84MB 峰值内存（0.4%），推理期 KV 内存和注意力延迟与基础方法持平。
7. **效率优势**：与 Attention Matching（强合成缓存基线）相比，在相当或更优精度下，4K 缓存构建速度约为其 13 倍。
8. **短训练长度可泛化到长上下文**：仅在 ≤15K 上下文中训练，在 ~104K 上下文的 SCBench 上仍一致提升。

## 7. 优点

**方法设计亮点：**

- **即插即用设计**：不改变基础评分器和驱逐规则，任何现有查询无关驱逐器均可直接叠加，兼容性极强。
- **预算严格保持**：恢复缓存不是额外开销，而是从现有预算中预留，与基础方法在相同 KV 内存条件下公平比较。
- **参数效率极高**：仅训练 0.4% 的参数（LoRA + 8 个嵌入），训练成本低（2 小时/模型）。
- **查询无关性保持**：恢复缓存生成不依赖任何未来查询，保持了下游推理的任意复用能力。
- **推理零额外成本**：LoRA 仅在单次恢复缓存生成时启用，后续查询与解码完全使用原始冻结模型。
- **独到的消融设计**：通过"固定嵌入"（用换行符嵌入替代学习嵌入）、"仅 q/k/v 投影"等精细对比，清晰定位了收益来源。

- 覆盖从 0.6B 到 8B 的多个规模与架构（Qwen3 系 + Llama）
- 严格的预算匹配原则保证公平性
- 控制实验（如 +8 位置偏移对照）排除了混淆因素
- 多种子稳定性验证（std < 0.57）
- 对比了强合成缓存基线（Attention Matching），展示了精度与速度的双重优势

## 8. 不足与局限

**实验覆盖方面的局限：**

- **训练数据均为英文**：仅使用 LongAlpaca、PG-19、Tulu-3 FLAN（英文），未涉及多语言场景，跨语言泛化未验证。
- **任务类型有限**：主实验四个基准集中在多项选择和合成任务，真实任务多样性有限（附录 LongBench 有补充但分析粒度较粗）。
- **训练-推断驱逐器绑定**：附录表 C 显示，当训练时用 SnapKV、推断时用 KVzip，紧预算下性能从 73.2 降至 42.0，说明跨驱逐器的迁移能力有限。
- **SCBench 实验虽然显示一致提升，但提升幅度小于中短上下文**（如 r=0.05 时 +1.5 点），长上下文下的恢复效果相对有限。
- **对于 0.6B 小模型的提升幅度**论文未做详细分析，小模型的恢复能力可能受容量限制。

**偏差风险：**

- **蒸馏"捷径"风险**：自蒸馏目标可能偏向于让恢复缓存迎合教师模型的输出分布，而非真正恢复上下文语义，存在表面拟合的可能性。
- **训练数据经教师生成**：教师生成的查询-答案对可能存在系统性偏差，训练分布与真实用户查询分布有差距。
- **基线选择偏乐观**：主要对比的 KVzip、KVzip+ 等方法本身在极低预算下性能崩溃严重（如 RULER-4K 仅 38 左右），RestoreKV 的提升空间天然较大；而在相对宽松预算（r=0.2）下提升有限（+2 点左右）。

**应用限制：**

- **KV 缓存压缩的单次性**：恢复缓存生成依赖完整 KV 缓存，对于流式/增量式长上下文仍需要一次性预填充完整上下文，不适合流式场景。
- **多层多头的缩放问题**：恢复缓存大小 nLH 随层数 L 和头数 H 线性增长，对于超大模型（如 70B+）其预算占用可能增加。
- **未与最新的并发工作全面对比**：虽然对比了 Attention Matching，但与其他并发合成缓存方法（如 VECTOR、Still、Latent Context Compilation）缺乏系统性比较，相对定位不够清晰。
