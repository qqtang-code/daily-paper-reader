## 摘要
使用大型语言模型（LLM）进行长上下文推理成本高昂：预填充期间的自注意力随序列长度二次增长，键值（KV）缓存随处理的标记数量增长。更大的上下文窗口也不能确保证据使用的可靠性。上下文压缩降低了这种成本，但许多软压缩方法使用LLM作为压缩器，并依赖紧凑记忆标记来保存信息和调节解码器。我们提出了SeDeM，一种选择性解压缩框架，将紧凑记忆存储与解码器调节分离。LLM从选定的中间Transformer层提取隐藏状态，轻量级压缩器将其存储为记忆块，查询条件选择器选择相关块，解压器仅将选定的块扩展为与中间解码器层兼容的隐藏状态。因此，解码器避免了全上下文处理和从高度压缩的记忆槽直接生成。在四个长上下文QA基准上，SeDeM在1B和3B同骨干设置中均优于评估的压缩基线，并且在3B骨干下在三个数据集上超过全上下文微调。学习的选择器在训练期间使用块级证据监督。SeDeM还相对于ICAE减少了在线首令牌时间并提高了自回归解码吞吐量。

## Abstract
Long-context inference with large language models (LLMs) is costly: self-attention during prefill scales quadratically with sequence length, and the key-value (KV) cache grows with the number of processed tokens. Larger context windows also do not ensure reliable evidence use. Context compression reduces this cost, but many soft-compression methods use LLMs as compressors and rely on compact memory tokens both to preserve information and to condition the decoder. We propose SeDeM, a selective decompression framework that decouples compact memory storage from decoder conditioning. An LLM extracts hidden states from a chosen intermediate Transformer layer, a lightweight compressor stores them as memory blocks, a query-conditioned selector selects relevant blocks, and a decompressor expands only the selected blocks into hidden states compatible with an intermediate decoder layer. Thus, the decoder avoids both full-context processing and direct generation from highly compressed memory slots. On four long-context QA benchmarks, SeDeM achieves higher QA scores than the evaluated compression baselines in both 1B and 3B same-backbone settings, and with the 3B backbone exceeds full-context fine-tuning on three datasets. The learned selector uses block-level evidence supervision during training. SeDeM also reduces online time-to-first-token and improves autoregressive decoding throughput relative to ICAE.

# SeDeM（论文中文总结）

## 1. 核心问题与研究动机

- **背景痛点**：LLM 长上下文推理成本高昂。预填充（prefill）阶段的自注意力计算量随序列长度呈**二次方增长**，KV 缓存大小随处理 token 数线性膨胀。
- **更大的上下文窗口并不保证答案质量**：模型在长输入中常无法可靠利用相关证据，尤其是当证据位于上下文中间位置时（"lost in the middle" 现象）。
- **现有压缩方法的缺陷**：许多软压缩方法采用"LLM 即压缩器"范式，把记忆/压缩 token 插入输入并让其在自注意力中反复更新。这种做法存在两个问题：
  1. 深层自注意力可能**覆写**浅层已聚合的信息，导致紧凑记忆偏离源内容；
  2. 解码器**直接消费**高度压缩的记忆槽（soft prefix），使其既要存信息又要充当解码条件，在高压缩率下性能受限。
- **核心研究问题**：如何设计一种框架，既避免解码器处理全量原始上下文，又避免直接从高度压缩的记忆槽生成，从而同时实现效率与选择性？

## 2. 方法论：SeDeM

### 2.1 核心思想
**将"紧凑记忆存储"与"解码器条件注入"解耦**。上下文被压缩成查询无关的记忆块存储；推理时按查询选择相关块；仅对选中块做**解压缩**，恢复为与解码器中间层兼容的隐藏状态再注入。解码器既不处理完整上下文，也不从压缩记忆槽直接生成。

### 2.2 三大组件

| 组件 | 功能 | 关键机制 |
|------|------|----------|
| **压缩器 Cθ** | 将每个上下文片段存为紧凑记忆块 | ① 冻结 LLM 编码器在前向抵达中间层 ℓ_extract，提取隐藏状态 H_s ∈ R^{T×d_enc}；② 按 C 个连续 token 一组做**局部均值池化**；③ 共享投影矩阵 W_in 映射至解码器隐藏维度，得到记忆槽 m_{s,j}；④ 每段形成记忆块 M_s ∈ R^{N_M×d_dec} |
| **Top-K 选择器 Rφ** | 选出与查询相关的记忆块 | ① 查询同样编码至 ℓ_extract；② **ColBERT 风格晚期交互**：R=4 个 scoring head，计算查询 token 与记忆槽的余弦相似度，块内取 MaxSim，跨 query token 求和、跨 head 平均得块分数 s_n；③ 选择分数最高的 K 个块 |
| **解压器 Dψ** | 将选中记忆块扩展为解码层可用隐藏状态 | ① 共享两层 MLP（LN→GELU→线性→线性），每个记忆向量 m_{s,j} 从 d_dec 映射为 C×d_dec；② 重塑为 C 个解码器空间隐藏状态；③ 拼接后得到片段重建 Ĥ_s ∈ R^{T×d_dec}；④ 注入解码器第 ℓ_inject 层后继续前向生成答案 |

### 2.3 训练目标（两阶段）

- **Stage 1（重建预训练）**：仅训练压缩器与解压器。损失为上下文窗口 next-token 损失 L_ctx + 蒸馏损失 L_distill（匹配解码器处理原始上下文的输出分布）+ 隐藏状态重建损失 L_rec（含逐 token 方向对齐 L_dir 与池化级对齐 L_pool）。
- **Stage 2（选择监督的任务训练）**：激活选择器与解码器 LoRA（rank=64, α=128），QA 生成损失 L_LM + 选择损失 L_ret（InfoNCE 项 + 成对间隔项，利用块级证据标签）+ 重建正则 L_rec。由于 Top-K 不可微，选择损失用于直接优化排序分数。

### 2.4 关键设计特点
- 压缩器**不向 LLM 自注意力插入任何可学习 token**，是轻量的局部池化+投影；
- 记忆是**查询无关**的，同一上下文可复用于多个查询；
- 计算量随选择预算 K 而非全上下文长度缩放；
- 支持**跨模型**使用（小编码器建记忆、大解码器消费）。

## 6. 主要结论与发现

1. **主结果**：在 1B 和 3B 同骨干设置中，SeDeM 在全部四个数据集上均**优于所有压缩基线**；3B 条件下在 2WikiMHQA、QASPER、HotpotQA-Distractor 上**超越全上下文微调参照**，仅在 MuSiQue 上低于全上下文微调。
2. **跨模型可行**：1B 编码器 + 3B 解码器在 2WikiMHQA 上（63.44）超过 3B 全上下文微调（62.50），证明记忆表示不限于同骨干。
3. **效率优势**：相对 ICAE，平均 TTFT 降低 1.74×（1B）和 2.46×（3B），解码吞吐提升约 1.06–1.11×。
4. **解压是核心增益**：直接记忆条件化（线性或更强 MLP 压缩器）均显著弱于选择性解压，说明增益来自"将选中记忆扩展为解码器兼容隐藏状态"而非压缩本身。
5. **记忆利用率更高**：有效秩显著高于 ICAE，说明记忆槽未坍缩为冗余表示。
6. **K 控制质量-上下文权衡**：不同数据集对选择预算敏感性不同——HotpotQA 偏好紧预算（K=2），2Wiki 可受益于更大 K 至 8 后饱和。

## 7. 优点

- **设计新颖性**：将"存储"与"解码条件注入"解耦，避免 LLM-as-compressor 的信息覆写问题，也避免解码器直接消费过压记忆。
- **工程效率**：压缩在 ℓ_extract 提前退出、片段级并行压缩、仅 K 块解压，在线成本受控；查询无关记忆可复用。
- **跨模型可迁移性**：分离了上下文处理成本与答案生成容量，支持小编码器+大解码器的灵活部署。
- **消融体系完整**：逐层拆解了解压、选择、LoRA、粒度、层深等因素，证据链条清晰。
- **分析视角多元**：除 F1/ROUGE 外，还提供了有效秩、FLOPs、参数开销、RULER 诊断等多维证据。

## 8. 不足与局限

- **依赖证据标签**：选择损失需要块级证据监督（四个数据集中恰好都有），无标签时只能退回选择器禁用模式，牺牲效率收益。
- **模型规模覆盖有限**：仅验证 1B/3B，未测试更大骨干（7B+）上是否保持质量与效率优势。
- **层选择缺乏原则性方法**：ℓ_extract 与 ℓ_inject 靠经验/诊断选取，未给出跨新骨干族的通用选择准则。
- **MuSiQue 上未超越全上下文微调**：多跳场景中更宽上下文仍有价值，固定 K 的机制不够自适应。
- **延迟协议保守**：TTFT 采用完全在线协议（不做文档侧缓存）；若允许预计算查询无关记忆，效率可进一步提升但未被评估。
- **随机性/统计细节缺失**：未报告多次运行的方差或显著性检验；部分表格存在修正后 ROUGE-L 缺失的情况。
- **长上下文范围有限**：未在超长上下文套件（如 32K/128K）或更广泛任务族上验证，外推能力未知。
