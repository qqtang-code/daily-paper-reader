## 摘要
大型语言模型（LLM）中的长上下文预填充会产生大量计算和内存流量，因为密集自注意力计算二次查询键分数。现有方法要么使用统一的低精度路径，要么选择token交互，将硬件对齐的分数块上的空间精度路由排除在融合密集注意力之外。我们引入了TileMix，一种以块为中心的精度路由内核，它将数值精度作为融合密集注意力中分数块组上的可执行空间决策。TileMix将注意力矩阵划分为硬件对齐的分数块，将路由决策打包成紧凑的位掩码，并通过FP16或INT8分数计算调度每个块组，同时两条路径都更新共享的在线softmax状态。可扩展的精度分组允许每个路由位控制多个相邻的键块，在长上下文中保留硬件对齐的计算块和紧凑的元数据。通过路由所有合法的块组，TileMix保留了密集的token连接性，无需训练，并支持分组查询注意力、可变长度批次和INT8键/值缓存。在LLaMA、Qwen和Vicuna上的LongEval、LV-Eval和A100预填充基准测试中，TileMix恢复了在统一INT8下丢失的长上下文质量，并提高了相对于FP16的预填充吞吐量，在多个模型家族中产生了可控的精度-效率前沿。实现可在https://github.com/HanzhiZhang-Ulrica/TileMix获取。

## Abstract
Long-context prefill in large language models (LLMs) incurs substantial computation and memory traffic because dense self-attention computes quadratic query-key scores. Existing methods either use a uniform low-precision path or select token interactions, leaving spatial precision routing over hardware-aligned score tiles outside fused dense attention. We introduce TileMix, a tile-centric precision-routing kernel that makes numerical precision an executable spatial decision over score-tile groups within fused dense attention. TileMix partitions the attention matrix into hardware-aligned score tiles, packs routing decisions into compact bitmasks, and dispatches each tile group through FP16 or INT8 score computation while both paths update a shared online-softmax state. Scalable precision grouping lets each routing bit govern multiple adjacent key tiles, preserving hardware-aligned compute tiles and compact metadata at long contexts. By routing all legal tile groups, TileMix preserves dense token connectivity, requires no training, and supports grouped-query attention, variable-length batches, and INT8 key/value caches. Across LongEval, LV-Eval, and A100 prefill benchmarks on LLaMA, Qwen, and Vicuna, TileMix recovers long-context quality lost under uniform INT8 and improves prefill throughput over FP16, yielding a controllable accuracy-efficiency frontier across model families. The implementation is available at https://github.com/HanzhiZhang-Ulrica/TileMix.

## 1. 核心问题与研究动机

*   **问题背景**：大型语言模型（LLM）在长上下文预填充（prefill）阶段，密集自注意力需要计算所有 query-key 分数，产生 **O(L²) 的二次复杂度**，导致巨大的计算量和 HBM 内存流量，成为长文档处理的主要瓶颈。
*   **现有方法的局限**：
    *   **量化方法**（如 INT8）通常采用**单一低精度路径**，注意力核在调用或阶段级别选择算术格式，缺乏对硬件对齐分数块的**空间精度路由**能力。
    *   **稀疏方法**通过选择 token 交互来减少计算（如 Sparse Transformer、BigBird），但会**改变注意力图**，丢掉部分合法连接。
    *   **IO 感知的融合注意力**（如 FlashAttention）用硬件对齐 tile 进行数据移动与工作划分，但**保留了统一的分数计算路径**，不能在不同 tile 组间混合精度。
*   **核心问题**：是否可以在**保持全部合法 token 连接**的前提下，在融合密集注意力内部，将分数块作为空间单元进行异构精度路由（FP16/INT8），从而兼顾精度与效率？

## 2. 方法论：TileMix 的技术方案

### 2.1 核心思想

*   TileMix 提出 **“以 tile 为中心的精度路由”**：把注意力分数矩阵划分成硬件对齐的分块（BLOCK_M × BLOCK_N），每个**键 tile 组**（key-tile group）通过一位 bit 决定走 FP16 还是 INT8 路径。
*   所有合法 tile 组都被计算，**不引入稀疏性**；精度选择独立于 token 连接合法性，实现“训练免”的密集连接混合精度注意力。

### 2.2 关键实现细节

*   **Tile 划分与分组**：保持 FlashAttention 风格的 outer loop（query tile）和 inner loop（key/value tile）。定义路由组宽度 `BLOCK_mask_N = g · BLOCK_N`，其中 `g` 为分组因子，一个路由位可控制相邻的 `g` 个计算 tile。每个 query-tile 行最多有 64 个组，因此每条路由信息可以打包进一个 64 位整数。
*   **位掩码打包**：对每个 KV 头 `hk` 和 query tile 行 `m`，把组决策打包为：
    `b_{hk,m} = Σ R_{hk,m,gj} · 2^{gj}`，总元数据量 O(H_k · T_m)。
*   **常数时间查找**：在内部循环中，通过移位和按位与操作 `R = (b >> gj) & 1` 常数时间获取算术路径，保证延迟关键路径的规整性。
*   **混合精度分数计算**：
    *   FP16 路径：`S = Q_m K_n^T / √d`，使用 FP16 Tensor Core。
    *   INT8 路径：先对 Q/K 做逐块对称量（Blockwise absmax INT8），得到 Q8、K8 与缩放因子 `δ_Q、δ_K`，用 INT8 MMA 计算并 INT32 累加，再还原得到 `S = δ_Q δ_K (Q8 K8^T) / √d`。
*   **共享在线 softmax 状态**：两条路径产生的分数进入**同一个 FP16 在线 softmax 递归**（维护 running max `m`、normalizer `z`、输出累加器 `O`），保证数值一致性。所有合法 tile 组均贡献到共享状态。
*   **可扩展性**：`g` 可随上下文长度增大，使单个 64 位路由字覆盖更长序列；同时计算 tile 保持硬件对齐。
*   **工程支持**：
    *   GQA：每个 query head 映射到对应 KV head 的路由决策。
    *   可变长度 batch：通过 `cu_seqlens` 和前缀和元数据实现无填充执行。
    *   INT8 KV cache：提供 decode 阶段的缓存接口（K8/V8 与 per-block scale）。

### 2.3 路由策略

*   使用静态、无数据的结构化模板定义路由图 `R`（同层层间、跨 batch 共享），例如：
    *   `One`（全 INT8）、`Zero`（全 FP16）
    *   `Band`（局部带状 FP16）
    *   `Global`（固定全局 FP16）
    *   `RowRandom`（逐行随机 FP16）
    *   `AlignedSparse`（右对齐扩展 FP16 区域）
    *   `BigBird`（带状 + 全局 + 随机的组合）
    *   `SpTrans`（Sparse Transformer 风格：局部 stride + 每个 stride 尾部若干位置）
*   控制 INT8 覆盖率 `ρ_INT8`（实验用 25%、50%、75%），但覆盖率指合法 tile 组的比例，不是 FLOPs 比例。

## 6. 主要结论与发现

*   **统一 INT8 过于粗糙**：`One`（全 INT8）在 LV-Eval 上普遍低于 FP16，显示均匀低精度路径不适合长上下文 QA。
*   **TileMix 恢复质量**：混合路由，特别是 `SpTrans`、`BigBird`、`RowRandom` 布局，相较 `One` 能显著缩小与 FP16 的差距，甚至部分设置下超过 FP16（如 LLaMA 在 `factrecall_en` 16k 上出现跨模型的 `SpTrans25/50/75` 高分）。
*   **效率提升明显**：以 LLaMA 3.2 3B 在 4k 长度为列，FlashAttention 吞吐 14.33 K tokens/s，`One` 29.80，`SpTrans75` 达到 31.80 K tokens/s；约是 FlashAttention 的 2.2 倍。
*   **数值可控**：输出偏差随 INT8 覆盖率增加而增大，0% 时接近 FP16；覆盖率是可控的精度-效率旋钮。
*   **结构布局与任务的交互**：`sptrans` 在 16k `factrecall` 上表现突出，且跨 LLaMA、Qwen 系列稳定出现，说明布局-任务交互是真实存在的。
*   **大模型稳定性**：FP16 与 FP32 累加在 LLaMA 3.1 8B、Qwen 2.5 14B 上逐层差异在 10⁻²~10⁻⁴ 量级，小于路由精度效应；FP16 累加可接受。
*   **重型交互保护**：静态 SpTrans 布局在名义 25% INT8 下，只将约 8.5% 的 heavy-hitter 注意力质量暴露给 INT8，能有效保护高重要分数不出现在低精度路径。

## 7. 优点

*   **创新性强**：首次在**融合密集注意力内部**做空间精度路由，将精度选择变成“可执行的决策”，而非调用级或张量级选择。
*   **保持密集连接**：不改变注意力图，不需要训练，部署友好。
*   **高效的工程实现**：紧凑位掩码、常数时间查找、O(H_k T_m) 元数据、组分组支持长序列，兼顾灵活性与内核规整性。
*   **完备的扩展支持**：GQA、可变长度 batch、INT8 KV cache 一并处理，实用性高。
*   **实验系统全面**：覆盖模型、基准、布局、覆盖率、数值稳定性、内存 accounting 等多个维度，结果可复现（开源代码链接）。
*   **清晰的精度-效率前沿**：暴露了可调的 `ρ_INT8` 作为控制器，便于使用者按需权衡。

## 8. 不足与局限

*   **硬件范围有限**：仅在 NVIDIA A100 上实现与评估，未验证 H100/Ada 等新型 GPU；其他格式（如 FP8/INT4）需要格式相关的 scale 处理和调度。
*   **静态路由模板**：当前策略均为静态、无数据的模板，没有根据实际注意力分布进行自适应选择；一些特殊“反直觉”结果（如 16k factrecall 上的 SpTrans 高分）暗示固定布局可能**碰巧**对特定任务有利，泛化性风险存在。
*   **计算量覆盖口径**：INT8 覆盖率按照 tile 组数量统计，而非实际 FLOPs；在长上下文下可能造成对收益的误读。
*   **评价指标局限**：LV-Eval 的 64k 结果普遍下降，但模型上下文能力的边界可能混淆精度路由的贡献；Vicuna 仅测到 16k，代表性不足。
