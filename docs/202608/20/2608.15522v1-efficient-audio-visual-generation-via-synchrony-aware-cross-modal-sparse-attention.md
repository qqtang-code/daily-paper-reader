## 摘要
最近的音视频生成模型能够在一个统一的扩散过程中合成同步的视频和声音，但由于长视频令牌序列需要在去噪步骤中重复进行注意力计算，其推理成本仍然很高。针对视频生成模型已经开发了多种加速技术，包括低位量化、注意稀疏化和特征缓存。然而，由于这些方法最初是为视频生成设计的，直接将它们应用于音视频模型会忽略音频和视频分支之间的交互，因此可能破坏音视频同步。我们提出了一个用于高效音视频生成的同步感知加速框架。我们的关键观察是，双向音视频交叉注意力揭示了两个分支之间的结构化交互，高响应通常集中在少数与声音相关的视觉和时间区域。在这种交互模式的指导下，我们引入了一种受保护的稀疏注意力策略，该策略为同步关键的令牌保留高保真计算，同时稀疏化冗余的注意力交互。通过在加速过程中明确考虑跨模态依赖，我们的方法在保持视频质量、音频质量和音视频同步的同时，提高了推理效率。

## Abstract
Recent audio-visual generation models can synthesize synchronized video and sound in a unified diffusion process, but their inference cost remains high because long video token sequences require repeated attention computation across denoising steps.A variety of acceleration techniques have been developed for video generation models, including low-bit quantization, attention sparsification, and feature caching.However, since these methods are originally designed for video generation, directly applying them to audio-visual models overlooks the interactions between the audio and video branches and may therefore disrupt audio-video synchronization.We present a synchronization-aware acceleration framework for efficient audio-visual generation.Our key observation is that bidirectional audio-video cross-attention reveals structured interactions between the two branches, with high responses often concentrated on a few sound-related visual and temporal regions.Guided by this interaction pattern, we introduce a protected sparse attention strategy that preserves high-fidelity computation for synchronization-critical tokens while sparsifying redundant attention interactions.By explicitly accounting for cross-modal dependence during acceleration, our method improves inference efficiency while keeping video quality, audio quality, and audio-video synchronization.

## 1. 论文核心问题与整体含义

**研究背景：**
- 音视频联合生成模型（如 Ovi、Harmony、LTX-2）能够在统一的扩散过程中同时合成视频和音频，使音画同步成为生成目标的一部分，而不再仅仅是后处理环节。
- 这类双流（dual-stream）架构模型引入了双向交叉注意力（bidirectional cross-modal attention）来实现音视频信息交换，推理成本远高于视频生成模型。
- 长视频 token 序列需要在多个去噪步骤中反复进行密集注意力计算，且视频 token 数量远大于音频 token，导致推理延迟极高。

**核心问题：**
- 现有的视频生成加速方法（如稀疏注意力、特征缓存、量化等）是根据单一模态内部的冗余性来设计加速决策的。
- 直接将这些模态无关（modality-agnostic）的加速方法迁移到音视频生成模型中，会忽略跨模态交互的重要性，可能把对音画同步至关重要的关键 token 或计算稀疏化或复用掉，从而破坏音视频对齐。

**核心含义与 Insight：**
- 作者的核心洞察是：**跨模态注意力的高响应集中在少数与声音相关的视觉区域和时间区域上**，这种非均匀的交叉注意力模式本身就可以作为同步关键内容的天然重要性信号。
- 因此，加速决策应**显式考虑双模态交互**，区分哪些计算可以安全近似、哪些计算承载关键跨模态证据。
- 整体意义：提出了一种**训练无关（training-free）** 的同步感知加速框架，在提升推理效率的同时保持视频质量、音频质量与音画同步。

## 2. 论文提出的方法论

### 2.1 总体框架

该框架包含三个核心组件，并以跨模态注意力中的显著交互模式作为共享指导信号：

1. 双向交叉模态显著性估计与滞后重用；
2. 同步感知的受保护稀疏注意力（Protected Sparse Attention）；
3. 同步感知的缓存重用机制（Synchronization-Aware Cache Reuse）。

### 2.2 双向交叉模态显著性估计与滞后重用

- 在音频→视频方向，音频 queries 与视频 keys 的注意力权重经过 softmax 后，将注意力质量在音频 queries、注意力头、选定层上聚合，得到视频 token 的显著性图：

  **sᵥ,ᵢ = Norm( Σ_ℓ Σₕ Σⱼ A^(a→v,t,ℓ,h)[j, i])**

- 视频→音频方向同理，获得音频 token 的显著性。
- 基于显著性分数，选择保护 query 集合：

  **Pᵥ = TopK({sᵥ,ᵢ}ᵢ₌₁..Nᵥ, ρᵥ·Nᵥ)**

  其中 ρᵥ 是较小的保护比例。

- **滞后显著性重用（Lagged Saliency Reuse）**：Ovi 式融合块中，视频自注意力先于音频-视频交叉注意力执行，因此当前交叉注意力图不能直接指导已经执行的自注意力。作者使用指数滑动平均对显著性图进行缓存：

  **s̄ᵥᵗ = α·s̄ᵥᵗ⁻¹ + (1−α)·sᵥᵗ**

  每 K 步更新一次，利用相邻去噪步骤中显著区域变化平滑的特性，在局部时间窗口内复用。

### 2.3 同步感知的受保护稀疏注意力

- 标准稀疏注意力为每个 query 限制其访问的 key 子集（掩码 Mᵐ），计算近似注意力输出。
- **保护机制**：根据缓存的显著性图，识别出高显著性的 query 集合 **Pᵐ**，对这些 query **恢复完整的 dense key 连接**，即保留完整注意力行：

  **Oᵐᵢ = DenseAttn(qᵐᵢ, Kᵐ, Vᵐ), 若 i ∈ Pᵐ；否则 SparseAttn_S(qᵐᵢ, Kᵐ, Vᵐ)**

- 这一保护不仅保留了选中 token 的值，更重要的是保留了这些 token 的高保真表示更新——声音相关的视觉 token 在与音频分支交互前，能聚合完整的视觉上下文；与同步相关的音频 token 同理。低显著性的 query 继续走稀疏计算路径。

### 2.4 同步感知的缓存重用机制

- 特征缓存方法利用跨相邻去噪步骤的特征冗余来复用中间表示。但模态无关的缓存标准可能存在风险：小的全局特征差异不意味着跨模态依赖未改变（如嘴部运动、物体接触可能只涉及少数 token，但对同步至关重要）。
- 因此作者提出**同步感知的缓存指示器**：

  **∆sync_t,ℓ = max( ∆v_t,ℓ, ∆a_t,ℓ, λₚ·∆p_t,ℓ, λₛ·∆s_t )**

  其中：
  - ∆v、∆a：视频分支和音频分支的流级特征相对变化；
  - ∆p：受保护区域的特征变化（对同步关键区域敏感）；
  - ∆s：当前与缓存交叉模态显著性图之间的余弦漂移（防止跨模态依赖变化时复用）。

- 仅当 ∆sync < τ 时才复用块输出；只应用于中间去噪步骤和中间层块，扩散特征更稳定，复用更安全。

### 2.5 复杂度

- 视频自注意力的评分计算复杂度从 O(H·Nᵥ²·dₕ) 降为 O(H·(κ·Nᵥ² + ρᵥ·Nᵥ²)·dₕ)，其中 κ 为稀疏保留比例，ρᵥ 为保护比例（默认约 5%），保护开销有限。
- 大型方法整体采用训练无关（training-free）方案，直接适配开源双流音视频生成模型。

## 6. 论文的主要结论与发现

1. **跨模态交互具有高度结构化和非均匀性**：双向音视频注意力中，高响应集中在少数与声音产生相关的视觉/时间区域和音频 token 上。这些区域即使视觉上看似冗余，也可能对同步至关重要。

2. **交叉模态注意力本身可作为加速指导信号**：该显著性信号不需要额外训练或额外的 profiling pass，可以直接用于识别应保护的同步关键计算。

3. **受保护稀疏注意力显著优于普通稀疏化**：对高显著性的 query 保留完整 dense 注意力行，能有效降低这些 token 的特征误差（图 4），在保持稀疏计算收益的同时大幅改善视频重建质量和同步性。

4. **同步感知的缓存重用比模态无关缓存更安全**：考虑音频/视频双流特征变化、受保护区域变化和跨模态显著性漂移的缓存判据能防止不安全的特征复用。

5. **主实验结论**：在 Ovi 上，方法取得 **~2× 加速** 的同时，PSNR 25.69（对比最佳基线 TeaCache 24.78）、Sync-C 4.606（对比 TeaCache 3.743），在视频质量、音频相似度和同步性上全面领先所有加速基线。在 LTX-2.3 上同样取得最优质量（PSNR 20.87 vs 最佳基线 19.50；Sync-C 5.134 vs 4.869）。

6. **保护收益来源不是增加计算，而是保护了正确的计算**：表 4 显示，随机选取 5% 保护带来的提升远小于按交叉模态显著性选取 5%，视频自注意力分数也不如跨模态显著性有效。

## 8. 不足与局限

1. **模型覆盖有限**：仅验证了 Ovi 和 LTX-2.3 两个开源模型，二者架构类型相同。对于其他架构设计的音视频生成模型（如 Harmony、Jova 或非 Ovi 式融合块设计），该方法是否依然有效尚不确定。

2. **加速比存在差异**：在 LTX-2.3 上仅取得约 1.3× 的速度提升，相比 Ovi 的 2× 差距明显。在低分辨率阶段之外的加速空间（如高分辨率精化阶段）未被探讨，方法的适用范围有一定局限。

3. **显著性计算引入额外开销**：虽然使用了滞后重用（每 4 步更新一次），但交叉注意力图的计算和显著性聚合本身仍产生额外延迟。论文对此有分析但缺乏与加速比贡献的精细拆解——有多少加速来自稀疏注意力、多少来自缓存、显著性开销占比如何，未单独量化。

4. **缺乏人类感知评估**：尽管 Q-Align、LPIPS 等指标覆盖了部分感知维度，但没有 user study 验证真实观众对加速后音视频同步的主观感受。

5. **与系统级加速方法的组合潜力未探索**：FlashAttention 和 SageAttention 等系统级/量化方法与该稀疏化方案是互补的，但实验中没有涉及组合测试，无法确认实际叠加收益。

6. **实际性能未用墙钟时间验证（有一定保留）** ：分析中报告了理论复杂度和端到端延迟，但稀疏注意力在 GPU 上的实际加速受稀疏度、内核实现效率影响很大，论文中未报告不同方法在各模块上的延迟细分。

7. **保护比例（5%）需要手动设定**：最优比例可能随模型/场景/分辨率变化，论文仅报告了 2%/5%/10% 三个档位的效果差异，未提出自适应调节方案。

8. **生成的新内容未经大规模评测**：现有指标均与 dense 基线对比（重构质量），对于"加速是否影响模型本身能生成的最佳内容"这一维度（如 FID、FVD、CLIP 等分布质量指标）未作评估。
