## 摘要
KV缓存驱逐限制了长推理轨迹的内存成本，但由于模型从部分历史视角进行解码，本质上有损。在激进的预算下，这不仅会降低准确性，还可能引发失控退化，即模型生成不连贯或重复的token，直到达到长度限制。我们将这种损失的大部分归因于由缺失上下文导致的信息差距，而非由有限模型容量导致的能力差距。一个被驱逐的7B模型和一个全上下文的1.5B模型会犯互补性错误，在它们的答案之间进行神谕选择可以恢复与全KV 7B模型之间79%的准确率差距。基于这一观察，我们提出了KV-Rescue，一个无需训练的推理框架，利用轻量级全上下文助手弥合KV驱逐引入的信息差距。KV-Rescue将两个模型的推理步骤交错到共享轨迹中。在线检测器利用熵和可压缩性提前终止不连贯或重复的基模型候选生成。在五个数学基准上，使用Qwen2.5-Math 7B和72B，在驱逐预算B=64下，KV-Rescue平均恢复了因驱逐而损失的87%的准确率。解码成本分析进一步表明，防止失控退化平均减少了43%的基模型token生成。

## Abstract
KV-cache eviction caps the memory cost of long reasoning traces but is inherently lossy because the model decodes from a partial view of its history. Under aggressive budgets, this not only lowers accuracy but can also cause runaway degeneration, where the model produces incoherent or repetitive tokens until reaching the length limit. We characterize much of this loss as an information gapf caused by missing context, rather than a capability gap caused by limited model capacity. An evicted 7B model and a full-context 1.5B model make complementary errors, and an oracle choice between their answers recovers 79% of the accuracy gap to the full-KV 7B model. Based on this observation, we propose KV-Rescue, a training-free inference framework that bridges the information gap introduced by KV eviction using a lightweight full-context helper. KV-Rescue interleaves reasoning steps from the two models into a shared trajectory. An online detector uses entropy and compressibility to terminate the generation of incoherent or repetitive base-model candidates early. Across five math benchmarks with Qwen2.5-Math 7B and 72B, KV-Rescue recovers an average of 87% of the accuracy lost to eviction at eviction budget B=64. A decode-cost analysis further shows that preventing runaway degeneration cuts base-model token generation by 43% on average.

- **关键洞察**：作者将驱逐带来的性能损失定性为**信息差距（information gap）** 而非**能力差距（capability gap）：
  - 信息差距 = 模型无法看到其历史上下文的部分内容；
  - 能力差距 = 模型看到了相同信息但解决能力不足。
  - 实验证据：一个被驱逐的7B模型与一个全上下文1.5B模型会在不同题目上犯错，二者错误具有互补性；通过 oracle（神谕）在两者答案之间做选择，可恢复与全KV 7B模型之间**79%的准确率差距**（图1a）。这证明信息差距是主要瓶颈。

## 2. 方法论：KV-Rescue

### 2.1 核心思想
KV-Rescue 是一个**无需训练（training-free）** 的推理框架，核心思想是在**每一步推理中交替使用两个策略**：
- **主模型 π_base**：被驱逐的7B/72B大模型（KV budget受限）。
- **辅助模型 π_helper**：全上下文的轻量级1.5B模型（KV不受限）。

二者共享同一条已提交的轨迹（trajectory），但各自访问不同的历史视图，并通过 PRM（过程奖励模型）逐步选择最优步骤，交错生成最终推理轨迹。

### 2.2 关键公式与算法流程

**基础框架（公式3）**：在第t步，主模型采样Nb个候选步骤，辅助模型采样Nh个候选步骤，PRM选择得分最高者：

```
st = arg max_{s ∈ Cbt ∪ Cht} R(ct, s)
```

- `Cbt`：主模型候选集合，基于驱逐缓存 EB(ct) 生成；
- `Cht`：辅助模型候选集合，基于全上下文 ct 生成；
- `R(ct, s)`：PRM为步骤s给出的得分。

**在线退化检测（公式4-6）**：检测两类退化模式并提前终止有问题的基模型候选：

- **不连贯生成（Incoherent generation）**：候选token表现出持续的高预测熵，通过移动平均熵判断：
  - `H̄e > τ_ent`（默认 τ_ent = 7.0 nats）

- **重复循环（Repetition loop）**：低熵但高度可压缩，用gzip压缩比检测：
  - `ρe = |gzip(ze)| / |ze| < τ_cmp`（默认 τ_cmp = 0.18）

检测器的综合判定：
```
deg_e(s) = 𝟙[H̄e > τ_ent] ∨ 𝟙[ρe < τ_cmp]
```

**算法流程（Algorithm 1）**：
1. 初始化：主模型采用被驱逐缓存，辅助模型采用全上下文缓存；
2. 每一步：主模型采样Nb个候选、辅助模型采样Nh个候选；
3. 主模型候选在生成过程中实时筛查，触发退化检测即终止；辅助模型不筛查；
4. PRM从所有未退化候选中选择最优步骤；
5. 若主模型步骤被选中，保留其fork（分支）作为新状态；若辅助模型步骤被选中，主模型编码这些token后重新应用驱逐；
6. 循环直至遇到 `<eos>` 或达到长度上限。

**工程实现关键点**：
- 基于vLLM v1引擎构建fork-based方案，避免重新prefill历史；
- 主模型、PRM和辅助模型分别作为独立vLLM实例运行，辅助模型和PRM通过异步HTTP查询，与主模型解码重叠执行；
- 支持 continuous-batching 批处理，同一step()推进多个问题的活动候选。

### 2.3 开销分析（理论推导）
- **KV内存**：主模型内存被预算限制为常数（与上下文长度无关），辅助模型虽全上下文但模型极小（1.5B），内存随上下文线性增长但斜率很低。在ℓ=4k、B=512时，7B基座的全KV/Best-of-N内存比约为1.5×，72B时约为4.1×。
- **解码计算**：每次辅助模型前向传播仅占7B基座逐token计算量的约24%，占72B基座的约2.5%。驱逐在token级别可能引入约2-6%的开销（取决于上下文长度），但通过避免失控生成减少大量token，整体效率收益显著。

## 6. 主要结论与发现

1. **信息差距理论得到验证**：oracle选择可恢复79%的驱逐损失，有力支持"驱逐损失主因是信息缺失而非能力不足"的核心假设。

2. **KV-Rescue恢复准确率**：在B=64的驱逐预算下，7B和72B模型跨5个数学基准平均恢复**87%**的准确率损失（表5，图5）。

3. **防止失控退化**：交错推理将B=64下的退化率从13.4%降至2.8%；在线提前退出进一步将其降至0.2%，且不损害准确率。

4. **显著降低token生成**：在B=64、N=8的分析中，主模型token生成平均减少**43%**。表1显示：B=64时，MATH500上Best-of-N的7B主模型输出达10,587 token，而KV-Rescue仅6,327 token（含辅助模型token）。

5. **端到端吞吐量提升**：批量64时，KV-Rescue的吞吐量是驱逐-only Best-of-N的**3.3倍**（prob/min 10.6 vs 3.2），且主模型token生成降低70%（18.4k→5.5k tokens/题）；全KV在批64时OOM，而KV-Rescue可正常服务。

6. **辅助步骤占比随驱逐加剧而增加**：辅助模型提供17%（B=512）至33%（B=64）的已提交步骤，证明其作用随主模型信息缺失加剧而增强，但主模型仍贡献大部分步骤（图6）。

7. **跨驱逐方法通用**：在R-KV和SnapKV两种驱逐策略下均表现出相同恢复模式。

8. **小模型作为验证器的可行性**：7B PRM成功为72B基座引导推理，表明验证器可小于生成器。

## 7. 方法亮点

- **诊断性创新**：将驱逐损失明确定义为"信息差距"并提供oracle实验证据，为问题提供了清晰的理论框架。
- **无需训练**：完全基于推理时策略，可直接应用于任何现有模型和服务框架。
- **轻量级解决方案**：1.5B辅助模型仅增加2.5%（72B基座）至24%（7B基座）的逐token计算开销，却能恢复87%的准确率损失。
- **在线退化检测设计**：利用解码过程中**已有**的熵信息与文本的gzip压缩性，无需额外模型前向传播即可检测两类退化模式，计算开销可忽略。
- **方法通用性**：与具体驱逐策略正交（已验证R-KV和SnapKV），可叠加其他KV压缩方法（如量化、合并）。
- **工程实现扎实**：fork-based引擎避免重新prefill、异步PRM/辅助模型调用隐藏延迟、continuous-batching支持多问题并发，具有实际部署价值。
- **理论推导完整**：附录给出了KV内存、解码计算、开销交叉点的严格推导，帮助理解何时驱逐真正划算。

## 8. 不足与局限

- **基准覆盖较窄**：实验全部为数学推理任务，未涵盖通用问答、代码生成、长文档理解、Agent场景等其他长上下文推理任务，泛化性有待验证。
- **辅助模型规模固定**：仅使用1.5B作为辅助，未探索最优的辅助模型大小/架构选择，也未系统评估辅助模型能力对恢复效果的影响。
- **比较公平性存疑**：KV-Rescue 的候选总数为2N（主+辅各N），而Best-of-N仅N个主候选。论文将主模型候选数对齐（N vs N+N），但若按**总策略候选数**比较，Best-of-N的准确率可能会略有提升（图1b表明仍会低于full-KV）。表3的端到端效率对比虽在总资源恒定条件下进行，但精度对比中两者总计算量不等。
- **总预算约束不足**：表3以总加速器不变为约束对比吞吐量，但KV-Rescue实际部署时还需额外的辅助模型服务开销（它们共享同一GPU池，因此并非完全免费）。
- **重复循环检测的参数依赖**：gzip窗口宽度（wcmp=800）和阈值（τcmp=0.18）依赖特定场景调参，可能需要针对不同模型/语言适配。
- **单次运行基准的统计性不足**：MATH500、GSM8K、OlympiadBench仅单次运行，未报告方差/置信区间。
- **未覆盖极端长上下文**：最大上下文限制为4096 token，未评估更长推理轨迹（如数万token）下的表现。
- **"not thinking too much"问题未处理**：论文明确承认，如"过度思考"（coherent but unnecessarily long）这类更渐进式的失败模式不在研究范围内。
