## 摘要
线性注意力模型通过将成对令牌交互替换为循环状态更新，消除了softmax注意力的二次前缀计算和不断增长的KV缓存。然而，现有的解码实现通常在生成每个令牌后物化并写回完整的循环状态，这使得状态维护成为内存流量的主要来源，尤其对于具有大状态和多头部的模型。本文提出了DeltaLog，一种循环状态解码方案，在不改变模型语义的情况下减少这种开销。具体而言，DeltaLog将循环状态表示为稠密基状态与近期紧凑更新的有界日志的组合。大多数解码步骤仅将紧凑更新因子追加到此日志，而定期合并步骤则将累积的更新折回稠密基状态。因此，模型观察到与即时解码相同的稠密状态，但大多数全状态写回被轻量级追加操作所取代。我们为GDN、KDA和RWKV6实现了DeltaLog，并将其集成到原型服务栈中。在这些模型上，DeltaLog将循环状态更新内核加速了高达1.86倍，将剖析的循环状态写流量减少了高达7.83倍，并实现了相对于稠密循环基线1.05至1.20倍的端到端服务加速。

## Abstract
Linear attention models eliminate the quadratic prefix computation and context-growing KV cache of softmax attention by replacing pairwise token interactions with recurrent state updates. However, existing decoding implementations often materialize and write back the full recurrent state after every generated token, making state maintenance a major source of memory traffic, especially for models with large states and many heads. This paper presents DeltaLog, a recurrent-state decoding scheme that reduces this overhead without changing the model semantics. Specifically, DeltaLog represents the recurrent state as a dense base state together with a bounded log of recent compact updates. Most decode steps append only compact update factors to this log, while periodic merge steps fold the accumulated updates back into the dense base state. Thus, the model observes the same dense state as in eager decoding, but most full-state write-backs are replaced by lightweight append operations. We implement DeltaLog for GDN, KDA, and RWKV6 and integrate it into a prototype serving stack. Across these models, DeltaLog accelerates the recurrent-state update kernel by up to $1.86\times$, reduces profiled recurrent-state write traffic by up to $7.83\times$, and achieves $1.05$--$1.20\times$ end-to-end serving speedups over dense recurrent baselines.

## 1. 核心问题与整体含义

- **研究动机**：线性注意力模型通过引入固定大小的循环状态（recurrent state）替代 softmax 注意力中随序列增长的 KV 缓存，从而消除了二次复杂度和缓存膨胀。然而在自回归解码阶段，现有实现（如 FLA、vLLM）通常采取“急切物化”（eager materialization）策略——每个生成令牌都读取完整稠密状态、执行更新、再写回完整状态。这种策略导致每令牌的 HBM 读写流量为 \(O(B H d_k d_v)\)，而令牌本身携带的紧凑更新信息仅有 \(O(BH(d_k+d_v))\)，造成了严重的“状态更新税”（state-update tax）。
- **核心问题**：在批处理规模较大或状态维度较高时，循环状态的重复读写成为解码延迟和内存带宽的主要瓶颈。作者通过实验表明，在 Qwen3.6-35B-A3B 模型中，当 batch size 为 256 时，循环状态物化占解码延迟的 44.6%（1k 上下文），说明该开销在真实服务中不可忽略。
- **整体含义**：论文提出一种不改变模型语义、仅改变物理执行调度的优化方案，旨在将“每令牌全状态写回”替换为“多数令牌轻量追加 + 周期合并”，从而降低内存流量、提升解码吞吐和响应速度。该思路不同于修改注意力架构或优化并行计算，而是聚焦于循环状态在 GPU HBM 中的存储与更新方式。

## 2. 方法论

- **核心思想**：将循环状态 \(S_t\) 的物理表示分解为两部分：
  - **稠密基态（dense base）** \(\bar{S}\)：保存最近一次合并后的历史信息；
  - **有界更新日志（bounded update log）**：保存最近 \(M-1\) 个令牌的紧凑更新因子，包括键侧因子 \(K_{\log}\)、值侧因子 \(U_{\log}\)、以及每条日志对应的累积对数衰减快照 \(\Lambda_{\log}\)。
- **解码流程（append–merge 循环）**：
  - **追加阶段（append）**：当活动日志长度 \(L < C = M-1\) 时，当前令牌的更新因子 \((a_t, b_t)\) 和更新后的累积对数衰减 \(\bar{\ell}\) 被追加到日志中，稠密基态不动。此阶段避免了对 \(O(BH d_k d_v)\) 状态张量的写回，只写入 \(O(BH(d_k+d_v))\) 的紧凑数据。
  - **合并阶段（merge）**：当 \(L = C\) 时，将日志中所有延迟更新（以及当前令牌的更新）按指数衰减加权后累加到稠密基态中，然后清空日志并重置累计衰减。合并操作每个周期只执行一次，将全状态写回成本摊还到 \(M\) 个令牌上。
- **状态不变量**：在任意时刻，物理表示对应的逻辑状态为：
  \[
  S_t = D(\bar{\ell})\bar{S} + \sum_{i=0}^{L-1} D(\bar{\ell} - \Lambda_{\log}[i]) K_{\log}[i] U_{\log}[i]^\top
  \]
  该式在精确算术下与急切物化的状态等价。追加操作使新条目以当前累积衰减存储，旧条目保持正确的后续衰减权重；合并操作将全量逻辑状态物化后清零。因此，该表示对循环递推闭合。
- **流量模型**：给定状态大小 \(C_{\text{state}}\)、日志条目大小 \(C_{\text{entry}}\)，理想情况下 DeltaLog 的平均每令牌状态流量约为：
  \[
  T_{\text{delta}} \approx T_{\text{common}} + C_{\text{state}} + \frac{C_{\text{state}}}{M} + \left(\frac{M-1}{M} + \frac{M-1}{2}\right)C_{\text{entry}} + 2C_{\text{decay}}
  \]
  相比急切物化 \(T_{\text{dense}} \approx T_{\text{common}} + 2C_{\text{state}}\)，DeltaLog 省去了 \((1 - 1/M)C_{\text{state}}\) 的写流量，但增加了日志写与回放读流量。因此合并间隔 \(M\) 存在最优值。
- **GPU 内核实现（Tiled Kernel Decomposition）**：
  - 沿值维度将每个状态的稠密基态划分为多个 \(d_k \times B_V\) 的瓦片（value tiles），每个瓦片由独立工作单元处理，增加并行度。
  - 值侧日志 \(U_{\log}\) 与稠密基态瓦片局部存储；键侧日志 \(K_{\log}\)、日志衰减快照、累积衰减等元数据在同一槽–头内共享。
  - 采用三阶段执行：ReplayPrep（按槽–头计算可复用回放系数）→ AppendDecode（并行瓦片处理，复用系数并写局部值日志）→ Finalize（单个写者提交共享元数据）。
- **算子实例化**：
  - GDN：头级标量衰减，日志键侧用 BF16、值侧用 FP32，\(M=8\)；
  - KDA：逐键对角衰减，日志键侧 BF16、值侧 FP32，\(M=4\)；
  - RWKV6：逐键对角衰减，无 Delta-rule 修正，日志键/值侧均用 BF16，\(M=4\)。
- **服务端集成**：在 vLLM 基础上实现，捕获 append 和 merge 两套 CUDA 图，按相位选择执行；请求在 append 和 merge 队列间迁移，以兼容连续批处理。

## 6. 主要结论与发现

- DeltaLog 能有效降低循环状态更新带来的内存写流量。在 H200 上：
  - 内核级解码延迟相对 FLA 加速：GDN 1.34–1.60×，KDA 1.19–1.60×，RWKV6 1.52–1.69×；
  - 相对 vLLM 稠密内核：GDN 1.26–1.42×，KDA 1.29–1.46×。
  - RTX 4090 上加速更明显：GDN 1.69–1.86×，KDA 1.30–1.55×，RWKV6 1.41–1.63×。
- 流量剖析（GDN，B=128，M=8）显示：稠密基线写流量 0.230 GiB/令牌，DeltaLog 摊销后写流量仅 0.0294 GiB/令牌，降低 7.83 倍；总 DRAM 流量降低 1.64 倍。
- 合并间隔存在最优值：过小的 \(M\) 增加合并频率，过大则增加回放开销。最佳选择：GDN \(M=8\)，KDA 与 RWKV6 \(M=4\)（在 B=128 时）。
- 状态规模越大，DeltaLog 收益越明显：从 128 MiB 到 1024 MiB，GDN 加速从 1.48× 提升至 1.62×，KDA 从 1.02× 提升至 1.58×，RWKV6 从 1.51× 提升至 1.69×。
- 数值误差在可接受范围内：输出相对误差最大值约 0.45%（KDA），状态相对误差最大值约 4.61e-4，满足 BF16 容忍度。
- 端到端服务中，Qwen/GDN 获得 1.08–1.20× 的 TPOT 加速，Kimi/KDA 获得 1.05–1.12× 加速。收益小于内核级，符合 Amdahl 定律——DeltaLog 仅优化循环状态更新路径。

## 7. 优点

- **问题识别清晰**：明确提出了“状态更新税”概念，并用 roofline 分析指出稠密循环状态更新的算术强度极低（~0.5–1 FLOPs/byte），远低于 H200 的机器平衡点（~208 FLOPs/byte），从理论上证明优化方向正确。
