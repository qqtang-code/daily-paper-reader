## 摘要
本文提出了一种异构解码阶段服务系统，将KV缓存从GPU内存中移出，其动机是近期前沿LLM采用基于检索的稀疏注意力来服务百万级token上下文。它按操作类型划分解码步骤：GPU节点持有模型权重并执行投影和MoE层，而近内存处理（PNM）节点持有KV缓存和索引键，并执行所有读取它们的操作。我们首先表明先前PIM和PNM设计背后的假设对这些操作不再成立，并为此类节点推导出四个设计需求。基于这些需求，我们提出了KARAT（面向基于检索的注意力的KV缓存驻留加速器），这是一种满足所有四个需求的通用PNM设计。KARAT设备将大容量LPDDR与为检索索引器量身定制的通用计算相结合，提供了超越为低强度GEMV目标设计的PIM/PNM设计的操作强度，同时适应固定功能单元在演进过程中无法支持的多样化稀疏注意力算法。为减少两种设备类型在微批次间交替时的流水线气泡，我们进一步提出了机会性细粒度微批次调度（OFMS），将专家全对全通信隐藏在其他微批次的GEMM之后，以及上下文长度感知的微批次再平衡（CMR），在上下文长度差异下均衡它们的token数量。在三个最先进的模型和真实代理轨迹上，我们提出的系统在服务水平目标下将每TDP吞吐量比纯GPU基线提高了2.09-6.13倍，并以1.36-3.21倍的改进运行免训练稀疏注意力方法。

## Abstract
This paper presents a heterogeneous decode-phase serving system that relocates the KV cache out of GPU memory, motivated by the retrieval-based sparse attention that recent frontier LLMs adopt to serve million-token contexts. It partitions a decode step by operation type: GPU nodes hold the model weights and execute the projections and MoE layers, while processing-near-memory (PNM) nodes hold the KV cache and index keys and execute every operation that reads them. We first show that the assumptions behind prior PIM and PNM designs no longer hold for these operations, and derive four design requirements for such a node. From these requirements, we propose KARAT (KV-cache-resident Accelerator for Retrieval-based ATtention), a general-purpose PNM design that is the design point meeting all four. A KARAT device combines large LPDDR capacity with general-purpose compute sized for the retrieval indexer, serving an operational intensity beyond what PIM/PNM designs built for low-intensity GEMV target while accommodating diverse sparse attention algorithms that fixed-function units cannot support as they evolve. To reduce pipeline bubbles as the two device types alternate between micro-batches, we further propose opportunistic, fine-grained micro-batch scheduling (OFMS), which hides expert all-to-all behind the other micro-batch's GEMMs, and context-length-aware micro-batch rebalancing (CMR), which equalizes their token counts despite the variance in context length. Across three state-of-the-art models and real agentic traces, our proposed system improves throughput per TDP under a service-level objective by 2.09-6.13x over a GPU-only baseline and runs training-free sparse attention methods with 1.36-3.21x improvements.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **长期上下文推理的存储瓶颈**：Agentic 工作负载中，多轮对话的上下文可累积至百万 token（99 分位 198K–791K），KV 缓存和索引键需全部驻留于内存，导致内存容量取代计算吞吐成为解码阶段的核心瓶颈。
- **检索式稀疏注意力带来的新挑战**：此类方法（如 DSA、GLM-5.2 的 indexer、MiniMax-M3 的块级稀疏）虽然将每次解码读取的数据量减少 6.6–32 倍，但它们并未减小内存足迹——完整的 KV 缓存与索引键仍需存放，且索引器扫描（indexer scan）是每步必须完成的 O(L)$ 操作。
- **现有 PIM/PNM 设计假设失效**：传统 PIM/PNM 为低操作强度（OI）的密集 MHA/GQA GEMV 场景设计、计算单元固定且容量受限于 HBM/GDDR；而检索式稀疏注意力要求同时满足大容量、高带宽、中等 OI（4–128 FLOPs/byte）和算法多样性，这是现有架构无法同时满足的。

## 2. 方法论：核心思想与关键技术细节

- **系统总体架构（KARAT 异构服务系统）**：将解码步骤按操作类型划分——GPU 节点保留模型权重并执行投影和 MoE 层；KARAT 节点持有 KV 缓存与索引键，并执行所有读取这些数据的操作（索引器扫描、Gather、Attention）。两者以微批次流水线方式交替执行。
- **KARAT 设备设计**：
  - 以 LPDDR5X 为存储介质，单设备提供 512GB 容量与 1.2 TB/s 带宽，容量/瓦是 HBM3 的 19 倍，带宽/瓦约为其 0.8 倍；
  - 配置 18 个通用近内存处理（GPNM）核心（SM 风格），FP8 性能 250 TFLOPS，脊点（ridge point）208 FLOPs/byte，高于索引器扫描 4–128 的 OI 区间；
  - 面积约 286 mm²（其中 LPDDR PHY/控制器占 58%），TDP 175W；每节点 32 个设备，构成 16TB/38.4TB/s 的 KARAT 节点，替代 8-GPU 节点的容量角色。
- **四个设计需求（R1–R4）**：
  - R1：容量/瓦比 HBM 高一个量级；
  - R2：带宽/瓦与 HBM 相当；
  - R3：计算脊点须高于目标操作的实际 OI 区间；
  - R4：通用可编程性以覆盖不断演进的稀疏注意力算法族。
- **OFMS（Opportunistic, Fine-grained Micro-batch Scheduling）**：在 GPU 侧以细粒度机会式方式跨微批次调度，将 MoE 的 all-to-all 通信隐藏到另一微批次的 GEMM 下，并在依赖不允许重叠时自动回退到静态调度；无需全局调度器。
- **CMR（Context-length-aware Micro-batch Rebalancing）**：每当请求完成或新请求到达时，按上下文长度降序将每个 KARAT 设备上的请求重新分配到两个微批次中，使各微批次的总体 token 数尽可能均衡，避免过长微批次拖慢同步。

- 模型原生稀疏注意力下，KARAT 相对 GPU-only 的吞吐/TDP 提升为 **2.09–6.13 倍**，提升幅度随上下文长度增大（SWE-Pro 约 2.1–2.4 倍 → KVCT 约 3.0–6.1 倍）。

## 7. 优点

- **问题刻画精准**：以实测数据证明检索式稀疏注意力把瓶颈从带宽转移到容量，并给出了具体 OI 数字（4–128）作为硬件设计的锚点，有较强的指导意义。
- **设计原则驱动**：用 R1–R4 四需求统领存储介质选择、核心数量配置和通用性要求，避免“为特定算法定制”的短视设计；结论对不同代际的内存技术具有可迁移性。
- **通用性**：一套硬件同时支持模型原生稀疏注意力、免训练稀疏注意力、密集注意力和未来未知算法，解决了现有 SPNM 固定的问题。
- **调度优化具有实践价值**：OFMS 的“机会式”重叠设计能够在 GPU 侧 busy 时回退到静态调度，不劣于原有方案，且可分布式实现；CMR 开销极低，仅重新分组而非搬移数据。
- **评估规范**：等功耗、相同 SLO、闭路到达、消融与灵敏度分析齐全，并与多类基线公平对比；采用真实 agentic 轨迹，提高结论可信度。

## 8. 不足与局限

- **模拟而非真机验证**：KARAT 芯片未流片，性能评估依赖 LUT 与事件驱动模拟器（虽基于 H200 MIG 校准），面积/功耗为估算值，实际 PHY 时序、散热和片上互连等物理效应可能带来偏差。
- **假设简化**：MoE 路由在默认实验中假定均匀分布，仅在单节实验考虑偏斜；链路延迟/带宽对性能的实际影响依赖所假设的 CXL/RDMA 参数，真实网络中不同拓扑下结论可能变化。
- **评估范围有限**：只覆盖 3 个模型、3 个 trace 和 8 节点规模；扩展到更大集群、更多工作负载（如共享上下文/多租户混合场景）的结论有待验证。
- **稀疏注意力方法范围**：本文主要覆盖 DSA、GQA+块稀疏与三类免训练方法，未涵盖所有可能的新兴算法族（如分层索引、学习型排序等），虽在文中讨论但未提供实验证据。
- **容量功耗权衡**：KARAT 依赖 LPDDR5X 的容量/瓦优势，但 LPDDR 的带宽/瓦低于 HBM，在更低 OI 或更高稀疏度场景下，注意力部分的每瓦性能可能不及 HBM 方案。
- **对 GPU-only 的提升存在场景依赖**：当上下文较短（如 SWE-Pro 62K 平均）时提升倍数较低（仍 >2 倍），而如果模型没有稀疏注意力（dense 场景），KARAT 提升仅为 1.24–1.32 倍，且不如 AttAcc。
