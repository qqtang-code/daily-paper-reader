## 摘要
全模态大语言模型（OmniLLMs）正迅速扩展多模态推理能力，以覆盖同步音频和视频。然而，由此产生的音视频令牌序列较长，导致推理时的预填充延迟和GPU内存占用过高。现有的令牌剪枝方法主要针对纯视觉输入设计，既忽略了音频与视频之间的跨模态关联，也未考虑决定哪些内容重要的用户查询。为弥补这一空缺，我们提出了Omni-Prune，一个无需训练、查询感知的音视频令牌剪枝框架，能够联合去除两种模态中的冗余信息，同时保留与任务相关的跨模态证据。具体而言，Omni-Prune首先将令牌序列分割为放置在音频显著性峰值处的自适应时间窗口，然后在单一尺度上对音频和视频令牌进行评分，该评分结合了编码器注意力与文本查询相关性，并将相关的音视频令牌配对以便共同保留。在每个窗口内，最终的K-medoids步骤会选取少量代表性令牌，增添仅基于评分的选取所无法涵盖的多样化线索。大量实验表明，Omni-Prune优于现有基线方法，可实现高达3.25倍的预填充速度提升和1.3倍的内存减少，同时保持超过99%的完整模型性能。

## Abstract
Omnimodal large language models (OmniLLMs) are rapidly extending multimodal reasoning to cover synchronized audio and video. However, the resulting audio-video token sequences are long, leading to high prefill latency and GPU memory usage at inference time. Existing token pruning methods, designed mainly for vision-only inputs, miss both the cross-modal links between audio and video and the user query that decides which content matters. To bridge this gap, we present Omni-Prune, a training-free, query-aware audio-visual token pruning framework that jointly removes redundancy from both modalities while keeping task-relevant cross-modal evidence. Specifically, Omni-Prune first splits the token sequence into adaptive time windows placed at audio saliency peaks, then scores audio and video tokens on a single scale that combines encoder attention with text-query relevance, and pairs related audio-video tokens so that they are kept together. Within each window, a final K-medoids step then selects a few representative tokens, adding diverse cues that score-based selection alone would miss. Extensive experiments demonstrate that Omni-Prune outperforms established baseline methods, delivering up to 3.25x prefill speedup and 1.3x memory reduction while retaining over 99% of full-model performance.

## 1. 核心问题与整体含义（研究动机与背景）

- **问题背景**：全模态大语言模型（OmniLLMs）将文本、音频、视频统一映射到同一 token 空间中，支持如唇语同步对话、声音定位事件等细粒度跨模态推理。然而，一分钟视频片段在中等采样率下即可产生约 10⁴ 个交错音视频 token，自注意力机制随序列长度二次增长，导致**预填充（prefill）延迟高、GPU 显存占用大**，成为实际部署的主要瓶颈。
- **现有方法的不足**：
  - 绝大多数 token 剪枝方法（如 FastV、DyCoke）仅针对纯视觉输入设计，无法利用音频与视频之间的互补时序信息；
  - 少数的全模态剪枝方法（如 OmniZip、OmniSIFT）采用**单向引导**（音频引导视频或视频引导音频），未实现模态间的对称信息交互；
  - 所有现有方法均**未将用户文本查询纳入剪枝决策**，而查询内容恰恰决定了哪些 token 对下游任务重要。
- **研究意义**：本文首次提出将**音频、视频、文本三种模态全部纳入剪枝决策**的框架，是面向 OmniLLM 的高效推理加速方向上的重要探索。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 整体框架
Omni-Prune 是一个**免训练、即插即用**的 token 剪枝框架，由三个核心模块组成：**音频锚定自适应分窗（AAW）**、**跨模态关系图（CMRM）**、**多样性保持聚类（K-medoids）**。给定全局保留率 α，方法在保持所有文本 token 不变的前提下，从音频与视频 token 中选出一个预算 B=⌊α·(|A|+|V|)⌉ 的子集送入 LLM 主干。

### 2.2 模块一：音频锚定自适应分窗（Audio-Anchor Adaptive Windowing, AAW）
- **动机**：固定大小的时间窗口会切断连贯的语义事件，而全序列全局处理又忽略事件在时间上的不均匀分布。
- **音频显著性计算**：将音频 token 序列按帧划分，计算每帧内音频 token 的编码器注意力均值作为能量 E_f；再通过 1D 平均池化（核大小为 3）平滑得到显著性曲线。
- **峰值引导分窗**：以平滑曲线的局部峰值为候选窗口边界（要求 ≥ 左右邻值），并施加最小间隔约束 f_min=2 以抑制噪声峰值、避免碎片化窗口。音频显著事件（语音起始、音效、音乐转场）通常与关键视觉时刻共现，因此窗口边界与语义事件对齐。

### 2.3 模块二：跨模态关系图（Cross-Modal Relation Map, CMRM）
该模块解决两个问题：**如何在统一尺度上对双模态 token 评分**，以及**如何保留跨模态配对证据**。

- **Token 重要性评分**：
  - 编码器注意力得分（s_i）：取自最后一个自注意力层，跨头平均并对所有 query 位置求和；
  - 联合 min-max 归一化（v_i）：将同一窗口内音频与视频的注意力得分一起归一化到 [0,1]，使双模态可在同一尺度上比较；
  - 文本查询相关性（r_text^i）：计算每个多模态 token 与用户查询中所有文本 token 的余弦相似度最大值，经仿射映射到 [0,1]；
  - 复合评分：φ_i = v_i + r_text^i。引入文本相关性阈值 τ=0.55 作为下限，避免通用问题导致所有 token 都“显得相关”；
  - 以 φ_i 为序选择每窗口的 keep 候选，每窗口保持预算上限 B_keep^w=⌊αρ_keep(|A_w|+|V_w|)⌉（ρ_keep=0.6 为最优）。
- **跨模态耦合**：
  - 构建窗口内音频-视频 token 两两余弦相似度矩阵 C^w；
  - 对未选中 token 执行**双向贪心匹配**，将每个音频 token 与其最相似的视频 token 配对；
  - 相似度超过门限 γ=0.6 的配对被联合保留，保证同一事件的双模态证据不因剪枝而断裂；
  - 剩余预算按照 φ_i 排序从未选中 token 中填充，优先补充少数模态以维持模态平衡。

### 2.4 模块三：多样性保持聚类（Diversity-Preserving Clustering）
- **动机**：单纯按评分保留会丢弃大量虽不显著但具有互补信息的 token（如环境音、背景物体），使保留集在嵌入空间中集中于高分区。
- **方法**：在每个窗口内、每个模态内，对未选中 token 应用 **K-medoids 聚类**（选择 K-means 的替代方法，因为 medoid 是真实存在的 token，不会引入分布外向量），通过最远优先遍历（farthest-first traversal）在余弦距离空间中选取 ρ_c=0.1 比例的 medoid，最大化表征覆盖度。
- **复杂度**：每个窗口 O(k·n)，开销可忽略。

### 2.5 完整流程（算法级描述）
1. 计算音频分帧能量 → 平滑 → 找峰值 → 施加最小间隔 → 得到自适应窗口集合；
2. 对每个窗口：联合归一化注意力得分 → 计算文本相关性 → 合成复合评分 → 选 top-k 高置信 token；
3. 对未选 token 进行双向贪心跨模态配对，超过门限的配对联合保留；
4. 对未选 token 做 K-medoids 聚类，补充多样化代表性 token；
5. 按全局预算 B 依次填充高置信 token、配对 token、聚类 medoid，保留原有 token 顺序，构造剪枝后的序列。

## 6. 主要结论与发现

- **近乎无损的剪枝**：在 7B 主干下，45% 预算保留 99.2% 性能，35% 预算仍保留 99.0%，且在 5 个基准上全部排名第一；3B 主干下性能差距更大，但 Omni-Prune 仍最优（98.6%/97.5%）。
- **效率提升显著**：7B 模型在 35% 预算下预填充从 899ms 降至 277ms（**3.25× 加速**），峰值显存降低 6.4GB（**约 1.28× 减少**）；3B 模型达 **3.63× 加速**。
- **剪枝亦可去噪**：在 VideoMME、OmniVideoBench、FutureOmni 上，Omni-Prune 的分数**超过全 token 基线**，说明剪枝在含大量冗余/离题上下文的基准上可起到“轻度去噪”作用。
- **消融结论**：
  - AAW 优于任何单一固定窗口设置，消除了窗口大小的数据集敏感性；
  - 评分模块贡献大于耦合模块，但两者互补；
  - K-medoids 聚类在**低预算 + 音视频密度高**时收益最大（如 VideoMME、Daily-Omni 在 35% 预算下）；
  - ρ_keep=0.6 最优，且对 0.4–0.8 范围不敏感。

## 7. 优点

- **创新性**：首个同时利用**音频+视频+文本**三种模态信息进行剪枝决策的框架，突破了现有方法“视觉专用”或“单向引导”的局限。
- **查询感知**：通过文本-多模态嵌入的余弦相似度将用户意图纳入评分，使预算集中在与问题直接相关的证据上。
- **免训练与即插即用**：无训练开销，不改变 token 嵌入、位置索引和模型参数，可直接适配现有 OmniLLM 解码器。
- **统一评分尺度**：对音频/视频注意力得分做联合归一化，而非各自独立归一化，使跨模态比较具有可操作性。
- **跨模态配对机制**：双向贪心匹配保证语义一致的音视频 token 对不被拆散，有效保留跨模态证据。
- **K-medoids 而非 K-means**：选择真实存在的 token 作为代表性样本，避免引入分布外向量，思路严谨。
- **实验设计较完整**：多基准、多模型规模、多预算、多消融的组合较系统，图 1 的性能/效率散点图直观展示了方法的 Pareto 优势。

## 8. 不足与局限

- **评估范围有限**：仅覆盖视频问答任务；开放域描述生成（open-ended captioning）和多轮对话等任务对 token 压缩的响应可能不同，且依赖人工评估，论文未涉及。
- **超参数未自适应**：τ、γ、ρ_c、f_min 等超参数在全部基准和两个主干上使用单一固定配置，虽保证了“开箱即用”，但无法适应不同数据集在片段长度和音频丰富度上的差异；论文也承认轻量级调优可进一步提升精度。
- **计算资源信息不透明**：未报告 GPU 数量、推理总时长或基准运行时间，第三方复现成本难以预估。
- **对比公平性的潜在风险**：FastV 等基线在长序列上的 OOM 被直接排除，可能弱化部分基线的表现；不同方法预算不完全对齐。
- **音频锚定的偏置风险**：以音频峰值为边界依赖“音频显著时刻与视觉重要事件重合”的先验，对于纯静音场景或视觉信息主导而音频无显著变化的内容（如无声监控视频），窗口划分可能失去意义。
- **文本相关性计算的局限**：余弦相似度基于 token 嵌入的浅层语义匹配，对复杂推理问题（需要隐含知识而非表层词汇对齐）的查询相关性度量能力有限。
- **未讨论解码阶段的 KV cache 压缩**：本文仅优化 prefill 阶段，解码阶段的长序列 KV cache 开销未纳入剪枝范围。
