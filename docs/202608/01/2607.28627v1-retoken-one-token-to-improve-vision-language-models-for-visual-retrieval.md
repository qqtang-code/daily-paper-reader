## 摘要
长视觉上下文对视觉-语言模型构成挑战：随着干扰项数量的增加，性能会下降，并且在GPU内存限制下，一次性处理所有token在计算上不可行。我们提出了ReToken，一个作为显式检索目标训练的可学习嵌入，它从预填充的视觉KV缓存中选择一组稀疏的与查询相关的视觉token。仅在小型图像问答数据集上训练，ReToken在图像和视频基准上均取得了一致的提升：在Visual Haystacks上，它使Qwen3VL-8B提升了13.4个百分点，InternVL3.5提升了12.4个百分点（相对提升>20%）；在LVBench上，它零样本迁移到长视频，Qwen3VL-8B获得了8.0个百分点的提升。得益于其轻量级设计，训练和长视频推理均可在一块H100上完成。代码可在以下网址获取：https://github.com/avaxiao/ReToken

## Abstract
Long visual context poses a challenge for vision-language models: performance degrades as the number of distractors grows, and processing all tokens at once is computationally infeasible under GPU memory constraints. We present ReToken, a single learnable embedding trained as an explicit retrieval target that selects a sparse set of query-relevant visual tokens from a pre-filled visual KV cache. Trained on only a small image-QA dataset, ReToken yields consistent gains across image and video benchmarks: on Visual Haystacks it improves Qwen3VL-8B by 13.4 points and InternVL3.5 by 12.4 points (>20% relative), and on LVBench it transfers zero-shot to long video for an 8.0-point gain with Qwen3VL-8B. Thanks to its lightweight design, both training and long-video inference fit on a single H100. Code is available at: https://github.com/avaxiao/ReToken

- **核心问题**：长视觉输入处理本质上可归结为一个**检索问题**——从大量候选帧/token 中选出与查询相关的小子集，使模型能据此生成正确答案。
- **关键发现/动机**：
  - 在纯文本 LLM 中，注意力信号对上下文具有选择性，但在 VLM 中，文本-视觉之间的注意力与相关性**弱关联**（图 1a）。
  - 基于注意力得分的检索器（如 ReKV）在 QAEgo4D Test-MC 上平均 recall@1 仅 5.1%（图 1b），远不能支撑有效检索。

- **整体意义**：提出一种轻量级、仅在小型图像 QA 数据上训练、可零样本迁移到长视频的检索方法，为长上下文多模态推理提供了一条实用路径。

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 核心思想

- 训练**单个可学习嵌入 token（ReToken）** 作为显式检索目标，替代传统的 query-key 注意力打分。
- 在**最后一层的 value 空间**计算检索分数，利用 value 携带的内容传播特性获得比 query-key 更强的相关性判别力。
- 保持 VLM 默认冻结，仅新增 ReToken 嵌入与一个投影矩阵，最小化参数开销。

### 2.2 关键技术与公式

**（1）注意力检索的缺陷分析**

- 传统方法在每层计算帧级检索分数：
  - 帧均值 key：`k̄_f = mean(K_i)`，问题均值 query：`q̄ = mean(q_t)`
  - 分数：`s_f = q̄^T · k̄_f`
- 两个结构性问题：
  - 注意力为**下一 token 预测**训练而非检索，高注意力不保证查询相关；
  - 对问题 token 做均值池化会引入噪声，排名随检索文本的选择而漂移。

**（2）ReToken 检索评分**

- 输入序列：视觉 tokens `Iv`、问题 tokens `Tq`、检索 token `Xr`。
- 最后一层 `L_N` 的检索分数（公式 3）：
  - 帧均值 value：`v̄_f^(N) = mean(v_i^(N))`
  - 投影 ReToken：`Z_r = W_r · X_r^(N)`
  - 余弦相似度：`s_f^(N) = cos(Z_r, v̄_f^(N))`
- 推理时：取 top-K 帧，将该选择从最后一层**广播到所有层**，仅用选中帧的 KV cache 生成答案。

**（3）训练损失（公式 4）**

- 类平衡二元交叉熵损失：
  ```
  L_ret = -1/|F+| Σ log σ(τ·s_f) - 1/|F-| Σ log σ(-τ·s_f)
  ```
  - `F+` / `F-` 分别表示相关/不相关帧集合，正负项分别平均以平衡类别；
  - `τ` 为可学习的 logit 缩放参数。
- 可选部分微调（tuning 前 3 层）时加入生成损失：
  ```
  L = L_ret + λ·L_gen
  ```

**（4）两遍推理流程**

- **第一步：缓存视频**——视频编码一次，逐块（chunk）处理并持久化 KV cache，可卸载至 CPU。
- **第二步：检索→回答**：
  - **第一遍（检索）**：追加 ReToken，在最后一层计算检索分数得到 top-K 帧集合；对长视频，早期层将 ReToken 注意力限制在 top-K1=256 帧内以保证显存可行。
  - **第二遍（回答）**：仅使用 top-K 帧的 KV cache 与问题一起进行标准生成。

## 6. 主要结论与发现

- **Value 空间优于 Key 空间**：在预训练 VLM 中，value 特征携带更强的内容与语义信息，以精确目标短语为查询时，value-value 余弦相似度显著优于 query-key 注意力分数。
- **ReToken 显著提升图像检索**：在 Visual Haystacks 上，冻结 VLM 时 Qwen3VL-8B 提升 13.4 点（58.6→72.0），InternVL3.5 提升 12.4 点；相对提升超过 20%，且上下文越大增益越明显。
- **零样本图像→视频迁移**：仅在图像 QA 上训练的 ReToken 迁移到长视频依然有效——LVBench 提升 8.0 点（40.6→48.6），Video-MME 长视频段提升 3.4 点。
- **检索预算越小，优势越明显**：K=1 时 ReToken 领先均匀采样 6.8 点，而 ReKV 甚至不如均匀采样；ReToken 的高精度使其在小检索预算下表现突出。
- **部分微调早期层可进一步提升图像性能**：tuning 前 3 层使 VHs C=50 达 75.0，且产生更干净的 KV cache；但在视频任务上会因域偏移（图像训练 vs. 视频评估）而略有下降。
- **适用边界明确**：ReToken 最适合“证据局部化、可命名”的问题（如关键信息检索 +15.4、实体识别 +10.5）；对时间跨度大、需跨帧推理的问题增益减小；对需要全局概括的 summarization 任务（-5.2）甚至有害。

## 7. 优点与亮点

- **极简设计，极高性价比**：仅一个可学习 token + 一个投影矩阵（加一个可学习温度参数），冻结 VLM 即可训练，参数开销几乎可以忽略。
- **单卡可训练与推理**：训练、长视频编码、检索和回答均可在单块 H100 上完成，落地门槛低。
- **诊断性发现具有普适价值**：揭示“value 空间比 query-key 空间携带更强文本对齐信号”这一现象，对后续 VLM 检索、分割（如 TextRegion）等方向有参考意义。
- **零样本视频迁移**：从多图像训练直接迁移至小时级长视频，验证了检索能力跨模态粒度的可泛化性。
- **训练数据过滤策略**：基于记忆化损失、注意力难度、多图像要求的三个过滤器有效提升了训练数据质量，体现对数据偏差的细致考量。
- **类平衡损失设计**：正负样本分别平均的 BCE 避免大量负样本主导训练，方法虽简单但有效。
- **实验分析深入**：包括 KV cache 污染分析（GT Image vs. GT Cache）、按问题类型细分的错误分析、效率/延迟分解等，令人信服。

## 8. 不足与局限

### 8.1 方法层面

- **两遍推理开销**：每条问题需两次前向（检索 + 回答），约增加 0.4 秒/问题的延迟，且早期层需保持较高的注意力预算（K1=256），峰值显存略高。
- **帧级均值池化可能稀释证据**：仅依赖每帧 value 均值做分数计算，对于只占少量 token 的局部证据（如画面角落的小物体）可能因平均而被稀释。
- **逐帧独立评分**：不建模跨帧/时序组合信息，对“某事件之前发生了什么”这类时间偏移查询，或需多帧联合才能回答的问题，现有机制天然不适用。
- **多 token 变体无增益**：3 个 ReToken 与 1 个相当，说明当前训练方式无法促使 token 特化，扩展性受限。

### 8.2 实验层面

- **骨干覆盖有限**：视频零样本迁移仅验证了 Qwen3VL-8B；InternVL3.5 仅做图像实验且训练 epoch 不足。
- **训练数据仅限多图像 QA**：未包含视频训练数据，对时间结构（时序推理、事件理解）的支撑较弱，这也是视频任务上增益较小的原因之一。
- **部分对比公平性存疑**：LVBench 基线引自其他技术报告（帧率、采样策略、prompt 可能不同），非同一代码库下的严格复现。
- **检索任务类型偏单一**：VHs 仅 Yes/No 二分类；QAEgo4D 视频较短（4~20 分钟）；更复杂的多针检索、开放域长视频问答未覆盖。

### 8.3 应用限制

- **依赖相关性标注**：训练需要每帧/每图像的 relevance label，在真实无标注场景中获取此类监督信号的成本可能较高。
- **检索预算 K 的选择**：K 是超参数，且最优 K 因任务类型（summarization vs. 关键信息检索）差异巨大，实际部署时需任务特定调整。
- **长视频编码占主导耗时**：虽然 KV cache 可复用，但每视频仍需约 14.7 秒的编码时间，对实时性要求高的场景仍是瓶颈。
- **domain shift 风险**：在图像数据上做 partial tuning 会降低视频任务表现，表明微调方向需谨慎选择。
