## 摘要
稀疏检索支撑着现代搜索系统，从网络搜索到检索增强生成。已有工作引入了学习型稀疏检索（LSR）以超越精确词汇匹配，迈向更丰富的语义。然而，LSR至今仍局限于编码器风格的双向架构，其向多模态场景的扩展也仍高度依赖辅助的跨模态模块。为解决这些局限，我们提出了UEmbed（统一嵌入），一种仅解码器的多模态嵌入模型，在单次因果前向传播中同时生成稀疏词汇表示和稠密表示。UEmbed在输入后附加N个可学习的特殊标记，并将词表划分为N个不相交的子集。每个标记的因果隐藏状态对其分配的子集预测稀疏权重，然后将这N个子集拼接成完整的稀疏向量。在公开数据上训练后，我们发布了UEmbed的2B、4B和9B三种规模版本。UEmbed-9B在MMEB-v2上达到了71.8（稠密）和71.0（稀疏）的成绩，优于在公开可用数据上训练的多模态嵌入模型（如RzenEmbed）。在BEIR上，UEmbed也与强大的稠密和稀疏基线保持竞争力。此外，我们从三个维度展示了UEmbed的实际效用：有效性、效率和智能体应用。总体而言，UEmbed提供了一种新范式：在一个模型中统一稠密和稀疏嵌入，同时进一步扩展稀疏检索以统一文本和多模态输入。

## Abstract
Sparse retrieval underpins modern search systems, from web search to retrieval-augmented generation. Existing work has introduced Learned Sparse Retrieval (LSR) to push beyond exact lexical matching toward richer semantics. Yet LSR has so far remained tied to encoder-style bidirectional architectures, and its extension to multimodal settings still relies heavily on auxiliary cross-modal modules. To address these limitations, we introduce UEmbed (Unified Embedding), a decoder-only multimodal embedding model that produces both sparse lexical and dense representations in one causal forward pass. UEmbed appends N learnable special tokens to the input and partitions the vocabulary into N disjoint subsets. Each token's causal hidden state predicts sparse weights over its assigned subset, and the N subsets are concatenated into the full sparse vector. Trained on public data, we release UEmbed at 2B, 4B, and 9B scales. UEmbed-9B reaches 71.8 (dense) and 71.0 (sparse) on MMEB-v2, outperforming multimodal embedding models trained on publicly available data (e.g., RzenEmbed). On BEIR, UEmbed also remains competitive with strong dense and sparse baselines. Furthermore, we demonstrate the practical utility of UEmbed across three dimensions: effectiveness, efficiency, and agentic applications. Overall, UEmbed offers a new paradigm: it unifies dense and sparse embeddings in one model, while further extending sparse retrieval to unify text and multimodal inputs.

- **核心挑战**：从因果模型中导出稀疏表示存在信息瓶颈——依赖单一 token（如 EOS 或 CLS）投影到巨大的 |V| 维词汇空间，表征能力严重受限。

## 2. 方法论：核心思想与关键技术细节

### 核心思想
- 在输入序列后追加 **N 个可学习的特殊标记**（⟨s1⟩…⟨sN⟩），并将词汇表划分为 **N 个不相交的子集**。每个特殊标记在因果注意力下汇总全部前置输入，仅对其指定子集内的词项预测稀疏权重，N 个子集拼接后构成完整稀疏向量。这有效绕过了单 token 投影到全词表的信息瓶颈。
- 稠密表示则由特殊标记之前的 EOS token 的隐藏状态获得；仅需稠密检索时可完全省略特殊标记，不引入额外计算。

### 关键技术细节
- **词汇表压缩**：通过去重音符号、小写化、折叠空白字符（NLTK），将词表从 248,320 压缩至 184,016，减少冗余 token 并提升表示稳定性。
- **分区稀疏头**：
  - 使用 **k-means 聚类**对压缩后的词汇进行语义聚类，将每一个簇分配给一个特殊标记（语义分区策略），使每个标记成为"软主题专家"。
  - 稀疏权重计算公式（对于属于第 k 个子集的词项 t）：
    - w(k)_t = log(1 + ReLU(W(k)_t^⊤ h_{sk} + b(k)_t))
    - 其中 h_{sk} 为第 k 个特殊标记的最终隐藏状态，W、b 为该词项对应的线性投影权重。
  - 最终稀疏向量 w = 拼接各子集向量构成完整 |V| 维稀疏向量，可直接由倒排索引服务。
- **统一训练目标**：
  - L = L^dense_InfoNCE + λ·L^sparse_InfoNCE + αq·L^q_FLOPS + αd·L^d_FLOPS
  - 稠密损失使用余弦相似度，稀疏损失使用内积相似度；FLOPS 正则化项惩罚平均词项权重平方，鼓励稀疏性。
  - 关键超参数：稀疏温度 τs=32（与稠密温度 0.03 解耦，避免内积动态范围过大导致稀疏 softmax 过度锐化）；λ=1.0；αq=αd=1e-4。
- **数据整理**：
  - 数据源：Echo-embedding（文本）、MLDR（长文档）、MMEB 训练集（多模态），共 394 万对
  - 使用 Qwen3-VL-Embedding-8B 作为教师模型，为多模态数据挖掘硬负样本（top-k 最相似但不相关的文档）

## 6. 主要结论与发现

1. **统一架构的有效性**：UEmbed-9B（稠密）在 MMEB-v2 上达 71.8，领先所有公开数据训练的多模态嵌入模型（如 RzenEmbed-V2-7B 71.1；Ops-MM-Embed-7B 67.1）；UEmbed-2B（66.5）甚至超越部分 7B 级别开源模型（如 UniME-7B 64.1）。
2. **稀疏与稠密性能高度接近**：各规模下稀疏与稠密平均差距 ≤1.0 点（9B：71.8 vs. 71.0）。这是 MMEB-v2 上首次报告的稀疏多模态检索结果，确立了稀疏多模态检索的新 SOTA；UEmbed-4B（稀疏）69.7 甚至超过稠密的 Ops-MM-Embed-7B（67.1）。
3. **文本检索竞争力不减**：BEIR 上 UEmbed-9B 稠密平均 56.3 和稀疏，均超过或持平强基线（如 Qwen3-VL-Embedding-8B 55.5、Echo-Mistral-SPLADE 55.2），而在如此表现的同时仍支持多模态与稠密检索。
4. **因果公式化优于双向 SPLADE 基线**：UEmbed 比共享主干/数据/正则化的双向 SPLADE 基线在稠密和稀疏上分别提升 3.2 和 2.1 个点（MMEB-v1 图像子集）。
5. **联合训练无损**：联合稠密-稀疏训练与单模式训练效果相当，无负迁移问题。
6. **语义分词表分区最优**：k-means 语义聚类优于随机分区和最大距离配对策略。
7. **实际效用三维验证**：
   - 混合打分（稠密+稀疏线性插值）在文本和视觉文档上分别提升 0.3 和 0.5 个点；
   - 纯自回归设计天然兼容 vLLM 等高速服务框架，稀疏表示可接入 Lucene 等标准倒排索引，并支持按最大激活 token 数裁剪以权衡延迟与精度；
   - 在 BrowseComp-Plus 上，稀疏模式比稠密模式减少工具调用轮次（如 9B：31.05 vs. 33.68），且召回相当，对成本敏感的迭代推理场景具有实际价值。

## 7. 优点

- **架构创新**：首次在纯因果解码器上实现原生稀疏检索，克服了单 token 信息瓶颈，无需双向化改造或辅助跨模态模块，保持与主流自回归服务框架（vLLM）的兼容性。
- **真正的统一性**：一个模型、一次前向、一份权重同时输出词汇级稀疏表示和语义稠密表示，同时支持文本、图像、视频、视觉文档等多种模态，并能以统一的稀疏/稠密双模式进行混合检索。
- **方法简洁可扩展**：通过"N 个特殊 token + 词汇表分区 + k-means 语义聚类"这一简洁方案解决复杂问题，可轻松扩展到新模态和新规模。
- **实验严谨**：区分公开数据与私有数据训练模型、刻意选择公平对比基线、提供随机种子复验和逐错误案例分析，展现了较高的客观性。
- **实用性导向**：在理论评测之外，从混合检索增益、服务效率（倒排索引 + 延迟-精度权衡曲线）、智能体工具调用成本三个维度验证了真实部署价值。
- **可解释性优势**：稀疏激活词项天然提供一定程度的可解释性，有助于偏见审计和错误诊断。

## 8. 不足与局限

- **语言与文化偏差**：训练语料以英文和中文为主，稀疏激活对其他语言支持有限，跨语言泛化需要大规模多语言训练数据。
- **词汇表稳定性问题**：LLM 超大词表导致模型偶尔激活非标准子词或伪 token（如 "_alt"），在严格的生成环境中需要进一步词汇压缩、语义聚类优化或后置过滤机制。
- **视频域性能差距**：稀疏与稠密在视频类别上的差距比其他模态更明显，反映视频帧的高信息密度和时间动态特性可能对扁平稀疏向量构成表征瓶颈。
- **BEIR 覆盖有限**：仅选用 9 个 BEIR 数据集，未覆盖完整 BEIR 基准，泛化结论的支撑力有限。
- **分类任务的稀疏激活质量**：案例研究显示，稀疏表示在分类任务上容易过度关联无关概念，指令遵循能力较弱。
- **训练数据规模限制**：对比的私有数据模型（如 Qwen3-VL-Embedding-8B）在多模态数据量和多阶段训练上占优，UEmbed 在部分视频推理任务（动作识别、时间定位）上差距较明显；论文将原因归于视频专用数据不足和缺乏 reranker 蒸馏目标（如 rank-KL）。
- **训练时长未披露**：论文未明确说明各规模的训练耗时，不利于复现时预估资源需求。
