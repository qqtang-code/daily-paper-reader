## 摘要
KV缓存压缩减少了长上下文内存占用，但聚合任务分数无法揭示哪些正确的执行失败了，以及为什么失败。我们提出了KVDiagnosis，一个诊断数据集和基准，包含三项贡献。第一，一个包含25种方法的分类法，将方法归为五个机制家族，并将其与八个已实现的验证版本及其有效的诊断测量联系起来。第二，对于每种受支持的方法设置，我们在每个固定分割中评估所有来源，并对照每源的FullCache控制，然后分别为每种方法设置选择FullCache正确/压缩错误（C-to-W）的行，因此没有压缩器定义另一个压缩器的测试集。第三，一种通用的记录格式将配对输出和运行元数据与缓存、似然、注意力和解码测量联系起来，并明确标注适用状态。在Qwen3-8B上，四个证据感知工作负载在2600个来源上产生了59,800次受支持的压缩运行，以及12,520个C-to-W行。在固定诊断规则下，63.2%的行具有低或部分的测量/预计覆盖率。只有19行（0.2%）结合了高测量/预计覆盖率与强似然漂移；另有2,126行（17.0%）保持了结构位置可寻址性，其表示保真度仍然未知，同时表现出相同的漂移。与C-to-C成功控制相比，所有十项诊断都能区分失败和成功的压缩（分层AUROC 0.684-0.871）。在96个可复现的低EAR失败中，控制下的4倍证据注意力提升修复了29.2%，而计数匹配的假干预为6.3%，匹配的C-to-C控制退化3.3%。代码和数据可在https://github.com/ChosenQC/KVDiagnosis获取。

## Abstract
KV-cache compression reduces long-context memory, but aggregate task scores reveal neither which correct executions fail nor why. We present KVDiagnosis, a diagnostic dataset and benchmark with three contributions. First, a 25-method taxonomy groups methods into five mechanism families and links them to eight verified implementations and their valid diagnostic measurements. Second, for every supported method setting, we evaluate all sources in each fixed split against a per-source FullCache control before selecting FullCache-correct/compressed-wrong (C-to-W) rows separately for each method-setting, so no compressor defines another's test set. Third, a common record format links paired outputs and run metadata to cache, likelihood, attention, and decoding measurements with explicit applicability states. On Qwen3-8B, four evidence-aware workloads yield 59 800 supported compressed runs over 2600 sources and 12 520 C-to-W rows. Under fixed diagnostic rules, 63.2% have low or partial measured/projected coverage. Only 19 rows (0.2%) combine high measured/projected coverage with strong likelihood drift; another 2,126 (17.0%) preserve structural position addressability, for which representation fidelity remains unknown, while showing the same drift. Against C-to-C success controls, all ten diagnostics separate failed from successful compression (stratified AUROC 0.684-0.871). Among 96 reproducible low-EAR failures, a controlled 4x evidence-attention boost repairs 29.2%, versus 6.3% under a count-matched sham intervention and 3.3% degradation on matched C-to-C controls. Code and data are available at https://github.com/ChosenQC/KVDiagnosis.

## 1. 核心问题与整体含义

KV缓存压缩是缓解长上下文大语言模型推理内存瓶颈的重要技术，但现有评估体系存在一个关键缺口：**聚合任务分数（如平均准确率）无法揭示"哪些原本正确的回答在压缩后失败"以及"为什么失败"**。不同压缩方法操作不同的对象——有的驱逐token位置，有的重分配层/头预算，有的裁剪通道、量化张量、压缩语义单元——因此"压缩50%"在不同方法下含义完全不同。缺乏结构化的失败归因机制，研究者难以判断失败源于证据被删除、保留条目表示被破坏、生成时访问能力下降，还是解码/评分阶段出现变化，也无法据此选择正确的修复策略。

KVDiagnosis作为一个诊断基准，核心贡献在于**将"质量评估"与"失败归因"分离**：对所有压缩运行提供逐源FullCache配对控制，按方法–设置分别筛选C→W（FullCache正确但压缩后错误）行，并为每行附加有效且适用于该机制的缓存、似然、注意力和解码层面的诊断测量。

## 2. 方法论

### 2.1 总体框架与流程

基准流程严格遵循"先完整评估，再筛选失败"的顺序：

1. 每个源（source）执行一次FullCache作为配对控制，并复用该控制。
2. 每个受支持的方法–设置单元在固定分割的全部源上运行，记录状态、输出、评分。
3. 全部运行完成后，才按单元提取该单元自身的C→W行（即`FullCache正确 ∧ 压缩错误`）。
4. 对C→W行逐一附加适用的诊断指标；不支持、执行错误或不适用的痕迹保留为显式状态码（N/A）而非被删除。

这种方法确保了**没有任何压缩器定义另一压缩器的测试集**，方法特有失败集保留完整，交集仅用于匹配比较（报告交集、并集和Jaccard相似度）。

### 2.2 25方法机制分类法

论文将25种代表方法按"主要压缩决策与变换对象"归为五个机制家族：

| 家族 | 代表方法 | 变换对象 |
|---|---|---|
| Token eviction / position selection | StreamingLLM、H2O、Scissorhands、TOVA、SnapKV、KeyDiff | token位置 |
| Budget allocation / hierarchy | PyramidKV、AdaKV、HeadKV、PolyKV | 层/头配额 |
| Query-aware access / channel pruning | ThinK、Keyformer、Quest、Q-Filters、CHESS | 块、位置或通道 |
| Tensor / representation compression | QuantizedCache、KIVI、KVQuant、CommVQ、Palu、SALS | 精度或隐维度 |
| Chunk / semantic / learned state | ChunkKV、DMC、KVzip、SCOPE | 块或KV状态 |

其中**8个实现通过验证并纳入评估**：StreamingLLM、SnapKV、TOVA、KeyDiff、ThinK、ChunkKV、AdaKV、QuantizedCache（HQQ）。

### 2.3 关键评估与诊断指标

- **质量指标**：任务分数（task score）按全源计算；压缩诱导失败率 `r_CW = |C→W| / |FullCache正确源数|`。
- **缓存保留**（仅对直接或投影的原始token映射有效）：
  - `ERR`：证据保留率（槽平均）；
  - `ECov`：证据覆盖阈值（τ=0.5）下的槽平均覆盖率。
  - ThinK与QuantizedCache仅记录"结构位置可寻址性"，ERR/ECov为N/A，因为表示保真度未知。
- **预测分布**：在相同参考token上计算FullCache与压缩的teacher-forced NLL，派生ΔNLL、几何概率比（GPR）、KL散度、Top-50重叠、gold-token秩位移。
- **注意力访问**：基于有效的eager trace，计算证据注意力质量（EAM）、证据注意力保留（EAR = 压缩EAM/FullCache EAM）和归一化证据注意力富集（NEAE）。
- **解码/评分**：记录首/平均gold秩、生成token数、停止原因和归一化输出。
- **预定义诊断分类规则**（6类互斥+2类组合）：低映射覆盖率、部分映射覆盖率、高映射覆盖率漂移、结构位置漂移、低EAR候选、解码/评分候选、冲突信号、模糊。

## 6. 主要结论与发现

1. **失败频率与形态多样**：C→W率随压缩强度从轻到重（75%→25%或8b→2b）在工作负载上从8%/7%/10%/9%升至46%/42%/36%/40%；方法间差异显著，ThinK在50%时崩溃且25%不支持。
2. **低/部分证据覆盖率是主要失败特征**：全部12,520个失败行中，40.3%为低映射覆盖率、22.9%为部分映射覆盖率；证据标注QA（Qasper+HotpotQA）中这一组合占比64.8%和64.7%。
3. **结构可寻址性不等于表示保真度**：仅19行（0.2%）在映射ECov≥0.90的同时出现强似然漂移；另有2,126行（17.0%）在ThinK/QuantizedCache下保持结构位置可寻址但同样出现漂移——这提示必须搭配似然/保真度诊断，不能把"位置可寻址"当作"覆盖率"。
4. **十项诊断均能有效区分失败与成功压缩**：分层AUROC 0.684–0.871；gold秩位移（0.871）、KL（0.869）、ΔNLL（0.853）、Top-50不一致（0.850）和EAR损失（0.823）最强；EAM/NEAE较弱且方法间变异较大。
5. **低EAR可预测选择性修复**：仅证据注意力提升（非假干预）能显著修复低EAR失败，支持其作为"访问/路由缺陷"的可操作信号。
6. **相似聚合质量不意味着失败可互换**：SnapKV和TOVA平均分相近（84.8 vs 85.7），但11/12的工作负载–设置单元中两者失败集Jaccard≤0.385。

8. **诊断归因具有可操作性，指向不同修复策略**：低覆盖率失败对应证据被驱逐或未写入，需要通过调整保留策略或增大预算来修复；低EAR失败对应证据在缓存中但注意力访问能力受损，可通过注意力增强或路由干预来修复。干预实验证明这种区分不是描述性的，而是能够预测修复效果的。此外，存在“冲突信号”和“模糊”类行，说明部分失败由多种机制共同导致，单一修复手段可能无效，需要联合诊断。

## 7. 局限性

- **方法覆盖不完整**：25种方法中仅8种通过实现验证并纳入评估，其余17种因代码不可复现、依赖不兼容或适配器审计失败而被排除。该基准的机制分类法覆盖了五个家族，但每个家族内被验证的方法数量有限，可能无法完全代表该家族的典型行为。
- **证据标注依赖**：缓存映射类诊断（ERR/ECov/EAM）依赖生成器提供的精确证据位置，对于证据缺失或映射模糊的源，相关诊断只能标记为N/A而非参与归因。在Qasper/HotpotQA上这类源的比例未被明确披露，可能影响证据相关结论的覆盖完整性。
- **干预实验规模较小**：96个可复现低EAR失败仅来自部分工作负载–设置单元，且只验证了“注意力增强”这一种修复机制；低覆盖率失败对应的“增加预算/重新保留”修复未做同等规模的干预验证，因此诊断→修复的因果链只对一类机制得到了强验证。
- **资源成本未透明披露**：虽然给出了单次运行的硬件配置，但未报告总GPU小时、能耗或生成62,400条记录的总成本，这既影响可复现性，也使后续研究者难以预估扩展成本。
- **模型规模范围有限**：跨模型验证覆盖7B–24B，未包含70B以上模型；KV压缩通常在更大模型上内存收益更显著，但大规模模型上的失败模式与诊断指标表现尚未得到验证。

## 8. 总体评价与意义

KVDiagnosis的实质贡献在于**把“压缩失败”从聚合分数的暗数变成一个可结构化归因的对象**。它通过配对FullCache控制、机制感知的诊断指标体系以及预定义的分类规则，使研究者能够回答三个此前难以回答的问题：失败发生在哪些源上？证据在缓存中是否仍然存在？如果存在，模型是否仍然能够访问并使用它？这种“存在性”与“可访问性”的分离，恰好对应了缓存压缩中完全不同的修复路径。

同时，该基准刻意避免了两个常见陷阱：一是用聚合分数掩盖方法间的失败差异，二是用一套不适用于所有方法的诊断指标强行比较不同机制。其对N/A的显式保留、按方法–设置筛选失败集、用交集/Jaccard而非统一排名进行比较，体现了评测设计上的严谨性。

从实际价值看，KVDiagnosis为KV压缩研究提供了一条从“提升平均分”转向“理解并修复特定失败模式”的路径；其诊断分类规则也可作为未来自动失败分析工具的基础。但该基准目前仍是一个以8种方法、3种模型为支撑的初步框架，其方法覆盖的广度和干预验证的深度仍有待扩展。
