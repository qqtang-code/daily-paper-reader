## 摘要
随着长上下文大语言模型（LLM）的快速普及，解码过程中持续增长的KV缓存已成为关键的内存瓶颈。为应对这一挑战，我们提出HiKV，一种通过层级重要性感知利用KV缓存冗余的算法-硬件协同设计方案。在算法层面，HiKV以两种粒度压缩KV缓存：阶段一在固定预算内驱逐不重要令牌，阶段二进一步仅加载每个保留令牌中的重要元素，达到单一粒度无法实现的压缩比。在架构层面，我们开发了一个专用加速器，其核心是可重构重要性排序器，可在两个阶段所需的差异化排序数据路径间切换，以最小开销将两阶段加速统一到单一电路中。在代表性LLM上的评估表明，与原始KV缓存基线相比，HiKV在注意力计算中实现了最高7.95倍加速和90%能耗降低，且精度损失可忽略不计（1%）。在等精度约束下，HiKV比现有最先进的重要性方法额外减少1.82~4.87倍的外部内存访问。这些优势得益于专用硬件组件，其仅增加8%的系统面积。

## Abstract
With the rapid adoption of long-context large language models (LLMs), the continuously growing KV cache during decoding has become the critical memory bottleneck. To tackle this challenge, we propose HiKV, a novel algorithm-hardware co-design that exploits KV cache redundancy through hierarchical importance awareness. Algorithmically, HiKV compresses the KV cache at two granularities: Stage I evicts unimportant tokens within a fixed budget, and Stage II further loads only the significant elements of each retained token, reaching compression ratios unattainable at a single granularity. Architecturally, we develop a dedicated accelerator centered on a reconfigurable importance sorter that switches between the distinct sorting datapaths each stage requires, unifying the two-stage acceleration in one circuit with minimal overhead. Evaluated on representative LLMs, HiKV achieves up to 7.95x speedup and 90% energy reduction in the attention computation over the vanilla KV cache baseline within negligible 1% accuracy loss. Under iso-accuracy constraints, HiKV outperforms state-of-the-art importance-based methods by achieving an additional 1.82~4.87x reduction in external memory accesses. These benefits are enabled by specialized hardware components that add only 8% to the system area.

- **HiKV的动机**：通过分层（token级+element级）重要性感知压缩，配合专用硬件加速，在保证精度（<1%损失）的前提下大幅减少外部内存访问，突破单粒度瓶颈。

## 2. 方法论：核心思想、关键技术细节、算法流程
- **核心思想**：利用注意分数分布的非均匀性，在**两个正交粒度**上压缩KV缓存：  
  - **Stage I（token级粗粒度）**：维持固定预算，保留重要token，驱逐不重要token。  
  - **Stage II（element级细粒度）**：对每个保留token，仅加载其重要元素（K侧按Q元素幅度选择，V侧按P向量分块选择）。
- **关键技术细节**：
  - **Stage I**：采用**双银行结构**（最近token银行R + 重要token银行I），预算各占一半。对R中的token，在后续`BI/2`步内累加注意分数作为重要性分数（IS），R中最老token移出时与I中最小IS比较决定是否晋升；I采用**冻结IS + 最小堆**维护，驱逐复杂度从O(BI)降至O(log BI)。
  - **Stage II**：  
    - **K侧**：对Q向量进行全局排序，选择幅度最大的`BII`个元素（`BII = dh/rII`），指导对应K cache加载。  
    - **V侧**：对softmax后的P向量进行**分块排序**（块大小=dh），每个块独立选top-BII元素，避免O(N log N)全局排序，降为O(N log dh)，且召回率超过95%。
  - **两阶段协作**：在Step内顺序执行：QK T前先Stage II（K侧）→ QK T → Stage I（IS更新+堆维护）→ Stage II（V侧）→ P V计算。
- **算法流程**（Algorithm 1）：  
  1. 获取token集合（R ∪ I）  
  2. 对Qt选top-BII元素，加载对应K  
  3. 计算Pt = softmax(Q·K^T)  
  4. 更新R中各token的IS，评估最老token是否晋升  
  5. 对Pt分块，每块选top-BII元素，加载对应V  
  6. 计算输出Ot = Pt·V，追加新token的KV到R

## 7. 优点
- **算法层面**：  
  - 首次提出**分层重要性感知**（token+element），压缩比远超单粒度方法。  
  - Stage II分块排序策略在保证高召回率（>95%）的同时大幅降低排序复杂度。  
  - Stage I采用局部累积+冻结堆，避免全局排序，兼顾精确性和低开销。  
- **硬件层面**：  
  - **可重构重要性排序器（RIS）** 设计巧妙，通过复用2输入双调排序器实现四种模式，减少硬件开销。  
  - 数据路径与存储布局（K cache element-first, V cache chunk-indexed）适配两级访问模式。  
  - 排序过程中跳过已确认非top-k区间，进一步降低动态功耗。  
- **全面性**：算法+硬件联合优化，端到端效果显著，且对多种LLM架构通用。
