## 摘要
长上下文、多轮和智能体LLM工作负载越来越多地重用先前处理过的上下文，使得KV缓存重用对减少冗余计算至关重要。然而，这种重用将瓶颈转移到了在集群规模下存储和提供可重用KV状态的内存层。GPU HBM和主机DRAM成本过高，无法扩展到TB级的共享上下文容量，这促使我们采用由低成本、高容量介质构建的远程层。本文提出了HyMCache，一个集成CXL混合内存（CXL-HM）的多轮LLM服务KV缓存框架。CXL-HM将少量的设备内DRAM与通过CXL接口连接的大容量SSD后端组合在一起。通过利用多轮KV缓存访问的读主导、可预测和仅追加特性，HyMCache重新思考了CXL-HM内部的DRAM管理，以高效支持TB级SSD后端KV重用。它采用请求级前缀预取和机会性写缓冲，将延迟关键型读取暂存到设备DRAM中，从而以SSD级别的成本实现DRAM级别的KV缓存效率。我们在真实CXL-HM原型上，在单聚合器和PD分离服务配置下评估了HyMCache。在相同的DRAM预算下，HyMCache在单节点服务中性能优于本地LMCache 3.0倍，在PD分离服务中性能优于本地LMCache 1.45倍。与1TB分布式DRAM的Mooncake相比，HyMCache性能降低约30%，但DRAM使用量减少16倍。

## Abstract
Long-context, multi-turn, and agentic LLM workloads increasingly reuse previously processed context, making KV-cache reuse essential for reducing redundant computation. However, this reuse shifts the bottleneck to the memory tier that stores and serves reusable KV states at cluster scale. GPU HBM and host DRAM are too costly to scale to TB-scale shared context capacity, motivating remote tiers built from lower-cost, higher-capacity media. This paper presents HyMCache, a KV-cache framework that integrates CXL-hybrid memory (CXL-HM) for multi-turn LLM serving. CXL-HM combines a small amount of in-device DRAM with large SSD-backed capacity behind a CXL interface. By exploiting the read-dominant, predictable, and append-only nature of multi-turn KV-cache access, HyMCache rethinks DRAM management within CXL-HM to efficiently support TB-scale SSD-backed KV reuse. It uses request-level prefix prefetching and opportunistic write buffering to stage latency-critical reads in device DRAM, enabling DRAM-scale KV-cache efficiency at SSD-level cost. We evaluate HyMCache on a real CXL-HM prototype under both single-aggregator and PD-disaggregated serving configurations. Under the same DRAM budget, HyMCache outperforms local LMCache by 3.0x in single-node serving and 1.45x in PD-disaggregated serving. Compared with 1 TB distributed-DRAM Mooncake, HyMCache incurs about 30% lower performance but uses 16x less DRAM.

## 2. 论文提出的方法论：核心思想、关键技术细节
- **核心思想**：利用多轮 KV 缓存访问的“读主导、可预测、仅追加”特性，重新设计 CXL-HM 内部的 DRAM 管理策略，从传统的透明 LRU 缓存转向“显式管理的暂存空间”，通过请求级前缀预取和机会性写缓冲，使延迟关键的 KV 块始终位于设备 DRAM 内部，而大容量 SSD 用于持久化存储。
- **关键技术细节**：
  - **CXL-HM 设备设计**：设备内部包含少量 DRAM（如 64 GB）和 SSD 后端（如 2×1 TB），通过 CXL.mem 接口暴露为统一内存地址空间，对主机透明。内部 DRAM 不作为容量缓存，而是作为“延迟隐藏暂存窗口”。
  - **请求级前缀预取**：利用多轮前缀缓存查找的有序列表，在 KV 块被实际读取前，通过显式 `chm_prefetch_object` API 将其从 SSD 预取到设备 DRAM，实现流水线化。
  - **写隔离与机会性缓冲**：新生成的 KV 块先写入一个小型写缓冲，在读取压力低时异步批量刷回 SSD，避免读写干扰，且写缓冲满时允许跳过写入（后续轮次重试）。
  - **用户级预取协调**：提供 `issue–wait–release` 三级 API，由 KV Manager 模块管理每个请求的预取窗口（默认约 128 MB），确保预取顺序与 RDMA 读取顺序一致。
  - **统一地址空间与跨请求负载均衡**：每个 CXL-HM 设备映射为一个 NUMA 节点，KV 块按请求粒度分配到同一设备，保持有序访问；跨请求则采用轮询或负载感知分配。
  - **软件集成**：在 Dynamo + vLLM 的 serving 栈中新增 Master、Lookup、KV Connector、KV Manager 四个模块，实现元数据查找、远程地址解析、预取协调和数据传输的分离。

## 6. 论文的主要结论与发现
- **主要结论**：HyMCache 能够以 SSD 级别的成本（约 $10.5K–$11K）提供接近 DRAM 级别的 KV 缓存服务效率。在相同 DRAM 预算下，单节点服务中性能是本地 LMCache 的 3.0 倍；PD 分离服务中是 LMCache 的 1.45 倍。相比 1 TB 分布式 DRAM 的 Mooncake，HyMCache 性能仅低约 30%，但 DRAM 使用量减少 16 倍。
- **关键发现**：
  - 多轮 KV 缓存访问具有可预测的前缀顺序，因此显式预取可以大幅提高命中率。
  - 传统 LRU 缓存策略不适合这种扫描式访问（one-hit-wonder）；HyMCache 通过暂存窗口和写隔离消除了此问题。
  - NVMe-oF 软件栈（如 XFS）会给远程 KV 读取引入巨大开销（带宽从 23 GB/s 降到 6.5 GB/s），而 CXL-HM 的内存语义避免了文件系统栈，性能更优。
  - 分布式 DRAM 方案在传输缓冲区不足时性能退化严重，HyMCache 因机会写缓冲对缓冲区大小不敏感。

## 7. 优点：方法或实验设计上的亮点
- **创新性**：首次将 CXL 混合内存专门用于多轮 LLM 服务的 KV 缓存，并重新设计了设备 DRAM 管理策略，与 LLM 工作负载特性深度匹配。
- **硬件-软件协同设计**：提供了暴露给 serving 框架的预取 API（chm_prefetch_*），使得系统级别的 KV 元数据能与设备内部 DRAM 状态同步，实现了从 SSD 到 DRAM 再到 GPU 的流水线预取。
- **写隔离策略**：避免写操作干扰读关键路径，有效降低读延迟。
- **实验设计扎实**：不仅对比了最先进的分布式 DRAM 方案（Mooncake）和本地缓存（LMCache），还分析了不同传输缓冲区大小、NVMe-oF 对比、预取消融实验，以及成本估算表格，验证了实用性和成本效益。
- **透明可扩展结构**：CXL-HM 设备可以堆叠增加容量，而无需按比例增加 DRAM 成本，具备良好的扩展潜力。
