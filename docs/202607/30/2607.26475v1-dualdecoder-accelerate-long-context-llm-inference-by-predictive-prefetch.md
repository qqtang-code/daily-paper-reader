## 摘要
长上下文推理正在成为现代LLM服务的一项基础能力，尤其是受新兴的代理型应用驱动。然而它面临严重的内存墙问题，即KV缓存随上下文长度和请求并发度成比例增长。现有的稀疏KV缓存方法将大部分KV条目卸载到主机内存，仅在每个解码步骤检索所需的临界KV条目。但它们通常会在GPU内存中引入大量辅助状态用于KV检索管理。我们的测量表明，这些常被忽视的辅助状态带来了显著的内存开销，并在高并发工作负载下成为新的瓶颈。本文提出DualDecoder，一个用于长上下文LLM推理的轻量级服务系统，支持从主机内存高效检索稀疏KV缓存。我们的关键洞察是：解码下一个token所需的临界KV条目可以从之前的推测token中准确预测。这种可预测性使得KV检索可以主动预取并与解码计算重叠，有效消除辅助状态的GPU内存开销。为了高效实现这种预取，DualDecoder利用新颖的双token解码流水线，以可忽略的计算开销准确识别临界KV条目，并设计了一种层感知传输调度以重叠KV预取与模型计算，以及一种层范围的内存管理器以减少GPU运行时缓冲区。实验结果表明，DualDecoder在保持解码延迟和模型质量的同时，解码吞吐量相比最先进的系统提升了高达2.62倍。

## Abstract
Long-context inference is becoming a fundamental capability for modern LLM serving, especially driven by emerging agentic applications. Yet it faces a severe memory wall that the KV cache scales proportionally with increasing context length and request concurrency. Existing sparse KV cache methods offload most KV entries to host memory and retrieve only the critical KV entries needed by each decoding step. However, they commonly introduce substantial auxiliary states in GPU memory for KV retrieval management. Our measurements show that these often-overlooked auxiliary states introduce significant memory overhead and become a new bottleneck under high-concurrency workloads.   In this paper, we present DualDecoder, a lightweight serving system for long-context LLM inference that enables efficient sparse KV cache retrieval from host memory. Our key insight is that the critical KV entries required for decoding the next token can be accurately predicted from the preceding speculated token. This predictability enables KV retrieval to be proactively prefetched and overlapped with decoding computation, effectively eliminating the GPU memory overhead of auxiliary states. To achieve this prefetching efficiently, DualDecoder leverages a novel dual-token decoding pipeline that accurately identifies critical KV entries with negligible computational overhead, and designs a layer-aware transfer schedule to overlap KV prefetching with model computation and a layer-scoped memory manager to reduce the GPU runtime buffer. Experimental results show that DualDecoder improves decoding throughput by up to 2.62$\times$ over state-of-the-art systems while preserving decoding latency and model quality.

### **DualDecoder: 通过预测性预取加速长上下文LLM推理 - 论文深度总结**

#### **1. 论文的核心问题与整体含义（研究动机和背景）**

*   **核心问题**：长上下文LLM推理面临严重的“内存墙”问题，即KV缓存的大小与上下文长度和请求并发度成正比增长，极易占满有限的GPU高带宽内存（HBM）。
*   **现有方法的不足**：为缓解此问题，动态稀疏KV缓存技术（如ShadowKV、SpeCache）将大部分KV卸载到主机内存（CPU），只在解码时检索少量关键KV。然而，为了加速检索，这些方法在GPU内存中引入了大量“辅助状态”（auxiliary state），如低秩Key缓存、量化KV表示等。这导致：
    *   **新瓶颈**：在高并发工作负载下，这些辅助状态的内存占用反而成为新的主要瓶颈（论文测量其可占GPU内存的64%）。
    *   **性能受限**：由于内存不足，可同时处理的请求批次大小受限，导致GPU计算资源的浪费，整体解码吞吐量远低于硬件可支撑的上限。
*   **整体含义**：论文旨在从根本上解决上述矛盾。其核心洞察是，与其在GPU内存中存储大量辅助状态来加速检索，不如利用长上下文推理中一个关键特性——**相邻解码步骤之间KV检索模式的可预测性**——来**主动预取**KV条目，从而在不依赖大块GPU辅助状态的前提下，实现高效的KV检索。

#### **2. 论文提出的方法论：核心思想与关键技术**

*   **核心思想**：利用KV检索的可预测性，通过轻量级的推测机制预测下一个解码步骤所需的关键KV条目，并提前将其从主机内存预取到GPU，与当前解码的计算过程重叠，从而隐藏数据传输延迟，并消除对GPU辅助状态的需求。

*   **关键技术 (DualDecoder)**:
    1.  **双Token解码流水线 (Dual-Token Decoding Pipeline)**:
        *   **目标**：在每个解码步内，以极小开销生成一个“推测Token”，用于预测下一个解码步的KV索引。
        *   **方法**：不运行两次自回归解码，而是将当前步骤的**输出Token** (T_i) 和上一步骤的**推测Token** (T‘_{i+1}) 拼接在一起，作为双Token输入。通过巧妙的因果掩码（Causal Mask）确保T_i不会受到T’_{i+1}的影响，从而在一个批次内同时完成两个token的计算。这相比独立运行两次解码，效率更高。
        *   **初始化**：第一个推测Token通过一个轻量的预解码步骤，使用真实的输出Token来初始化，以保证后续推测的质量。

    2.  **推测KV缓存传输调度 (Speculative KV Cache Transfer Schedule)**:
        *   **目标**：高效地将预取的KV条目传输到GPU，并处理预测失误。
        *   **层感知重叠 (Layer-aware Overlap)**：将KV预取与解码计算的各个层对齐。并非一次性预取所有层的KV，而是为当前层的计算窗口开始后，才启动下下层的KV预取，从而在隐藏延迟的同时避免过早占用GPU缓冲区。
        *   **优先级修正传输 (Prioritized Missing KV Transfer)**：当预测失误时，缺失的KV条目被赋予最高优先级（高优先级流），确保它们在当前层的注意力计算开始前被紧急传输，避免解码停滞。
        *   **自适应Key重建 (Adaptive Key Reconstruction)**：对于预测准确率较低的层，可选择使用GPU上的一个非常小的低秩Key缓存来重建缺失的Key，而不是从主机内存中一个一个地获取，以减少紧急传输的开销。

    3.  **层范围KV内存管理 (Layer-Scoped KV Memory Management)**:
        *   **目标**：严格限制预取KV条目在GPU中的缓冲区大小，避免预取行为本身造成新的内存压力。
        *   **双缓冲区乒乓设计 (Two-Layer Ping-Pong Buffer)**：仅维护两个稀疏KV缓冲区。一个作为当前层的计算缓冲区，另一个作为即将到来的层的传输缓冲区。当计算完一层后，两个缓冲区的角色立即交换，实现了跨层的循环利用，将驻留的KV缓冲区从全模型深度减少到恒定两层。
        *   **GPU端稀疏KV组装 (GPU-side Sparse KV Assembly)**：为了避免CPU端因非连续内存拷贝导致的低效，主机传输仅将原始块数据送入GPU暂存区，由GPU端的轻量级内核来完成数据的最终布局调整和合并，利用了GPU的高并行性和内存带宽。
