## 摘要
大型语言模型越来越多地部署有持久的个性化上下文，例如累积的记忆配置文件或长对话历史，这些上下文在用户的多个请求之间共享。生产内存系统（例如Mem0、MemGPT和Zep）会检索此记忆的相关子集并将其注入提示中，迫使服务引擎重复预填充相同的内容。随着检索预算的增长，首令牌延迟（TTFT）会增加，尽管底层内存在请求之间被重复使用。我们提出了InferScale，一种GPU原生的LLM内存系统，它用可重用的KV状态取代重复的提示预填充。InferScale预先计算每个记忆事实的KV表示，将其与语义嵌入一起存储在GPU上，在服务时检索相关事实，并将其KV直接注入vLLM的分页缓存中。为了支持在旋转位置嵌入下动态组装的记忆，我们引入了Chunked RoPE，它在旋转前存储键，并在注入期间应用其服务时的位置。然而，独立编码记忆事实忽略了联合预填充时可用的交叉事实上下文。我们通过上下文窗口编码来缓解这一问题，该编码将每个记忆事实与前面对话上下文的一个小窗口一起编码，同时仅缓存目标事实的KV。InferScale通过vLLM的KV连接器接口实现，无需修改引擎或微调模型。在LoCoMo上的三个开放权重模型上，随着检索预算的增加，InferScale使TTFT几乎保持不变：在k=50时，它将TTFT降低了72-79%（3.6-4.8倍），实现了60.3%的准确率，而Mem0在不进行服务时重新计算的情况下为63.3%，并且在并发负载下提供了3.7-4.5倍的吞吐量。因此，可重用的KV状态将记忆条件服务延迟与检索上下文大小解耦，同时保持应用质量。

## Abstract
Large language models are increasingly deployed with persistent personalized context, such as accumulated memory profiles or long conversation histories, that is shared across a user's many requests. Production memory systems (e.g., Mem0, MemGPT, and Zep) retrieve a relevant subset of this memory and inject it into the prompt, forcing the serving engine to repeatedly prefill the same content. As the retrieval budget grows, time-to-first-token (TTFT) increases even though the underlying memory is reused across requests.   We present InferScale, a GPU-native LLM memory system that replaces repeated prompt prefilling with reusable KV state. InferScale precomputes each memory fact's KV representation, stores it alongside a semantic embedding on the GPU, retrieves relevant facts at serving time, and injects their KV directly into vLLM's paged cache. To support dynamically assembled memories under rotary position embeddings, we introduce Chunked RoPE, which stores keys before rotation and applies their serving-time positions during injection. However, encoding memory facts independently omits the cross-fact context available during joint prefilling. We mitigate this with Context-Window Encoding, which encodes each memory fact together with a small window of preceding conversation context while caching only the target fact's KV.   InferScale is implemented through vLLM's KV-connector interface, requiring neither engine modifications nor model fine-tuning. Across three open-weight models on LoCoMo, InferScale keeps TTFT nearly constant as the retrieval budget increases: at k=50 it reduces TTFT by 72-79% (3.6-4.8x), achieves 60.3% accuracy versus 63.3% for Mem0 without serving-time recomputation, and delivers 3.7-4.5x the throughput under concurrent load. Reusable KV state thus decouples memory-conditioned serving latency from retrieved-context size while preserving application quality.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：大型语言模型（LLM）服务中，持续个性化上下文（如用户记忆、对话历史）被反复检索并注入到提示中，导致每次请求都需要重复预填充相同的记忆内容。随着检索预算（top‑k）增长，首令牌延迟（TTFT）线性增加，即使底层记忆在请求间被重复使用，也无法避免重复计算。
- **背景**：现有生产级记忆系统（如Mem0、MemGPT、Zep）通过检索相关记忆子集并注入提示文本，但依然每次请求都重做全部预填充，造成TTFT随检索量增长。前缀缓存（prefix caching）仅能处理固定前缀，无法应对动态组装的记忆。
- **整体含义**：提出一种新的方法，将记忆的事实预先计算为KV表示并存储在GPU上，在服务时直接注入KV缓存，从而将服务延迟与检索上下文大小解耦，无需模型微调或引擎改动。

## 2. 论文提出的方法论

### 核心思想
- **KV注入**：在因果注意力下，静态记忆事实的KV表示仅依赖于事实本身，独立于查询。因此可在离线时一次性编码，在线请求时直接注入KV缓存，而非每次都重新预填充文本。
- **Chunked RoPE**：存储键时在RoPE旋转之前（pre‑RoPE），注入时根据服务时的位置重新旋转，使一个事实的KV可被任意位置重用，且保持与提示注入完全相同的注意力行为（定理6）。
- **Context‑Window Encoding**：离线编码每个事实时，将其与前面若干轮对话上下文窗口一起编码，但只保留目标事实的KV，从而保留跨事实间上下文信息，弥补独立编码导致的精度损失。

### 关键技术细节
- **离线阶段**：按照Mem0提取事实并用同一LLM编码，但编码时在前缀窗口内运行前向传播，拦截key投影后的值（pre‑RoPE），仅缓存事实的KV和检索embedding。
- **在线阶段**：对查询进行embedding，在GPU上的Jasper索引中检索top‑k事实；利用fact_id映射获取预存KV；应用Chunked RoPE按连续虚拟位置旋转keys；通过vLLM的KV‑Connector接口将KV注入到请求的分页缓存中。
- **精确等价证明**：定理3证明KV注入与提示注入在查询位置上的隐藏状态和输出分布完全相同（前提是位置一致）；定理6证明Chunked RoPE使位置重映射精确；定理8证明上下文窗口编码保留了因果依赖。

### Benchmark
- **对比方法**：Mem0（默认配置，使用Qdrant CPU向量存储和提示注入）作为生产基线；InferScale使用GPU上的Jasper索引和KV注入。

## 6. 论文的主要结论与发现

- **延迟几乎与检索量无关**：在Llama‑3.1‑8B上，k从5到50时TTFT仅增加4%（16.6→17.3 ms），而Mem0增长106%（33.2→68.3 ms）；k=50时InferScale TTFT降低72‑79%（3.6‑4.8倍）。
- **端到端延迟优势**：k=50时查询到首令牌时间InferScale约60 ms vs Mem0约236 ms（Llama），加速约3.9倍。
- **吞吐量近线性扩展**：100并发用户时InferScale QPS 100‑135 vs Mem0 27‑32，提升3.7‑4.5倍；且CPU卸载后吞吐量几乎无损失。
- **准确率接近提示注入**：w=50时InferScale在k=50上准确率60.3% vs Mem0 63.3%（Llama）；w=0的独立编码准确率随k增加下降，而上下文窗口编码恢复单调上升趋势。
- **Chunked RoPE顺序独立**：TTFT不受块排列影响，始终与缓存命中态的延迟持平（16K tokens时4.44倍快于无缓存的提示注入）。
- **经验等价性成立**：在bfloat16非确定性下，KV注入与提示注入输出在大约9/12案例中完全一致或语义等价，语义事实准确率100%。

## 7. 优点

- **方法创新**：首次将记忆注入从token层提升到attention层，提出位置无关的Chunked RoPE和上下文窗口编码，理论上严格证明等价性。
- **工程友好**：通过vLLM的KV‑Connector接口实现，无需修改服务引擎或模型微调，兼容现有检索管线。
- **性能提升显著**：在延迟、吞吐量和准确率三个关键维度均大幅优于现有生产系统，且随模型规模扩大优势更明显。
- **精心设计的消融**：分离了GPU原生检索和KV注入各自的贡献；量化了编码窗口w对准确率和预计算时间的影响；验证了CPU卸载的代价。
- **理论支撑强**：给出多个定理证明KV注入的精确等价性、Chunked RoPE的位置无关性、上下文窗口编码的因果保留。

## 8. 不足与局限

- **实验覆盖有限**：仅使用了LoCoMo一个基准，未在更复杂的RAG或长上下文场景（如多文档问答、持续学习）验证泛化性；仅对比了Mem0，未与LMCache、CacheBlend、RetroInfer等最近的KV重用或稀疏注意力系统直接比较。
- **准确率差距**：在k=50时，InferScale准确率仍低于Mem0约3个百分点（部分在多跳问题上差距可达16个百分点），说明独立编码丢失的交叉事实注意力无法完全被上下文窗口补偿。
- **GPU内存瓶颈**：每个对话KV存储占用1.8‑4.8 GB，限制了单GPU上可同时服务的用户数（Llama约10个用户）。CPU卸载虽可行但增加端到端延迟（约33‑38 ms），且随k增长。
- **不支持在线更新**：当前KV存储构建后只读，不支持增量插入、修改或删除事实，无法适应对话演变。
- **单节点局限**：所有实验在单GPU上进行，未涉及多节点多GPU的KV分片和路由，可扩展性未验证。
- **评判偏差风险**：准确率仅依赖Gemma‑2‑9B一个LLM判断器，未人工交叉验证或使用多个评判器，可能存在系统偏差。
