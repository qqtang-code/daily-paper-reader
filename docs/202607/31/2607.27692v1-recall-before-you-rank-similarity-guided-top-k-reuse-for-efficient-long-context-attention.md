## 摘要
Top-$K$ 稀疏注意力通过仅关注一小部分键值（KV）条目来降低 Softmax 和值聚合的成本。然而，识别这一子集仍需要将当前查询与完整的 KV 缓存进行评分，并执行全局 Top-$K$ 选择，这使得选择器的成本随上下文长度线性增长，从而限制了稀疏注意力在长上下文解码中的实际效率。在本文中，我们引入了 ReTopK，一种无需训练的方法，通过复用历史检索决策来加速动态 Top-$K$ 注意力。ReTopK 基于以下观察：相似查询通常关注重叠的支持集，而部分重叠的支持集仍能保留大部分精确 Top-$K$ 注意力质量。对于每个注意力头，它维护一个有界的查询-支持对历史缓存，为每个新查询检索最相似的缓存查询，将其存储的支持集与最近窗口合并，并仅使用精确的当前查询分数对生成的紧凑候选集重新排序。当复用不可靠时，基于相似性的回退机制会调用全历史的精确 Top-$K$，而周期性精确刷新则限制缓存漂移。ReTopK 保留完整的 KV 缓存，仅复用选定的索引，而非历史分数、注意力权重或输出。在 16K--128K 上下文中，ReTopK 在评估的近似方法中取得了最低的 PG19 困惑度和最高的 NIAH 与 LongBench 分数。在 128K 且 $K=512$ 时，ReTopK 相对于精确 Top-$K$ 仅增加 0.50\% 的困惑度，同时将注意力计算加速了 $3.07\times$。

## Abstract
Top-$K$ sparse attention reduces the cost of Softmax and value aggregation by attending to only a small subset of key--value (KV) entries. However, identifying this subset still requires scoring the current query against the full KV cache and performing global Top-$K$ selection, leaving selector cost linear in context length and limiting the practical efficiency of sparse attention for long-context decoding. In this paper, we introduce ReTopK, a training-free method that accelerates dynamic Top-$K$ attention by reusing historical retrieval decisions. ReTopK builds on the observation that similar queries often attend to overlapping supports and that partially overlapping supports can still preserve most of the Exact Top-$K$ attention mass. For each attention head, it maintains a bounded cache of historical query--support pairs, retrieves the most similar cached queries for each new query, unions their stored supports with a recent window, and reranks only the resulting compact candidate set using exact current-query scores. A similarity-based fallback invokes full-history Exact Top-$K$ when reuse is unreliable, while periodic exact refreshes limit cache drift. ReTopK retains the complete KV cache and reuses only selected indices, rather than historical scores, attention weights, or outputs. Across 16K--128K contexts, ReTopK achieves the lowest PG19 perplexity and the highest NIAH and LongBench scores among the evaluated approximate methods. At 128K with $K=512$, ReTopK incurs only a 0.50\% perplexity increase over Exact Top-$K$ while accelerating attention computation by $3.07\times$.

- **背景**：大语言模型（LLM）在长文档、代码库和长交互历史中解码时，注意力计算成本随 KV 缓存长度线性增长。即便使用 FlashAttention 等 IO 感知内核，也没有消除解码注意力对上下文长度的线性依赖。
- **问题**：Top-K 稀疏注意力虽然将 Softmax 和值聚合限制在 K 个最高分条目上，但**识别这个子集仍需要对完整 KV 缓存计算 QK 分数并执行全局 Top-K 选择**。因此它稀疏化的是“注意力聚合”，而不是“索引发现”。论文指出，全历史 QK 打分和 Top-K 选择在 Exact Top-K 延迟中占比随上下文增长（128K 时可达 95% 以上）。
- **核心研究问题**：能否在不扫描全历史的前提下，动态恢复查询相关的注意力支持集？
- **整体含义**：论文提出 ReTopK，通过复用历史“查询—支持集”检索决策来绕过全历史索引发现，把选择器成本从随上下文线性增长变为有界常数，从而在不逐出任何 KV 条目、不做训练的情况下显著加速长上下文稀疏注意力。

## 2. 方法论

### 核心思想
- **观察依据**：相似查询往往关注重叠的 Top-K 支持集；即使支持集仅部分重叠，仍能保留大部分 Exact Top-K 注意力质量。论文用实验验证了查询余弦相似度与支持集重叠度显著正相关，且 R 个相似历史查询支持集的并集能有效覆盖当前查询的 Exact Top-K 支持。
- **三个设计原则**：(1) 检索决策与产生它的查询一起存储，用查询相似度作为轻量级检索信号；(2) 召回的支持只作为候选，必须用当前查询分数重排；(3) 必须配合针对低置信度和陈旧检索决策的安全机制。

### ReTopK 流程（每个注意力头独立维护）
1. **查询—支持缓存**：维护容量为 C 的 FIFO 缓存，存储归一化历史查询向量及其对应的 Top-K 索引支持集。缓存仅增加有界元数据，完整 KV 缓存保持不变。
2. **相似性召回**：对当前查询计算与所有缓存查询的余弦相似度，取最相似的 R 个缓存条目；若最大相似度低于阈值 τ，则回退到 Exact Top-K。
3. **候选集构建**：将 R 个召回支持集与最近 W 个 token 的窗口取并集，得到紧凑候选集 A_t，大小 M_t ≤ RK + W。
4. **精确重排**：仅对候选集内的 key 计算当前查询的精确 QK 分数，重新选出 Top-K 支持集，再进行稀疏 Softmax−值聚合。
5. **可靠机制**：相似性回退（ρ_max < τ 时走 Exact 路径）处理无可靠匹配的查询；周期性刷新（每 T_r 步执行一次 Exact Top-K）限制缓存长期漂移。
6. **重要性质**：ReTopK 只复用历史索引选择，**不复用历史 QK 分数、注意力权重或输出**；所有保留的分数、权重和值聚合都是用当前查询和原始 KV 计算的。

### 复杂度
- Exact Top-K：每次 O(L_t·d) 全历史 QK + O(L_t) 全局选择。
- ReTopK 复用步：O(C·d) 缓存匹配 + O(RK+W) 候选构建 + O(M_t·d) 候选 QK（M_t ≪ L_t），选择器工作量不随上下文长度增长。

## 6. 主要结论与发现

- 在 16K–128K 上下文中，ReTopK 在所有评估任务上取得了近似方法中最好或次好的质量：PG19 困惑度最低、NIAH 与 LongBench 分数最高（τ=0.90 时 LongBench 平均 52.7，甚至超过 Exact Top-K 的 52.5）。

- 跨模型验证一致：在 Llama-3.1-8B 和 Qwen2.5-14B 上复用率 82.5%–89.6%，困惑度变化 −0.46% 到 +2.76%，加速 1.26×–2.66×，无需逐模型调参。

## 7. 优点

- **思想简洁且有效**：将“相似查询共享注意力支持”这一观察转化为可落地的召回-重排框架，复杂性低且直觉清晰。
- **训练-free、零侵入**：无需修改模型权重，复用历史索引而非分数/权重/输出，保留完整 KV 缓存、不逐出任何 token，保证全局可检索性。
- **可靠性设计完善**：相似性回退 + 周期刷新 + 近窗保护的组合有效防止了错误累积与冷启动问题。
- **实现质量高**：提供了融合 GPU 内核的分级优化（从分离内核到全融合，2.29×–2.57× 额外加速），并做了详细的延迟分解。
- **实验充分且公平**：覆盖多模型、多任务、多长度、跨模型泛化、超参数敏感性、组件消融、长时程稳定性、端到端超长上下文，并对 baseline 配置差异做了透明说明。

## 8. 不足与局限

- **近似性质**：ReTopK 不能保证恢复 Exact Top-K 支持集，存在极端情况下重要 token 未被召回的风险；依赖相似度阈值 τ 和周期刷新来兜底，但并不能从根本上消除这一偏差。
- **无与更多新方法的直接对比**：相关工作提到了 Kascade、IndexCache、PRR 等同样利用 Top-K 索引复用的方法，但实验部分未包含这些基线。
- **对窗口参数较敏感**：消融显示 W=0 会导致灾难性退化（PPL 716），说明最近窗口保护是一个必要组件而非可选优化；这也在一定程度上削弱了“完全避免全历史搜索”的纯粹性。
- **baseline 配置限制**：Loki 在共享严格预算下性能远差于其论文报告，说明比较结果与预算设定高度相关；论文虽做了说明，但仍可能引起对基线“是否公平”的质疑。
- **硬件细节不足**：端到端多卡实验未报告 GPU 型号、显存占用、能耗等；注意力延迟仅在 L20 单卡上测量，缺少对不同硬件平台的验证。
- **长上下文的实际收益依赖注意力占比**：在非注意力开销占主导的短上下文或低负载场景中，端到端加速有限；随着 KV 逐出等优化普及，ReTopK 的相对优势可能缩小。
- **未讨论理论保证**：论文主要依赖经验验证，没有给出支持集覆盖率的理论界或最坏情况分析。
