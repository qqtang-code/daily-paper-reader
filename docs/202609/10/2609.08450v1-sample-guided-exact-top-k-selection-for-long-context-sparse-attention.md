## 摘要
稀疏注意力通过保留固定大小的索引 token 子集来限制下游注意力计算量，但其独立的精确 Top-K 阶段仍必须处理已物化的分数行，而这些行的长度随上下文增长。生产环境中的基数选择器只有在完成一次完整行遍历后才能发现其首个可操作的边界，从而迫使在精确细化之前再进行一次行规模遍历。我们观察到，定位一个紧凑的上尾所需的分辨率远低于确定精确排名边界，并且当前行的固定步长部分视图在不同不规则长度下仍与对应的完整行排名保持校准。我们提出 HPC-Ops Top-K，一种面向不规则稀疏注意力分数行的采样引导精确选择器。固定步长视图提出行局部粗边界；强制的完整行遍历验证其充分性，形成准入候选集，并在未解决的前沿上启动精确 FP32 细化。嵌套的次级边界和精确恢复会在任何输出提交之前处理未填满的提议，因此采样控制常见路径的工作量，但绝不影响正确性。GPU 实现融合了完整行验证和候选集形成，并在可被图捕获的不规则行调度背后结合了持久化、KV 拆分和直接精确执行。我们在来自 Hy4-Preview 的索引器分数上评估 HPC-Ops Top-K。在 20 种算子配置下，它比最快的已验证外部精确基线快 1.29–1.75 倍，几何平均加速比为 1.55 倍。它在两条源自框架的稀疏注意力轨迹上进一步实现了 1.36 倍和 1.48 倍的加速。该实现已在 HPC-Ops 中提供，这是腾讯面向 LLM 推理的开源高性能算子库，地址为 https://github.com/Tencent/hpc-ops。

## Abstract
Sparse attention bounds downstream attention work by retaining a fixed-size subset of indexed tokens, but its standalone exact Top-$K$ stage must still process materialized score rows whose length grows with context. Production radix selectors discover their first actionable boundary only after a complete-row pass, forcing another row-scale traversal before exact refinement. We observe that locating a compact upper tail requires substantially less resolution than identifying the exact rank boundary, and that fixed-stride partial views of the current row remain calibrated to the corresponding complete-row rank across ragged lengths. We present HPC-Ops Top-K, a sample-guided exact selector for ragged sparse-attention score rows. A fixed-stride view proposes a row-local coarse boundary; the mandatory complete-row pass certifies its sufficiency, forms the admitted candidate set, and initializes exact FP32 refinement over the unresolved frontier. A nested secondary boundary and exact recovery handle underfilled proposals before any output is committed, so sampling controls common-path work but never correctness. The GPU implementation fuses complete-row certification and candidate formation, and combines persistent, KV-split, and direct-exact execution behind graph-capturable ragged-row dispatch. We evaluate HPC-Ops Top-K on indexer scores from Hy4-Preview. It outperforms the fastest verified external exact baseline by $1.29$--$1.75\times$ across 20 operator configurations, with a $1.55\times$ geometric-mean speedup. It further achieves $1.36\times$ and $1.48\times$ speedups on two framework-derived sparse-attention traces. The implementation is available in HPC-Ops, Tencent's open-source high-performance operator library for LLM inference, at https://github.com/Tencent/hpc-ops.

# 论文总结：Sample-Guided Exact Top-K Selection for Long-Context Sparse Attention

## 1. 核心问题与整体含义

- **背景**：长上下文推理中，稀疏注意力（如 DeepSeek Sparse Attention、GLM-5.3、Hy4-Preview 等基于 indexer 的设计）通过只保留固定数量 K 个索引 token 来限制下游注意力计算。但 indexer 会为每个 query 物化一整行 FP32 相关性分数，独立的精确 Top-K 阶段仍须扫描长度随上下文增长的完整分数行。
- **核心痛点**：固定 K 限制了后续注意力开销，却没有限制选择本身——每一行都必须在其完整有效长度 L 上被检查。在数十万 token、大量不规则（ragged）行的场景下，Top-K 仍位于关键路径上。
- **关键瓶颈（生产级基数选择器）**：radix select 必须先用一次完整行遍历构建数字直方图，直方图完成后才能确定 rank K 所在桶，因此流式经过的分数在首次遇到时无法被分类，候选集形成需要**再一次行规模遍历**，即 `Req ≥ 2`，而非理论下限 `Req = 1`。
- **整体含义**：论文指出，定位一个"紧凑上尾"所需的分辨率远低于确定精确 rank 边界；因此可用当前行的廉价部分视图在完整行遍历之前提出粗边界，把采样仅作为**提议机制**而非近似手段，在保持精确语义的前提下把行规模流量压到接近单次扫描下限。

## 2. 方法论

### 2.1 核心思想：提议–认证–精炼三阶段分离

- **观察 1（值空间容差）**：把精确边界下移 ϵ 个相邻分数间隔，保留的上尾仅约增加 ϵ 个值（近似 `C(ϵ) − K ≈ ϵ`），而非按 ϵ 倍增长。实测 100× 误差仅保留中位 1.03K 值，500× 时中位 1.18K、95 分位 2.02K。
- **观察 2（位置空间校准）**：固定步长 s 的部分视图（同一残差类为一个 phase）的第 q 大值在完整行中的 rank 期望约为请求 rank，误差随 s 以平方根速率增长；真实稀疏注意力分数在上尾呈端点聚集（首尾两个十分位含 52–74% 的精确 top-K 索引，均匀假设下仅 20%），进一步降低 14–28% 的 RMS rank 误差。
- **理论支撑**：局部序统计量给出平坦代价区间的解释；有限总体序统计量（exchangeability）给出位置无关的校准基线；连续区间在相位间的均衡分布解释了端点结构带来的额外裕度。

### 2.2 算法流程

- **Phase 1（粗边界定位）**：将 FP32 分数投影为 FP16 的可排序键，取前 11 位得到 2048 个粗 bin（单调且多对一）。按行分配确定性相位 `a_r = π_s(r mod s)`，读取固定步长视图 `V_{r,s}`（约 L/s 个值），构建粗键直方图与前缀计数，以目标 rank `eK = ρK` 定位主边界 `τ0` 与嵌套恢复边界 `τ1`（同一前缀扫描内完成，无需额外采样）。
- **Phase 2（融合验证与候选形成）**：仅做**一次**完整行遍历，用 `τ0` 对应的 FP32 端点直接比较原始分数，同时完成三件事——持久化准入上尾 `A(τ0)`、计数 `C(τ0)` 作为包含性证书、构建前导精确数字直方图 `ĥ0`。依据 **Lemma 4.1**，若 `C(τ) ≥ K`，则所有被准入值不小于被排除值，`A(τ)` 内含一个合法 Top-K 解。
  - **欠填处理**：若 `C(τ0) < K`，先做有界带宽扩展（只追加 `A(τ1)\A(τ0)` 的新增带），仍不足则进入精确粗恢复（全行粗直方图求 `τ*`，只保留边界 bin 作为前沿）。所有路径统一输出 `(E0, Q0, k0, h0)` 接口。
- **Phase 3（精确 FP32 基数精炼）**：把 32 位排序键切为 11+11+10 三段。每轮对当前唯一未决前沿 `Qj` 建直方图与前缀，找到边界数字 `bj`，提交严格优于边界的所有组（`Rj`），丢弃更差组，仅把边界组 `Qj+1` 带入下一位；最后从相同键值的组中补齐剩余配额。**Theorem 4.2** 保证端到端精确性。

### 2.3 关键工程细节

- **复杂度**：认证采样路径每行 `Θ(L/s + L + Σ|Qj| + K)`，行规模流量 `Req = 1 + 1/s`（KV-split 为 `1 + P/s`）；含恢复期望为 `E[Req] = 1 + 1/s + p_band + 2p_exact`。
- **执行映射**：Persistent（一行一个 CTA，按完成顺序领取行，消除跨 CTA 协调）、KV-split（2/4/8 段 CTA + 最后到达者 finisher，用于行数少而行长）、Row-local exact（1024 线程宽 CTA，直接精确路径）、Eight-CTA cluster（8 CTA 硬件簇，经 DSM 协作，用于极少数超长行）。
- **实现要点**：128 位 `ld.global.cg.v4.f32` 向量化加载与下一组预取；复用同一个 2048-bin 共享内存直方图（Phase 1 → Phase 2 → Phase 3 逐位）；候选索引驻留 CTA 数组，溢出写入全局 ping-pong 切片，工作区随固定 worker 池而非 batch 缩放；**shape-stable dispatch** 在 CUDA Graph 捕获前由主机规划器固定 kernel 家族、视图密度、split 数与工作区契约，捕获/重放期间无 host 回读与数据依赖重启动。

## 6. 主要结论与发现

- HPC-Ops Top-K 在全部 **20 种算子配置中均为最快**，相对最快外部精确基线加速 **1.29–1.75×**（128K 列 1.29–1.42×，256K 1.49–1.53×，512K 1.60–1.72×，1M 1.68–1.75×），几何平均 **1.55×**；优势随 N 增大而扩大。
- 框架轨迹上分别取得 **1.36×（245K）** 与 **1.48×（430K）** 加速（对比 SGLang，77.15→56.53 ms 与 233.50→158.12 ms）；score-and-select 集成中 Top-K 段加速 1.51×/1.58×，完整链节省 9.15/13.31 ms。
- 采样增益来源明确：稀疏定位把提议时间从约 18→2 μs（245K）和 33→3.5 μs（430K），解释了 92%/97% 的延迟差；替换提议使整步延迟从 32.8→18.3 ms 与 43.2→24.2 ms。
- 配置膝盖：`eK = 1.5K`、`s = 128`；此时主边界欠填率 0.40%/0.86%，条件恢复再削减 93–96% 的残余精确恢复，且恢复路径延迟降低 61–62%。
- 采样在足够宽的行上才摊销其固定开销，应作为**提议机制**而非 Top-K 近似使用。

## 7. 优点

- **算法与系统解耦干净**：采样只决定常见路径的工作量，正确性由完整行证书 + 精确 FP32 精炼 + 采样无关的恢复路径保证，精确性论证（Lemma 4.1、Theorem 4.2）完整且 rank 通用。
- **洞察有理论支撑**：不只给经验曲线，还用局部序统计量、有限总体序统计量、连续区间余数分布三条理论解释了"容差平坦区""位置无关校准""端点结构增益"。
- **流量下限意识强**：明确提出精确选择 `Req ≥ 1` 的信息论下界，并以 `Req` 作为跨实现的可比轴，避免了不同 radix 位数/桶布局带来的噪声比较。
- **工程完成度高**：四种执行映射 + 图稳定调度 + 复用直方图 + 溢出 ping-pong 工作区随 worker 池而非 batch 缩放，避免 TRT 那种 `2MN` 级别的额外显存预留；代码开源并入 HPC-Ops。
- **实验诚实**：报告了交叉区间、失败点、未验证点，并区分"性能敏感"与"正确性"（所有机制都保留精确完成）。

## 8. 不足与局限

- **数据覆盖窄**：全部评测基于 Hy4-Preview 单一模型的 indexer 分数；未验证其他稀疏注意力模型（如 DeepSeek、GLM-5.3）或合成分布，跨分布泛化性未知。
- **K 固定**：全文固定 K = 2048。作者也承认算法虽 rank 通用，但 `eK`、样本 rank、候选预算、采样/直接精确路由的常数需按 K 重新标定，论文未给出其他 K 的实证。
- **交叉阈值非硬性**：32K–56K 宽度区间结果混合，依赖行数与捕获几何，实际部署需按设备与形状调参，通用性有限。
- **硬件单一**：仅在 H20 上评测，未涉及其他架构（如 Blackwell，而对比的 GVR 正是 Blackwell 工作），SM 数、DSM 能力、内存带宽差异可能改变映射选择。
- **恢复路径仍有长尾成本**：虽然条件恢复把精确恢复率降到 0.015%/0.060%，但欠填行仍需额外扫描；论文未给出最坏情况（对抗性分布导致大量欠填）下的端到端性能
