## 摘要
长输出推理使键值（KV）缓存成为高效 LLM 服务的关键内存瓶颈。现有的 KV 压缩方法通常依赖预先定义的每请求预算，并且仅调整保留哪些 KV 状态，而在整个解码过程中总容量保持不变。然而，推理工作负载表现出显著的需求变化：不同请求需要不同的 KV 容量，并且单个请求的注意力需求会在生成过程中演变。我们提出 GrowPage，一种按需 KV 预算分配框架，将 KV 容量视为运行时资源。GrowPage 维护轻量级的双时间尺度查询摘要，以捕捉近期和长期的注意力行为，并利用它们相对的注意力工作集来估计需求演变。在每个容量边界，GrowPage 要么在当前分配内压缩 KV 状态，要么在出现更大需求时获取一个额外的物理页。通过与 PagedAttention 的页级内存抽象集成，GrowPage 保持了连续批处理和前缀缓存。在多个模型上的推理基准实验表明，GrowPage 相比现有方法实现了更优的性能-吞吐量权衡。

## Abstract
Long-output reasoning has made the key--value (KV) cache a critical memory bottleneck for efficient LLM serving. Existing KV compression methods usually rely on a predefined per-request budget and adjust only which KV states are retained, leaving the total capacity fixed throughout decoding. However, reasoning workloads exhibit substantial demand variation: different requests require different KV capacities, and the attention demand of an individual request evolves during generation. We introduce \textbf{GrowPage}, an on-demand KV budgeting framework that treats KV capacity as a runtime resource. GrowPage maintains lightweight dual-timescale query summaries to capture recent and long-term attention behaviors, and uses their relative attention working sets to estimate demand evolution. At each capacity boundary, GrowPage either compresses KV states within the current allocation or acquires an additional physical page when broader demand emerges. By integrating with PagedAttention's page-level memory abstraction, GrowPage preserves continuous batching and prefix caching. Experiments on reasoning benchmarks across multiple models show that GrowPage achieves a superior performance--throughput trade-off over existing approaches.

## 1. 核心问题与整体含义

- **研究背景**：大型推理模型（如 DeepSeek-R1、Qwen3）通过生成数千乃至数万 token 的长思维链（CoT）来解决数学推理、代码生成等难题，但长输出导致 KV 缓存持续膨胀，成为 LLM 服务中最主要的内存瓶颈。
- **核心问题**：现有 KV 缓存压缩方法（如 H2O、SnapKV、R-KV、G-KV、Zipage 等）普遍依赖**预先定义的每请求 KV 预算**，仅调整"保留哪些 KV 状态"，而**总容量在整个解码过程中固定不变**。
- **关键矛盾**：
  - **请求间异构性**（Observation 1）：不同请求的最小充分 KV 预算差异巨大（Figure 2 显示从 512 到 8K token 甚至"未解决"均有分布）。
  - **请求内时间变化**（Observation 2）：同一请求在解码过程中注意力稀疏度反复在"集中"与"弥散"之间切换（Figure 3），所需历史 KV 信息量本身非平稳。
- **整体含义**：固定预算要么过度供给低需求请求（浪费内存），要么供给不足高需求请求（错误驱逐关键历史）。论文主张将 **KV 容量本身视为运行时决策变量**，而非事先选定的静态预算，从而在异构推理负载下获得更优的性能—吞吐权衡。

## 2. 方法论

### 2.1 核心思想
GrowPage 将每请求 KV 容量作为按需分配的运行时资源，在每个容量边界（capacity boundary）根据注意力需求趋势，在**压缩现有 KV（Compress & Hold）**与**新增一个物理页（Grow by One Page）**之间做二选一决策。

### 2.2 理论分析（第 3.1 节）
- 定义 **p-覆盖注意力需求** $D_p(a_t)$：覆盖注意力质量 $p$ 所需的最小 KV 数。
- 定义**最坏情况 KV 容量** $C^{wc}_\delta(a_t)$：在值向量 $\|v_i\|_2 \le V_{max}$ 假设下，保证注意力输出误差 ≤ δ 所需的最小保留子集大小。
- **定理 3.1**：$C^{wc}_\delta(a_t) = D_{1-\delta/(2V_{max})}(a_t)$，即误差容忍度 δ 等价于保留注意力质量 $1-\delta/(2V_{max})$。**注意力越弥散，所需鲁棒 KV 容量越大**，为在线容量控制提供理论依据。

### 2.3 在线需求估计（第 3.2 节）
- **双时间尺度查询摘要**：对每个请求、每层、每头维护两个 EMA 查询表示（在 RoPE 之前）：
  $$\bar{q}^x_t = \beta_x \bar{q}^x_{t-1} + (1-\beta_x) q_t,\quad x \in \{S, L\}$$
  默认 $\beta_S=0.9$（短期）、$\beta_L=0.999$（长期）。
- **需求趋势信号**：在容量边界构建历史候选集 $C_t$（排除最近一个 KV block），对短期/长期摘要分别做 RMS 校准 + 当前位置 RoPE，计算 Top-p（p=0.99）工作集比率 $r^S_t, r^L_t$，跨层与 KV 头平均后得到
  $$\Delta_t = r^S_t - r^L_t$$
  - $\Delta_t < 0$：注意力趋于集中（可压缩）；$\Delta_t > 0$：工作集扩大（需扩页）。
  - 阈值 $\tau=0$ 时默认选择 Grow by One Page。

### 2.4 趋势引导的容量控制（第 3.3 节）
- **Compress & Hold**：保持当前分配，在每层每头独立选择保留 token，重要性分数为 $s_{i,\ell,h} = \max(a^S_{i,\ell,h}, a^L_{i,\ell,h})$；采用**块局部保留配额 $k_{loc}$（默认 64）+ 全局 Top-K** 混合策略，每次压缩恰好释放 1 个页的 KV 槽位（保留预算由目标容量 $(P_t-1)b$ 推导，而非超参）。
- **Grow by One Page**：从全局空闲页池获取 1 个物理页，追加到请求 block table，解码继续。
- **单调增长策略**：不做主动收缩（避免不可逆 KV 驱逐），双向收缩在附录 H.1 中讨论。

### 2.5 系统集成（第 4 章）
- 预分配查询摘要存储池（大小与序列长度无关，随活跃请求槽复用），在常规解码路径中就地更新；需求估计仅在容量边界触发。
- 直接映射到 PagedAttention 物理页抽象，保持**连续批处理、前缀缓存、CUDA Graph** 兼容。
- 内存压力下**回退到压缩**，并可与现有调度器的抢占/重调度机制协同；继承 Zipage 的异步压缩流水线。

## 6. 主要结论与发现

- **性能—吞吐权衡更优**：相比 FullKV，GrowPage 在 DeepSeek-R1-Distill-Llama-8B 上平均 TPS 提升 **64.3%**，Qwen3-8B 上提升 **60.2%**，同时保持相当的 Pass@1。
- **优于固定预算 Zipage**：在混合负载下（Qwen3-8B），GrowPage 以平均 3442 token 预算达到 84.9% 准确率、2213 tokens/s、C=121，全面超过 Zipage-4096（83.7%、1690 tokens/s、C=100），并接近 Zipage-8192 的准确率（85.1%）但吞吐高约 1.9×。
- **信号有效性**：$\Delta_t$ 与未来注意力需求变化呈强单调关系（ρ=0.78，符号一致率 80.3%）；反事实分析显示容量扩展收益随 $\Delta_t$ 增大而单调上升。
- **开销可忽略**：容量决策相关操作（需求估计、注意力打分、Top-k 选择、KV 压缩等）合计仅占解码时间的 **<0.32%**。
- **策略对比结论**：随机策略（同频率）准确率仅 88.3%、吞吐 2008 tokens/s，显著低于 GrowPage 的 91.4%/2261；反向信号与激进收缩策略均导致更差结果，说明**决策时机与信号方向是关键**。
- **请求级对齐**：GrowPage 对高最小充分预算的请求分配更大自适应容量（尤其 LiveCodeBench 呈单调递增趋势），验证了请求级需求适配能力。

## 7. 优点

- **问题视角新颖**：将 KV 容量从"静态预算"提升为"运行时决策变量"，与 PagedAttention 页级抽象天然契合，抓住了固定预算在异构推理负载下的根本失配。
- **理论支撑扎实**：定理 3.1 将注意力集中度与最坏情况 KV 容量严格联系，为在线容量控制提供可解释依据。
- **信号设计轻量且有效**：双时间尺度 pre-RoPE 查询 EMA + Top-p 工作集比值，避免存储历史查询序列，状态大小与序列长度无关。
- **系统协同良好**：保持连续批处理、前缀缓存、CUDA Graph、异步压缩，具备实际部署价值。
- **实验设计严谨**：频率匹配对照、反事实 NLL 验证、事件级统计、请求级对齐分析，多角度排除替代解释。
- **超参鲁棒性**：$\tau=0$、$k_{loc}=64$ 的默认设置在多个数据集上稳定取得最佳或接近最佳表现。

## 8. 不足与局限

- **模型规模与场景覆盖有限**：仅在 8B 级模型（DeepSeek-R1-Distill-Llama-8B、Qwen3-8B）上验证，未覆盖更大规模模型或多模态/长上下文场景。
- **硬件与部署单一**：实验仅限单张 A100，未讨论多卡张量并行、分布式服务或 KV 卸载场景下的表现。
- **对比基线不完全**：未与 Ada-KV、ThinkKV、LazyEviction、Kara 等近期自适应/推理专用 KV 压缩方法直接对比。
- **主动收缩被放弃**：GROW PAGE-SHRINK 准确率大幅下降（84.2%），说明 GrowPage 保守的单调增长策略虽稳定，但在内存回收灵活性上存在牺牲；文中未探索更精细的可逆压缩机制。
- **系统级代价**：动态扩页引入了 597 次 fallback 和 1361 次抢占事件（虽优于随机策略），在极端内存压力下可能带来调度抖动。
- **超参依赖**：$\tau$、$\beta_S$、$\beta_L$、$k_{loc}$、$p$ 等虽做了敏感性分析，但默认值是否在所有模型/任务上通用仍需更多验证。
- **前缀缓存共享块处理复杂**：压缩时需为目标块分配临时空间，在严重内存压力下可能触发死锁风险（文中提及由调度器抢占规避）。
- **可复现性**：部分数据集（如 LiveCodeBench v1）与 KV 预算配置依赖 Zipage 的设定，复现需参考其代码与配置。
