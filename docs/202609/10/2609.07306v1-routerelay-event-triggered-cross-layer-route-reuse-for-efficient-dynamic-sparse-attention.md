## 摘要
动态稀疏注意力通过在每个 Transformer 层将每个查询块路由到一小组键块，从而降低长上下文预填充成本。稀疏注意力核避免了大多数 token 交互，但路由器仍会逐层重建块-块得分矩阵，即使所选路由变化很小。我们提出 RouteRelay，一种与路由器无关的方法，它仅跨深度复用路由元数据，同时继续使用当前层的查询、键和值计算注意力。锚点层执行完整路由。中间层对先前的 top-$k$ 路由以及一个紧凑的哨兵集合（由近失误和随机探测的块组成）重新评分。仅当某个哨兵对其最弱的已选块构成挑战时，才重新路由该查询行。我们给出了 top-$k$ 稳定性条件、遗漏挑战者的概率界，以及行选择性的 GPU 执行设计。在可复现的经验评估中，RouteRelay 在低、中、高跨层漂移下分别重新路由 25.0%、55.4% 和 78.2% 的行，同时保持至少 99.99% 的路由召回率。在不同路由规模下，随着键块数量从 128 增长到 1024，RouteRelay 在评估 38.4--51.6% 的完整路由得分对的同时保持 100.0% 的召回率。其未融合的 CPU 执行仍慢于稠密矩阵乘法，这暴露出行压缩和账本更新是主要的内核工程目标。

## Abstract
Dynamic sparse attention reduces long-context prefill cost by routing each query chunk to a small set of key chunks at every Transformer layer. The sparse attention kernel avoids most token interactions, but the router still rebuilds a chunk--chunk score matrix layer after layer, even when the selected routes change little. We introduce RouteRelay, a router-agnostic method that reuses only route metadata across depth while continuing to compute attention with the current layer's queries, keys, and values. Anchor layers perform full routing. Intermediate layers rescore the previous top-$k$ route and a compact sentinel set of near-miss and randomly probed chunks. A query row is rerouted only when a sentinel challenges its weakest selected chunk. We give a top-$k$ stability condition, a probabilistic bound on missed challengers, and a row-selective GPU execution design. In a reproducible empirical evaluation, RouteRelay retains at least 99.99% route recall while rerouting 25.0%, 55.4%, and 78.2% of rows under low, moderate, and high cross-layer drift, respectively. Across routing scales, RouteRelay retains 100.0% recall while evaluating 38.4--51.6% of full-routing score pairs as the key-chunk count grows from 128 to 1024. Its unfused CPU execution remains slower than dense matrix multiplication, exposing row compaction and ledger updates as the main kernel-engineering targets.

# RouteRelay 论文详细总结

## 1. 核心问题与研究背景

- **研究动机**：长上下文语言模型的预填充成本主要来自因果自注意力，其计算量随序列长度呈二次增长。动态稀疏注意力通过将每个查询块路由到少量关键块来跳过大部分 token 交互，但**路由器本身仍需逐层重建完整的块-块（chunk-chunk）得分矩阵**。
- **核心观察**：相邻 Transformer 层虽然表示不同，但处理的是相同的 token 位置，往往保留相同的语义依赖关系；当所选路由跨层变化很小时，逐层重建完整路由矩阵是**冗余计算**。
- **关键区分**：复用整个注意力输出会改变模型数值计算（如跨层 KV 共享），而**仅复用稀疏索引集（整数块 ID）**侵入性更小——每层仍用自己的 Q/K/V 计算精确注意力，唯一近似在于索引集是否匹配当前层的真实 top-k 路由。
- **整体含义**：论文主张把"路由构建"与"注意力计算"解耦，为已有动态稀疏路由器（如 MInference、DHSA）提供一种正交的、路由器无关的跨层加速手段。

## 2. 方法论

### 2.1 核心思想
- 在**锚点层（anchor layer）**执行完整路由，存储每个查询行的**路由账本（route ledger）**。
- 在**中间层**只对紧凑候选集重新打分，根据"事件触发"决定该行是否重路由；稳定行直接沿用上一层的路由索引。
- 全程只跨层传递**整数块 ID**，不共享 KV 状态、注意力概率或输出，所有浮点注意力量保持层特定。

### 2.2 关键技术细节

- **路由账本**：每行存储 $\mathcal{L}_i^a = (\mathcal{R}_i^a, \mathcal{C}_i^a, a)$，即 top-k 路由、哨兵集合与锚点层号。哨兵集合包含三类：
  1. $m$ 个紧邻 top-k 截断线之下的最高分块（**近失误哨兵**）；
  2. $r$ 个均匀采样的被遗漏块（**随机哨兵**）；
  3. 强制全局候选（如 attention sink、最近窗口块）。

- **候选重打分**：中间层仅对 $\mathcal{A}_i^\ell = \mathcal{R}_i^a \cup \mathcal{C}_i^a$ 打分。定义最弱已选分 $\alpha_i^\ell = \min_{j\in\mathcal{R}_i^a} S_{ij}^\ell$ 与最强哨兵分 $\beta_i^\ell = \max_{j\in\mathcal{C}_i^a} S_{ij}^\ell$，**当且仅当 $\alpha_i^\ell > \beta_i^\ell + \gamma_i$ 时复用路由**，否则该行执行全量 $n_k$ 打分、替换路由并重建哨兵。刷新决策按行、按层异步进行。
- **迟滞机制（Hysteresis）**：防止在临界点反复刷新，刚刷新的行至少保持一层复用期，并可用更大保护裕度直至锚点裕度恢复。
- **强制锚点**：可在嵌入转换层、每隔 $H_{max}$ 层、或已知路由持久性低的层强制全量路由，以限定陈旧随机哨兵的生命周期。

### 2.3 理论分析

- **Lemma 1（确定性路由稳定性）**：若 $\max_j |S_{ij}^\ell - S_{ij}^a| \le \epsilon_i$ 且锚点裕度 $\Delta_i^a > 2\epsilon_i$，则 $\mathcal{R}_i^\ell = \mathcal{R}_i^a$。因需完整分数行才能计算精确扰动，该引理主要作为分析工具，实际触发器由哨兵承担。
- **随机哨兵遗漏概率界**：若除近失误集外有 $u$ 个遗漏块变得有竞争力，从规模 $N$ 的残差池无放回采样 $r$ 个哨兵，则
  $$P_{miss} = \frac{\binom{N-u}{r}}{\binom{N}{r}} \le \left(1-\frac{u}{N}\right)^r$$
  说明随机哨兵在路由广泛变化（$u$ 大）时最有效，近失误哨兵则针对截断线附近的孤立秩交换。
- **复杂度**：全量动态路由 $T_{full} = O(n_q n_k d)$；RouteRelay 为 $T_{relay}^\ell = O(n_q(k+m+r)d + \rho_\ell n_q n_k d)$，其中 $\rho_\ell$ 为刷新行比例。当 $k+m+r \ll n_k$ 且 $\rho_\ell \ll 1$ 时路由工作量显著下降，而稀疏注意力成本不变。

### 2.4 系统设计

- 路由维护状态由三个行主序张量组成：形状 $[n_q, k]$ 的已选路由、$[n_q, m+r]$ 的哨兵、$[n_q]$ 的锚点年龄。
- 中间层将已选与哨兵 ID 拼接为定宽候选张量，一次性批量打分；通过比较最弱已选分与最强哨兵分得到每行刷新标志，再用**前缀和压缩**不稳定行 ID，仅对压缩后的子集计算完整分数行并更新账本。
- 若没有不稳定行，则完全跳过全量路由器；该方法可插入路由打分与 token 扩展之间，不改动底层路由器的边界构造、因果掩码与稀疏注意力后端。

## 3. 实验设计

- **数据集 / 场景**：论文**未使用任何真实数据集或真实 LLM**，全部为可复现的合成实验。实验使用层演化的 64 维查询/关键块表示，每行有持久偏好块并叠加层局部高斯漂移，通过改变漂移标准差模拟跨层路由稳定性。
- **基准（Benchmark）**：
  - "Route every layer"（逐层精确 top-k）作为召回率参考基准；
  - "Fixed stride 4"（每四层全量刷新一次）作为固定调度对比。
- **对比方法**：
  - 逐层路由 vs. 固定步长 4 vs. RouteRelay（跨层漂移实验）；

  - 不同 key chunk 规模（128/256/512/1024）下的评估分数对比例与 CPU 耗时。
- **评价指标**：top-k 路由召回率、重路由行比例、相对于全量路由的评估分数对比例、CPU 路由墙钟时间。
- **默认配置**：表示维度 64、top-12 路由、12 近失误 + 12 随机哨兵、$\gamma=0$、FP32、取中位数计时。

## 6. 主要结论与发现

- **跨层路由复用可行**：在低/中/高漂移下分别仅重路由 25.0%、55.4%、78.2% 的行，同时保持至少 99.99% 的 top-k 路由召回率；固定步长 4 虽然也只刷新 25% 行，但召回率降至 94.9%（漂移 0.03）和 91.2%（漂移 0.06），说明**事件触发式自适应刷新优于固定全局刷新间隔**。
- **哨兵设计**：仅随机哨兵虽只评估 14.2% 分数对，但召回率仅 92.32%；近失误哨兵是保真的关键（100% 召回，50.8% 分数对）；再叠加随机哨兵或扩大近失误集宽度（24、48）在测试场景下召回率无提升，仅增加计算量，12 个近失误哨兵处于最佳权衡点。
- **规模效应**：key chunk 从 128 增至 1024 时，评估分数对比例从 51.6% 降至约 38%，说明定宽候选集在完整路由矩阵增大时相对更划算；512–1024 之间的平台期表明刷新行的全量路由已成为剩余工作的主要成分。
- **负面系统结果**：未融合 CPU 实现比全量路由慢约 1.6–3.7×（加速比 0.27×–0.61×），因为不规则 gather、刷新标志处理、行压缩与账本重建的开销抵消了算术节省。**算术节省并不自动转化为延迟收益**，需要融合 GPU 内核才能兑现。

## 7. 优点

- **方法层面**：
  - 只复用离散路由元数据而非注意力输出/KV，最大限度保持模型数值行为不变，侵入性低，可与任意动态稀疏路由器正交组合。
  - 行级、事件触发的刷新机制比固定刷新步长更贴合真实的路由稳定性分布（按行、按层自适应分配计算）。
  - 引入迟滞机制与强制锚点，工程上考虑了临界抖动与陈旧哨兵问题。
- **理论与实验设计**：
  - 给出了 top-k 确定性稳定性引理与随机哨兵遗漏概率上界，使"开销-风险"权衡显式化。
  - 提供了行选择性 GPU 内核设计（前缀和压缩不稳定行、跳过无刷新层的全量路由）。
  - **诚实报告负面结果**（CPU 反而更慢），明确指出行压缩与账本更新是后续内核优化目标，学术态度客观。
  - 实验配置完整、多种子平均、可复现性好。

## 8. 不足与局限

- **实验覆盖**：
  - 全部为合成数据，**无真实长上下文数据集、无真实 LLM 端到端评估**，无法证明路由召回率的微小损失不会损害下游语言建模质量。
  - 规模有限（最多 1024 个 key chunk、384 个查询行），与真实 128K 上下文的块规模差距较大。
  - 未与 MInference、DHSA、Quest 等真实动态稀疏系统做端到端对比。
- **偏差风险**：
  - 合成的高斯漂移模型可能无法反映真实注意力路由的漂移结构，实验结果的外部效度存疑。
  - 关键超参（近失误哨兵数、随机哨兵数、保护裕度 $\gamma$）在真实场景下的最优值未知，论文自身也承认消融结果"在此设置下"成立。
