## 摘要
大型推理模型（LRMs）通过扩展的思维链（CoT）生成实现卓越的问题求解能力，但由此产生的键值（KV）缓存随序列长度线性增长，造成严重的内存瓶颈，对于长推理轨迹常常超出 GPU 容量。现有的 KV 缓存压缩方法依赖近期查询来估计未来 token 的重要性，并隐含地假设这些查询可作为未来注意力模式的可靠代理。我们证明，这一假设在长时程推理中并不成立：某些解码步骤会生成思维重访 token（Thought Revisiting Tokens, TRT），这些 token 会重新关注遥远的先前上下文，例如推理轨迹早期形成的任务求解计划。通过系统性分析，我们发现与 TRT 对应的查询在嵌入空间中聚集成少量相似性组。基于这一洞见，我们提出 BeaconKV，一种无需训练的 KV 缓存压缩方法。它维护信标查询——每个全局查询簇的紧凑代表——以预测哪些 KV 对将被重访，而无需存储完整的查询历史。在四个开源 LRM 和多样化的推理基准上，BeaconKV 总体优于现有压缩方法，实现最高 5.8× 的内存降低，同时几乎保持完整缓存的准确率，并将吞吐量提升超过 4.3×。

## Abstract
Large Reasoning Models (LRMs) achieve superior problem-solving through extended Chain-of-Thought (CoT) generation, but the resulting key-value (KV) cache grows linearly with sequence length and creates severe memory bottlenecks, often exceeding GPU capacity for long reasoning traces. Existing KV cache compression methods rely on recent queries to estimate future token importance, implicitly assuming these serve as reliable proxies for future attention patterns. We demonstrate that this assumption fails in long-horizon reasoning: certain decoding steps generate Thought Revisiting Tokens (TRT) that re-attend to distant previous context, such as task-solving plans formulated early in the trace. Through systematic analysis, we discover that queries corresponding to the TRT cluster into a small number of similarity groups in the embedding space. Based on this insight, we propose BeaconKV, a training-free KV cache compression method that maintains beacon queries, compact representatives for each global query cluster, to anticipate which KV pairs will be revisited without storing the entire query history. Across four open-source LRMs and diverse reasoning benchmarks, BeaconKV generally outperforms existing compression methods, achieving up to $5.8\times$ memory reduction while nearly preserving full cache accuracy and improving throughput by over $4.3\times$.

# BeaconKV 论文中文总结

## 1. 核心问题与整体含义

- **背景**：大型推理模型（LRMs，如 o1、DeepSeek-R1、Qwen3 等）通过扩展的思维链（CoT）生成实现强推理能力，但推理轨迹常达数万 token，导致 KV 缓存随序列长度线性增长。
- **问题**：KV 缓存造成严重显存瓶颈。例如 Qwen3-4B 生成 32K token、batch size 为 16 时，KV 缓存本身可超过 77GB，使单张 80GB GPU 逼近极限，限制了 LRM 在受限资源下的部署。
- **现有方法的缺陷**：RPC、R-KV 等压缩方法依赖"近期查询"（observation queries）估计未来 token 重要性，隐含假设近期查询是未来注意力模式的可靠代理。但作者指出，这一假设在长时程推理中失效。
- **关键观察（TRT）**：某些解码步骤会生成"思维重访 token"（Thought Revisiting Tokens, TRT），它们重新关注遥远的先前上下文（如推理早期形成的任务求解计划、问题约束），以维持全局连贯性。这类全局查询在时间上稀疏且不可预测，导致现有方法过早驱逐后续仍被需要的 KV 对。
- **整体含义**：论文揭示长程推理中查询的几何聚类与重访规律，提出免训练的 KV 缓存压缩方案，为降低 LRM 长序列推理的显存与成本提供新思路。

## 2. 方法论

### 核心思想
- 维护一组 **beacon queries（信标查询）**——每个全局查询相似簇的紧凑代表，配合近期查询共同构成 observation query set，用于预测哪些 KV 对会被未来 TRT 重访，而无需保存完整查询历史。

### 关键技术细节
- **查询分类**：局部查询主要关注邻近 key；全局查询对应 TRT，关注远处 key。作者发现全局查询并非随机分布，而是在 pre-RoPE 查询嵌入空间中聚成少量相似性组（用余弦相似度与 PCA 验证）。
- **Continual FPS（持续最远点采样）**：
  - 每个注意力头维护一个有界缓冲区，存放历史 pre-RoPE 查询。
  - 当缓冲区达到上限 `B_max_Q` 时，触发一次 FPS，将其降采样回 `B_min_Q`，只保留几何上最具多样性的查询。
  - 采用"填充—压缩"循环，使 beacon 查询随推理推进持续演化，同时保证显存有界（尤其适用于 GQA 场景）。
  - FPS 以余弦相似度为基础，先选平均相似度最低的查询作为初始点，再贪心选择与已选集合最不相似的查询。
- **查询对齐与 RoPE**：
  - beacon 查询用当前解码步 `t` 的 RoPE 旋转，模拟"若此刻发生 TRT 会访问哪些 key"。
  - 近期查询保留其原始生成位置 `τ` 的 RoPE，维持局部注意力信号。
- **重要性打分与 Max 聚合**：
  - 对 observation query set 计算对当前 KV 缓存的注意力权重。
  - 在 GQA 的 head group 内，对 head 与查询做 **max-pooling**（而非 mean-pooling）。原因是 TRT 稀疏、事件驱动、信号高幅度但罕见，均值会稀释关键信号，max 则能保留任何 beacon 识别出的重要 KV。
- **保留策略**：始终保留前缀 token 与最近 `n_recent` 个 token，剩余预算按分数取 top-K；驱逐后 beacon 与 recent 查询合并再经 FPS 压缩。
- **超参数**：beacon 查询上限 32、下限 16，近期查询 16，KV 预算 `B_min_KV = 7/8 B_max_KV`，达到上限时驱逐 1/8 的输出 token KV。

### 算法流程（文字描述）
1. Prefill 阶段：全部 KV 入缓存，各头对 pre-RoPE 查询序列做 FPS 初始化 observation set。
2. Decoding 阶段：新查询持续追加到 observation set；达到 `B_max_Q` 时用 FPS 压缩回 `B_min_Q`。
3. 当 KV 缓存接近上限时，固定 beacon 查询并收集 recent 查询。
4. 达到 `B_max_KV` 时，构造 `Q_obs`（beacon + recent），计算注意力权重，按 max 聚合打分，保留前缀、最近 token 与 top-K，驱逐其余 KV。
5. 合并并重新压缩查询集，进入下一轮循环。

## 6. 主要结论与发现

- **TRT 现象真实存在**：全局查询跨层、跨头出现，重新关注早期计划与约束，是维持长推理连贯性的关键行为。
- **全局查询具有几何聚类结构**：在 pre-RoPE 空间中聚成少量相似组，可用 beacon 查询紧凑表示。
- **BeaconKV 总体优于现有压缩方法**，低预算区间优势最大；相对现有方法最大精度提升达 **31.7 个百分点**（Qwen3-14B、AIME24、预算 1024）。
- **效率提升**：峰值显存从 77.0GB 降至 13.3GB（**5.8×**），吞吐从 82.3 提升至 356.4 tokens/s（**>4.3×**），解码延迟从 5573.4s 降至 1287.3s。
- **匹配预算下**：与 RPC 系统效率相当，但精度更高（2K 预算 +6.3 分，1K 预算 +12.3 分）。
- **Max 聚合优于 Mean 聚合**，低预算下差距更明显。
- **平衡配置 (16 recent, 16 beacon) 取得最佳精度-延迟权衡**；过度偏向 beacon 会损害局部上下文并增加延迟。
- **动态捕捉全局查询模式是关键**：仅保留初始查询（Initial+Recent）不足以解释增益。
