## 摘要
键值（KV）缓存压缩是降低大语言模型（LLM）推理内存开销的有效方法，尤其适用于长上下文工作负载。然而，现有压缩方法在准确率、推理延迟和峰值KV缓存内存利用率之间做出不同权衡，使得单一固定配置难以适用于不同提示和资源约束。我们提出MetaKV，一种自适应框架，它根据用户指定的延迟和峰值内存预算，为每个输入提示选择KV缓存压缩配置。MetaKV使用轻量级预测模型来估计每个候选配置的端到端延迟、峰值内存和正确响应的概率，并选择在保持准确率的同时最好地满足延迟-内存约束的配置。我们在涵盖数学、科学、常识推理和阅读理解的四个数据集上，评估了MetaKV在来自三种代表性KV缓存压缩方法（KVQuant、H$_2$O和RocketKV）的十种配置以及未压缩FP16配置上的表现。在广泛的延迟和峰值内存约束范围内，MetaKV始终优于最佳静态配置，将约束成功率（CSR）——即在同时满足两个约束的情况下正确回答的提示比例——平均提高约0.07，最高提高0.135。这些结果证明了将KV缓存压缩适配到单个提示以及延迟-内存约束的益处。代码见 https://github.com/MichaelWang0505/MetaKV.git

## Abstract
Key--value (KV) cache compression is an effective way to reduce the memory overhead of large language model (LLM) inference, particularly for long-context workloads. However, existing compression methods make different trade-offs among accuracy, inference latency, and peak KV cache memory utilization, making a single fixed configuration unsuitable across different prompts and resource constraints. We introduce MetaKV, an adaptive framework that selects a KV cache compression configuration for each input prompt based on user-specified latency and peak memory budgets. MetaKV uses lightweight prediction models to estimate the end-to-end latency, peak memory, and probability of a correct response for each candidate configuration, and selects the configuration that best satisfies the latency-memory constraints while preserving accuracy. We evaluate MetaKV across ten configurations from three representative KV cache compression methods, KVQuant, H$_2$O, and RocketKV, together with an uncompressed FP16 configuration, on four datasets covering mathematics, science, commonsense reasoning, and reading comprehension. Across a wide range of latency and peak memory constraints, MetaKV consistently outperforms the best static configuration, improving constrained success rate (CSR), the fraction of prompts answered correctly while satisfying both constraints, by approximately 0.07 on average and up to 0.135. These results demonstrate the benefit of adapting KV cache compression to individual prompts and latency-memory constraints. Code is available at https://github.com/MichaelWang0505/MetaKV.git

# MetaKV：面向受限 LLM 推理的自适应 KV 缓存压缩 —— 论文中文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：大语言模型（LLM）广泛用于对话助手、代码生成等场景，长上下文推理中 KV 缓存可占用高达 **80% 的 GPU 显存**，成为推理效率的核心瓶颈。
- **现有方法分类**：KV 缓存压缩分为无损与有损两类；由于无损压缩节省有限，本文聚焦**有损压缩**，涵盖三大代表方向：
  - **量化**（KVQuant）：降低 KV 值的比特精度，峰值内存最低，但量化/反量化带来**高延迟**；
  - **Token 驱逐**（H₂O）：按累积注意力分数丢弃不重要 token，延迟低，但保留值精度高、峰值内存偏大；
  - **稀疏注意力**（RocketKV）：两阶段剪枝 + 稀疏注意力，延迟较低，但在部分任务上精度损失明显。
- **核心矛盾**：三类方法在**准确率、端到端延迟、峰值 KV 内存**之间做出不同权衡，**不存在单一固定配置在所有提示与资源约束下都最优**。
- **部署环境差异**：边缘设备（如手机）受限于峰值内存，交互式客服机器人受限于延迟，不同场景偏好不同压缩策略；且不同数据集（数学、科学推理等）下各方法相对表现也会翻转。
- **整体含义**：提出 **MetaKV**——按**单个输入提示**与用户给定的延迟/峰值内存预算，自适应选择最合适的 KV 缓存压缩配置，在满足约束的前提下最大化回答正确率。

## 2. 方法论

### 2.1 核心思想
- 将压缩配置选择建模为**带约束的逐提示决策问题**：给定用户约束 $L_{\max}$（最大端到端延迟）与 $M_{\max}$（最大峰值内存），在候选配置池中选出最可能正确回答且满足双重约束的配置。

### 2.2 候选配置池（10 种）
- 未压缩 FP16；
- KVQuant：2-bit / 3-bit / 4-bit；
- H₂O：保留 20% / 40% / 60% token；
- RocketKV：8× / 16× / 32× 压缩比。

### 2.3 关键技术细节与流程
1. **资源预测**：用 **LightGBM** 对每个候选配置预测端到端延迟 $\hat{L}_c$ 与峰值内存 $\hat{M}_c$。
2. **预算过滤（Budget Filter）**：剔除 $\hat{L}_c > L_{\max}$ 或 $\hat{M}_c > M_{\max}$ 的配置。
3. **选择逻辑（逻辑层级）**：
   - 若 **未压缩 FP16** 通过过滤 → **直接选中**（因其无信息损失、总体精度最高）；
   - 否则，在每种方法内**仅保留压缩最轻的设置**（尽量保留信息）；
   - 若只剩一个候选 → 直接选中；
   - 若仍有多个 → 用 **Accuracy LightGBM** 预测各配置正确概率，选最高者。
4. **执行**：选中的配置与提示送入 Hugging Face Transformers 推理引擎生成响应。
5. **无可行配置时的回退**：计算相对违规分数
   $$v_c = \hat{L}_c / L_{\max} + \hat{M}_c / M_{\max}$$
   选择违规最小者，若并列则用精度模型打破平局。

## 3. 实验设计

- **模型**：Meta Llama 3.1 8B。
- **数据集（4 个，覆盖不同能力）**：
  - **GSM8K**（数学）、**HellaSwag**（常识）、**ARC-Challenge**（科学推理）、**SQuAD 1.1**（阅读理解）。
- **数据规模**：每个数据集采集 2,048 条提示，按 85%/15% 划分，测试集每数据集 308 条，**共 1,232 条评测提示**。
- **评测指标**：
  - 准确率（生成任务用精确匹配，多选用最低负对数似然选答案）；
  - 端到端延迟、峰值 KV 缓存内存；
  - **约束成功率 CSR**：
    $$\text{CSR} = \frac{1}{N}\sum_{i=1}^{N} \mathbb{I}(\text{correct}_i \wedge \ell_i \le L_{\max} \wedge m_i \le M_{\max})$$
- **对比基线**：
  - **STATIC BASELINE**：对每个 $(L_{\max}, M_{\max})$ 约束对，在训练集上选 CSR 最高的单一固定配置，在测试集评估；
  - **ORACLE**：完美预测下的理论上界（只要存在物理满足约束且回答正确的配置即计成功）。
- **约束网格**：延迟 ∈ {2s, 5s, 10s, 50s} × 峰值内存 ∈ {5, 10, 30, 80 MB}，并选取 4 组代表性约束做深入分析（紧延迟/松内存、松延迟/紧内存、中等、宽松）。

## 6. 主要结论与发现

- **MetaKV 在所有测试的约束对上均优于最佳静态配置**，∆CSR 平均约 **0.07**，最高 **0.135**。
- **峰值内存 30 MB 阈值下增益最大且最稳定**（∆CSR 0.10–0.13）；最紧的 5 MB 内存约束下平均提升约 0.06；最紧的 2s 延迟约束下提升约 0.073。
- **在 80 MB 峰值内存下**，延迟从 50s 收紧到 2s 时增益从 0.01 升至 0.052，说明内存宽松时 MetaKV 有更大空间按延迟敏感度换配置。
- **自适应机制有效**：
  - 紧延迟/松内存时，MetaKV 把违规率从 45.9% 降至 35.8%，精度仅降 2.2 个百分点；
  - 紧内存/松延迟时，精度提升 5.3 个百分点，违规率仅增 3.1 个百分点；
  - 中等约束下精度提升 10.6 个百分点，违规率仅增 0.9 个百分点。
- **违规主要源于配置池限制而非预测错误**：ORACLE 也会违规高达 35%，MetaKV 违规率仅比 ORACLE 高 0–6 个百分点；精度仅比 ORACLE 低 0.2–1.8 个百分点。
- **配置选择随约束动态变化**：松约束下 74.9% 用 FP16；紧延迟下 FP16 降至 63.6%，转向 H₂O 60% 与 RocketKV；紧内存下 FP16 仅 18.5%，分散到 H₂O 20%、KVQuant 2-bit/4-bit。
