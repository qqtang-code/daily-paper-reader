## 摘要
当智能体会话运行到一百万 token 且同时驻留许多会话时，KV 缓存以及为其排序的索引位于主机内存中，而为 top-k 步骤对所有 n 个键进行排序的扫描成为限制解码的流量。我们提出 Fathom，一种键扫描方法，其中每个查询决定读取每个键通道的多少位。4 位 K 缓存按通道主序以位平面形式存储，因此 t 个位平面的前缀恰好是该通道的 t 位量化器，查询通过对其通道的方差加权重要性进行反向注水来花费其位预算。在 Qwen3-8B 上的一百万 token 时，一个解码步骤在 GPU 时间上比 Double Sparsity、Loki 和 SparQ r=32 的 136 位扫描快 1.67 倍；而在与 SparQ 的 68 位读取（r=16）相同的 GPU 时间内，Fathom 读取的字节数少 18%，并在七种模型和上下文设置中的六种上具有更低的注意力误差。在 RULER 风格任务上，每一次逐 token 扫描都与精确 top-k 解码匹配；在真实编码智能体会话中，Fathom 以 92 位达到最准确的 136 位扫描的步骤一致率。其存储是量化服务栈已经持有的 4 位 K 副本，并且当索引驻留在 GPU 内存中时，该方法并不更快。

## Abstract
When agentic sessions run to a million tokens with many sessions resident at once, the KV cache and the index that ranks it live in host memory, and the scan that ranks all n keys for a top-k step becomes the traffic that bounds decoding. We present Fathom, a key scan in which each query decides how many bits of each key channel to read. The 4-bit K cache is stored channel-major as bit planes, so a prefix of t planes is exactly the channel's t-bit quantizer, and the query spends its bit budget by reverse water-filling over the variance-weighted importance of its channels. At one million tokens on Qwen3-8B a decode step is 1.67x faster in GPU time than with the 136-bit scans of Double Sparsity, Loki and SparQ r=32, and in the same GPU time as SparQ's 68-bit read (r=16) Fathom reads 18% fewer bytes with lower attention error on six of seven model and context settings. On RULER-style tasks every per-token scan matches exact top-k decoding, and on real coding-agent sessions Fathom reaches the step agreement of the most accurate 136-bit scan at 92 bits. The store is the 4-bit K copy a quantized serving stack already holds, and the method is not faster when the index is resident in GPU memory.

# Fathom 论文结构化总结

## 1. 核心问题与研究动机

- **背景场景**：编码/浏览类智能体会话可持续运行数十万乃至百万 token，大部分内容是被缓存的 KV 而非新生成内容；单台服务器同时承载大量此类会话。
- **瓶颈转移**：KV 缓存已无法与权重共置于 GPU 显存，被卸载到主机内存或更慢的存储层。解码步骤因此由跨互连（PCIe）传输的数据量决定。
- **稀疏解码的固有矛盾**：top-k 稀疏注意力只取分数最高的 k 个键值，但**分数在读之前未知**，因此所有方法都必须先扫描全部 n 个键的廉价表示来排序。
  - 示例（Qwen3-8B，32k token）：稠密注意力每步读 4.8 GB；top-k 的 winner 行约 200 MB 且不随上下文增长；而 136-bit 的扫描项随上下文线性增长，1M token 时达 5.1 GB。
  - 即 **scan 项随 n 线性增长，winner 行项不增长**，成为长上下文多会话下的主瓶颈。
- **现有方法的共性缺陷**：Loki、Double Sparsity、SparQ、thumbnail 等都**预先固定每个通道的读取位深**（r 个坐标、c 个通道、或全通道 2-bit），无法按查询自适应分配位预算。
- **论文定位**：在"KV 缓存与索引均在主机内存"这一特定但现实的 regime 下，让**读深度由每个查询、每个通道自行决定**。

## 2. 方法论

### 2.1 核心思想
- 两个观察支撑：
  1. 量化误差每增加 1 bit 下降 4 倍。若通道 j 读到深度 tⱼ，多读 1 bit 带来的剩余分数误差下降正比于 gⱼ·4^(−tⱼ)，gⱼ 为该通道对分数方差的贡献。按边际价值分配比特即**反向注水（reverse water-filling）**，且有闭式解。
  2. 若 4-bit K 缓存按**通道主序存为位平面**，则某通道前 t 个平面恰是其 t-bit mid-rise 量化器（同一 block scale），**前缀读取是精确的、连续的，无需额外低精度副本**。

### 2.2 关键技术细节

- **位平面 K 缓存（§3.2）**
  - 键一次性量化为 4-bit：每通道均匀对称码，每 64-token 块一个 fp16 scale。
  - 块最大绝对值 a_{β,j}=max|k|，格宽 s_{β,j}=a/8；码 c = clip(⌊k/s⌋, −8, 7)+8 ∈ [0,16)，码 8 为零，MSB 为符号位。
  - 位 p 的 64 个码打包进一个 64-bit 字 P_{β,j,p}（plane），通道主序存储使 P_{·,j,0..t−1} 在序列上连续。
  - 读前 t 平面得到 c(t)=c≫(4−t)，反量化值恰为 t-bit mid-rise 量化器；t=4 时退化为原 4-bit 码。
  - 存储开销：每 token 每 KV head 68 字节（4-bit 码 + fp16 block scale）。

- **逐查询读深度（§3.3）**
  - 重要性权重：gⱼ = Σ_h (q(h)ⱼ)² · Var(kⱼ)，其中 Var(kⱼ) 在标定键上一次性测得。
  - t-bit 量化的误差方差 ∝ a²_{β,j}/(3·4ᵗ)，故通道 j 的期望分数平方误差 ∝ gⱼ·4^(−tⱼ)，总量为 Σⱼ gⱼ·4^(−tⱼ)。
  - 在 Σ tⱼ ≤ B 下最小化该误差即反向注水：
    - **tⱼ = clip(round(log₄(gⱼ/θ)), 0, 4)**，且 Σ tⱼ ≤ B。
  - 水位线 θ 通过 **30 步 log θ 二分**求解（取满足预算的最小 θ）；tⱼ=0 的通道完全跳过。
  - 计划由共享同一 KV head 的 G 个 query head 共用，K 字节只读一次。
  - 与 SparQ 的两点差异：用 key 方差加权 q 而非仅按 |qⱼ| 排序；深度是**分级**而非全有全无。
  - 实测：均值 48 bit 时约触碰 128 个通道中的 30–34 个，各 1–4 个平面。

- **逐层预算（§3.4）**
  - flat budget（所有层相同 B）vs 贪婪 per-layer plan（按"每比特误差下降最大"分配，Bℓ∈{24,…,128}）。
  - 结论：per-layer 在 Qwen3 上 16k 有助、32k 减弱，在 Qwen2.5-7B 与 Llama-3.1-8B 上变差；**推荐默认使用 flat budget**（无需标定、无上下文长度依赖）。

- **基底规则（§3.5）**
  - 有 QK-norm 的模型（Qwen3）：分数方差天然集中于原始通道，旋转反而抬高误差 → **用原始通道**。
  - 无 QK-norm 的模型（Llama-3.1-8B、Qwen2.5-7B/1M）：用标定键 KLT 特征基旋转后**方差不集中** → **用旋转后的平面**。
  - 旋转变体存 (k−μ)V 的平面，gⱼ = Σ_h ((q(h)V)ⱼ)²·λⱼ；与 Loki 不同，**不做截断**，所有 D 个坐标都存，查询自行决定读多深。

- **主机驻留存储的读取（§3.6）**
  - 逐字读取 mapped host memory 受限于小散事务；改为**连续 run 的 gather**：每通道前 tⱼ 个平面是一段连续 tj·n/8 字节，gather kernel 每次拷一段到 staging buffer，扫描在 HBM 内进行。
  - run list 固定大小（每通道一槽，非活跃槽长度为 0），无需主机同步。

- **兼容性说明**：布局要求每通道标量码的位前缀是更粗的量化器。兼容均匀整数格式（KIVI 的 per-channel 码、INT8）；不兼容非均匀码（KVQuant LUT、TurboQuant 的 Lloyd–Max 与随机旋转）；FP8 因前缀是符号+指数位，需实测边际增益。

    - RULER 分数标准误达数个百分点，逐 token 扫描之间差异未确立。
    - 卸载时序表基本为 batch 1（仅一处 batch 2 检查），而论文动机中的"多会话"情形是**从索引大小论证而非实测**。
    - 128k 以上的时序使用**合成 KV 内容**（真实模型无法 prefill 百万 token）。
    - 128k 的 instruct 模型未套用 chat template，绝对分数偏低（作者声明不影响方法间比较）。
    - landmark 基线是 ShadowKV 块均值在"主机驻留索引"设定下的复现，并非 ShadowKV/Quest 自身设定；未与 RetroInfer/MagicPIG 类 CPU 侧检索比较。

## 6. 主要结论与发现

- **目标 regime 的实测加速**：1M token、KV 与索引在主机内存时，解码步 GPU 时间比 136-bit 扫描（Double Sparsity/Loki/SparQ r=32）快 **1.67×**，比 block landmark 快 **2.50×**，比 2-bit thumbnail 快 **3.12×**（wall-clock 分别为 1.38×/2.07×/2.59×）。256k 时对 32 通道扫描为 1.37×。
- **匹配 GPU 时间下的字节/精度优势**：与 SparQ r=16（68 bit）同耗时，Fathom 少读 **18%** 字节，在 7 个设置中 6 个（用两种计划中较优者则 7 个）注意力误差低
