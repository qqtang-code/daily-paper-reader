## 摘要
在混合专家（MoE）模型的单GPU长上下文推理中，需要将键值缓存（KVCache）卸载到CPU内存。溢出的KV有两个互补用途——传输到GPU进行注意力计算，或在CPU上就地计算——二者要求相反的物理状态。二者之间的最优划分随工作负载变化，而现有KVCache抽象仅对单一物理状态的单体对象提供存储语义，无法表达动态负载均衡。我们提出InplaceKVCache，这是首个在写入时即固定每个字节物理驻留位置的KVCache抽象，从而无需在放置后移动数据即可调整CPU-GPU负载均衡。它通过沿设备亲和性与访问模式两个维度构建四区域布局来实现这一点，将负载均衡转化为纯调度问题。基于该抽象，WriteScope沿序列维度划分CPU-GPU份额，并使用可移植的roofline性能模型在序列长度变化时确定最优CPU份额，同时通过在线反馈跟踪CPU成本漂移。在三个MoE模型（DeepSeek-V2-Lite、Qwen3-30B-A3B、Mixtral-8×7B）上，在32 GB显存预算下，WriteScope支持总计100万token规模的端到端推理。在长上下文场景（≥8K）中，相较于四个复现基线，它在A100上取得1.5×–2.5×、在V100上取得1.4×–1.7×的几何平均加速；而vLLM、SGLang和KTransformers即使将KV预算加倍仍会失败。一个DeepSeek-V4-Flash案例研究验证了其与原生稀疏注意力的组合能力。

## Abstract
Single-GPU long-context inference with Mixture-of-Experts (MoE) models requires spilling the key-value cache (KVCache) to CPU memory. The spilled KV serves two complementary purposes---transferring to the GPU for attention computation, or computing in-place on the CPU---which demand opposing physical states. The optimal split between them varies with workload, yet existing KVCache abstractions offer only storage semantics over a monolithic object of a single physical state, and cannot express dynamic load balancing. We propose InplaceKVCache, the first KVCache abstraction whose format fixes each byte's physical residency at write time, so that the CPU--GPU load balance can be adjusted without moving data after placement. It realizes this as a four-region layout along two dimensions---device affinity and access pattern---turning load balancing into pure scheduling. Built on this abstraction, WriteScope splits CPU--GPU shares along the sequence dimension, and a portable roofline performance model determines the optimal CPU share as sequence length evolves, with online feedback tracking CPU cost drift. On three MoE models (DeepSeek-V2-Lite, Qwen3-30B-A3B, Mixtral-8$\times$7B) with a 32~GB VRAM budget, WriteScope supports end-to-end inference at the 1M-token aggregate scale. In the long-context regime ($\ge$8K), it achieves geometric-mean speedups of $1.5\times$--$2.5\times$ on A100 and $1.4\times$--$1.7\times$ on V100 over four reproduced baselines, while vLLM, SGLang, and KTransformers fail even with a doubled KV budget. A DeepSeek-V4-Flash case study validates composition with native sparse attention.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：单 GPU、预算受限、隐私优先的场景（个人机或本地服务器）正成为 MoE 模型的重要部署形态，单用户长上下文推理（长程智能体、持久记忆对话、并行 rollout）成为核心需求。
- **核心矛盾**：MoE 模型的权重与长上下文 KVCache 总量远超单卡显存。例如 Qwen3-30B-A3B 在 128K 上下文下至少需 78 GB，远超 32 GB 显存；实测三个模型在 128K 聚合 token 下显存需求达 32 GB 卡的 1.2×/2.4×/3.6×，溢写不可避免。
- **为什么溢写 KV 而非权重**：实验表明把 vLLM 的 KV 预算从 2 GB 提升到 11 GB、把更多专家权重推到 CPU，反而使 prefill 延迟 +53%、decode 延迟 +51%；专家 GEMM 算术强度远高于注意力，因此**应溢写 KV 而非权重**。
- **溢写 KV 的双重用途冲突**：
  - **加载**（GPU-centric）：KV 经 PCIe 传回 GPU 做注意力，受 PCIe 带宽限制；
  - **原地计算**（CPU-centric）：KV 留在 DRAM 由 CPU 核计算，受 CPU 算力限制。
  - 二者物理状态要求**相反**：GPU 加载要求 pinned + 逻辑连续（否则 DMA 带宽崩塌），CPU 计算要求 unpinned + 按 head 组织（否则 CPU 读惩罚）。
- **最优划分随负载漂移**：Qwen3 上最优 CPU 份额可在 0–0.625 之间变化，无固定划分可覆盖。
- **AF overlap 在 MoE 下失效**：原有"FFN 阶段 CPU/PCIe 空闲、可预取下一层 KV"的前提被 MoE 打破——专家参数驻留 CPU，FFN 阶段 CPU 与 PCIe 已被专家计算/加载占满。实测 SolidAttention 预加载使注意力延迟 33.7→74.2 ms（2.2×），H2D 带宽 25.4→14.9 GB/s（0.6×）；ScoutAttention 预计算使注意力 1.36×、专家侧 1.43×。
- **根本症结**：现有 KVCache 抽象只提供**单一物理状态的单体对象的存储语义**（store/retrieve），"哪些字节归 CPU、哪些归 GPU"不在其词汇表中；事后重组代价随上下文增长爆炸（2K→64K 时每层每步准备流水线 3.5 ms→185.9 ms）。

## 2. 方法论

### 核心思想：写入时原则（Write-time Principle）
- **一个字节只有唯一的最终物理驻留位置，且该位置在写入时确定**；物理归属成为数据格式的属性，而非运行时机制；负载均衡因此退化为纯调度，放置后数据永不移动。

### InplaceKVCache：四区域格式
- 沿两个正交维度——**设备亲和性 × 访问模式**——把 KVCache 切为四个区域：
  - **CPU × 计算** → unpinned compute region（CPU 原地计算）
  - **CPU × 传输** → pinned load region（H2D 源，cudaHostAlloc）
  - **GPU × 传输** → D-window offload region（新 KV 暂存）
  - **GPU × 计算** → ping-pong compute region（流式加载、覆盖复用）
- 每个区域内部按固定大小块组织；块是路由、暂存、驱逐、传输的统一粒度。

### 写入时路由流程
- **Prefill**：KV 批量生成，写入时一次性路由到最终区域；整段 prefill 无需均衡（每层 KV 生成即被消费，且走空闲的 D2H 方向）。
- **Decode**：新 KV 先暂存于 GPU D-window，参与 GPU 计算（零 H2D 成本）；累积到 **D=256**（块大小整数倍）后整批驱逐到 unpinned 或 pinned 区域，方向由 roofline 策略决定。
- D2H 回写走在空闲的全双工 PCIe 上，被专家阶段隐藏；D 在 256–1024 范围内稳态开销不变，因此 D 是**路由粒度而非决策单元**。
- 已放置批次永不再动；ping-pong 采用覆盖复用（块大小与骨架不变，只换数据），CPU 侧保有全量备份，覆盖不丢数据。
- 两侧部分输出经 **LSE（log-sum-exp）重标定**精确合并，CPU 只回传部分输出与归一化项（远小于原始 KV），由 GPU 执行合并。

### 接口语义（框架无关）
- `PartitionSpec`：记录 roofline 参数、四区域、块粒度、驱逐批大小。
- 四个操作：`init`（划分并预分配）、`append`（写入时路由）、`views`（零拷贝视图）、`flush`（按比例把 D-window 卸载到 pinned/unpinned）。
- 四条保证：(i) 无临时单体状态；(ii) 物理隔离，各引擎只读自己区域；(iii) 零拷贝（非稀疏场景）；(iv) 精确性（不引入压缩/稀疏化）。
- pinned 区域的 pin 操作被提前一个驱逐窗口调度，不在关键路径上。

### WriteScope 调度：序列维切分 + Roofline
- **沿序列维而非 head 维切分**：序列轴使比例连续，head 切分受 GQA（Qwen3 仅 4 个 KV head）量化粗、MLA 共享 latent 下定义不清。两引擎都覆盖全部 head，只在不相交的序列区间上工作。
- **解析模型**（每 token 的 CPU 读成本 A、GPU 传输成本 B、固定开销 C_CPU/C_GPU）：
  - `T_CPU(r) = r·A·L + C_CPU`
  - `T_GPU(r) = (1−r)·B·L + C_GPU`
  - 端到端延迟 `T = max(T_CPU, T_GPU) + T_merge`（merge 与 r 无关，不影响最优解）
- **最优份额**：令 T_CPU = T_GPU 得
  - `r(L) = min(1, max(0, B/(A+B) + Δ/((A+B)·L)))`，其中 Δ = C_GPU − C_CPU。
  - B/(A+B) 决定长序列收敛值，Δ/((A+B)·L) 刻画短序列过渡；clamp 到 0/1 处理极端配置。
- **在线反馈**：B 由格式保证恒定（ping-pong 块形状固定）只需离线标定一次；A 随工作集与缓存局部性漂移，需在线跟踪（每步滑窗采样 CPU 侧延迟反推 A，256 步跨多层即可准确估计）。
- **操作化**：不冻结固定份额，而是保持**边际份额 p = B/(A+B)** 恒定；累积份额 `R(L) = p + (R(L0) − p)·L0/L` 以每批 D/L 的速度收敛，初始份额由离线标定给出，误差在最初几批内衰减。
- **稀疏兼容**：块对齐格式天然支持块级 top-k；load region 中预留 staging buffer 将选中块聚成一段连续数据，一次满带宽 DMA；gather 带宽（35.1 GB/s）高于 H2D（25.4 GB/s），可被流水线隐藏。

### 实现
- 自定义融合 **AVX-512 CPU 注意力核**：stride-aware 直接索引分区视图（零拷贝），分数不落内存、在线 softmax、fp32 累加于 L1；MLA 变体利用解耦结构（q 侧投影 + 输出侧展开，8-token tile 共享压缩 latent，L1 命中）。
- 运行时复用 HuggingFace Transformers 作骨架，替换所有计算路径；专家侧用 CPU–GPU 分层调度（IPEX AVX-512），KV 与专家权重由统一联合分配模型管理。
- 代码规模：约 2.2K 行 Python（路由 + 调度器）、1.2K 行 C++（CPU 注意力）、2.1K 行 DeepSeek-V4 稀疏核，共享 5K 行底座；移植到 vLLM/SGLang 估计需约 5K 行。
