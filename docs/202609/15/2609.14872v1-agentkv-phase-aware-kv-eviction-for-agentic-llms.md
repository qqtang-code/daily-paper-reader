## 摘要
智能体服务所消耗的 token 数可能比聊天机器人工作负载高出若干数量级，从而给 KV 缓存容量和解码时带宽都带来压力。大多数 KV 驱逐方法会以取自最近 token 的代表性查询来为缓存键打分，并假设未来的注意力与近期注意力相似。我们表明，智能体生成违背了这一假设：未来的查询是 think、act、tool 及其他阶段的混合，主角度分析表明这些成分占据可测量地不同的查询子空间，因此近期代表性查询会系统性地低估即将到来的阶段所需要的键。我们提出 AGENTKV，它为每个阶段维护一个小型查询缓冲区，并基于这些查询的并集为缓存键打分。我们进一步在持久化多轮服务路径中实现 AGENTKV，该路径跨轮次携带压缩的 KV 状态，并在线压缩保留的 KV 页。在两个模型、六个任务领域以及每种三个 KV 预算下，AGENTKV 相比 R-KV 平均提升任务得分 5.5 分，相比 Tri-attention 提升 5.3 分。相对于上游 full-KV SGLang，AGENTKV 将输出 token 吞吐量最高提升至 1.80 倍。代码：https://github.com/LiuTaowen-Tony/agentkv。

## Abstract
Agentic serving can consume orders of magnitude more tokens than chatbot workloads, stressing both KV-cache capacity and decode-time bandwidth. Most KV-eviction methods score cached keys against representative queries drawn from the most recent tokens, assuming future attention resembles recent attention. We show that agentic generation violates this assumption: future queries form a mixture over think, act, tool, and others phases, and principal-angle analysis shows these components occupy measurably different query subspaces, so recency representatives systematically undervalue keys that upcoming phases will need. We propose AGENTKV, which maintains a small query buffer per phase and scores cached keys against their union. We further implement AGENTKV in a persistent multi-turn serving path that carries compressed KV state across turns and compacts retained KV pages online. Across two models, six task domains, and three KV budgets each, AGENTKV improves task score by 5.5 points on average over R-KV and 5.3 over Tri-attention. Relative to upstream full-KV SGLang, AGENTKV improves output-token throughput by up to 1.80x. Code: https://github.com/LiuTaowen-Tony/agentkv.

## 1. 核心问题与研究动机

- **背景**：智能体（agentic）推理正成为 LLM 的核心用例，但服务成本远高于单轮聊天。论文引用数据指出，智能体工作负载的 token 消耗可达传统聊天负载的 **1000 倍**，导致序列长度与 KV 缓存压力剧增。
- **成本来源**：智能体需跨多轮交替执行若干**循环阶段**——推理（think）、动作生成（act）、工具返回（tool）以及系统提示/工具描述/用户问题（others）。KV 缓存容量与解码期显存带宽因此成为吞吐与延迟的主要瓶颈。
- **现有方法的隐含假设**：主流 KV 驱逐/压缩方法（H2O、StreamingLLM、SnapKV、R-KV 等）都属于"查询中心"范式，用**最近 token 中的代表性查询**去估计未来查询分布，即假设"未来注意力≈近期注意力"。
- **核心发现（问题所在）**：智能体生成违反该假设。未来查询实际是 think/act/tool/others 四个阶段的**混合分布**，主角度（principal angle）分析证明各阶段查询占据可测量地不同的子空间。因此基于近期代表性的估计会产生**系统性偏差**，低估即将到来的阶段所需要的键。
- **整体含义**：论文将 KV 驱逐重新表述为"估计未来查询分布"的问题，指出在非平稳的多轮智能体场景下，代表查询应当覆盖**阶段混合**而非仅覆盖最近上下文；并进一步把该策略落地为可在真实服务路径中生效的持久化多轮缓存机制。

## 2. 方法论

### 2.1 核心思想
- 将 KV 驱逐形式化为按期望注意力排序键：`A_i = E_{q∼p̂(q)}[softmax(qᵀK/√d)_i]`，其中 `p̂(q)` 是对未知未来查询分布 `p(q)` 的估计。
- 近期代表性方法取 `p̂(q) = p_recent(q)`，仅在查询分布平稳时可靠。
- AgentKV 取 `p̂(q)` 为**四阶段查询分布的混合**：为每个阶段维护小型查询缓冲区，用其**并集**为候选键打分。

### 2.2 关键技术细节
- **在线阶段解析器（Algorithm 1）**：基于 tokenizer 可见的 chat-template 标记做确定性解析（`<|im_start|>system/user → others`、`<think> → think`、`<tool_call> → act`、`<tool_response> → tool`），使用滚动前缀处理被切分到多个解码 token 的标记。无需模型侧分类器，不引入新特殊 token。
- **分阶段查询缓冲区**：每阶段一个固定大小 FIFO 队列，各存 ⌈q/4⌉ 条最近查询；压缩事件 e 时取并集 `Q(e) = Q_think ∪ Q_act ∪ Q_tool ∪ Q_others`，且 `|Q(e)| ≤ q`，与近期基线的代表预算**严格对齐**。
- **打分与淘汰（Algorithm 2）**：所有候选键在**同一池**中打分，不按阶段划分键、不设每阶段键配额。每个候选 token 的得分为其在并集代表查询下的平均注意力，保留 top-B，其余驱逐；受保护索引（attention sink）得分置为 -∞ 强制保留。每 128 个解码 token 触发一次压缩。
- **服务感知实现（§3.4 + Algorithm 3）**：面向持久化多轮推理，压缩后的 KV 状态需跨工具调用与后续用户轮次复用。实现包含：将保留 KV 收集写入紧凑目标槽位、把被驱逐页归还分配器、仅在拷贝完成后重定向 page table。通过**物理长度与单调递增逻辑长度分离**来保持 RoPE 偏移与后续前缀扩展正确性；兼容 chunked prefill、CUDA graph capture 与常规解码路径。

### 2.3 诊断性分析（支撑方法的两条证据链）
- **主角度分析**：对每个（层，KV 头）分别做，将阶段跨度 s 的查询矩阵 `X_s` 做薄 SVD，取前 k=5 个右奇异向量构成正交基，用 `cosθ_i = σ_i(V_{s,k}ᵀ V_{t,k})` 计算跨阶段与阶段内（不同步）的主角度。结果显示**跨阶段角度系统性大于阶段内角度**。
- **效用覆盖率（utility coverage）**：定义候选 token 的未来效用 `U_i = Σ_{j>i_comp} a_{j,i}`（仅离线可得，作为 oracle 诊断），阶段 φ 的覆盖率 `UC_φ = Σ_{i∈R_φ} U_i / Σ_{i∈K_φ} U_i`。近期代表保留了大量 think/act 效用，但严重漏掉早期 tool 效用；多阶段代表显著提升 tool 覆盖率。

## 6. 主要结论与发现

- **机制层面**：智能体的未来查询分布是阶段混合的、非平稳的；跨阶段查询子空间主角度显著大于阶段内，近期代表估计存在系统性偏差。
- **效用覆盖**：多阶段代表将 tool 阶段覆盖率从 **0.042 → 0.175**（B=512）、**0.117 → 0.416**（B=1536），证明阶段感知打分能召回被近期策略忽略的有用 token。
- **任务质量**：相比 R-KV 平均 **+5.5 分**，相比 Tri-attention **+5.3 分**；最大且最一致的增益出现在 BFCL `multi_turn` 与 τ² retail / 32B telecom 的**中间预算**处。
- **代表选择消融**：在完全匹配的设置下，阶段感知代表比同等数量的近期查询平均 **+4.2 分**（12 个设置）。
- **阶段必要性**：移除任一阶段缓冲区都会掉分（Full 40.0 → 移除 others 最低 35.5），说明四阶段提供互补覆盖。
- **鲁棒性**：标签噪声导致性能**渐进下降**而非崩溃（30% 损坏仍优于匹配 R-KV 的 27.0）；四阶段划分在固定 q 下优于更粗或更细的划分。
- **跨家族迁移**：在 Nemotron 上，较大预算处仍稳定优于匹配近期选择（B=3072 +4.5，B=4096 +4.0），最小预算受容量限制为 −1.0。
- **服务吞吐**：相比上游 full-KV SGLang，输出 token 吞吐最高 **1.80×**（H100 NVL，Qwen3-32B，32k/1k）；16k/1k 受益于减少解码期 KV 读取，32k/1k 受益于释放显存页带来的更高并发。
- **统计结论**：36 个对比中，AgentKV 相对 R-KV 有 **15/36**、相对 Tri-attention 有 **16/36** 获得 CI 支持；**0/36** 出现基线获 CI 支持的反向增益，其余为未分辨。
- **质量–吞吐前沿**：在全部 6 个匹配的 workload–预算设置中，AgentKV 同时取得最高点估计任务质量与最高吞吐；batch=16 时吞吐为 Tri-attention 的 1.18–1.22×、R-KV 的 1.61–2.08×。
