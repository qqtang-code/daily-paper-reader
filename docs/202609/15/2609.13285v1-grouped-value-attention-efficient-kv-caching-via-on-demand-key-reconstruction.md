## 摘要
KV 缓存是 Transformer 解码的主要瓶颈：其内存占用和缓存读取流量随序列长度增长。分组查询注意力（GQA）通过共享键值头降低这一开销，但仍在每一步存储键和值。我们提出分组值注意力（GVA），它存储分组值，并用学习到的线性映射重建内容键。在推理时，该映射可被吸收到查询中，从而在预期的解码路径中无需物化内容键。一个小的共享解耦 RoPE 通道通过单独缓存的位置键保留位置信息。在所研究的配置中，相对于匹配的 GQA，这种表示将持久缓存标量减少约 45-47%。在 3.5 亿参数规模、使用 300 亿 FineWeb-Edu token 时，16 维位置变体在五项任务上达到 44.18 的平均准确率，而 GQA 为 44.36，MLA 为 43.88。这些结果表明，在更紧凑的缓存表示下，基准准确率接近 GQA。为了将这种紧凑表示转化为更快的自回归推理，我们开发了自定义解码内核，目前正在评估其端到端推理性能，并计划很快开源发布。

## Abstract
The KV cache is a primary bottleneck for Transformer decoding: its memory footprint and cache-read traffic grow with sequence length. Grouped-query attention (GQA) reduces this cost by sharing key-value heads, but still stores both a key and a value at every step. We introduce Grouped Value Attention (GVA), which stores grouped values and reconstructs content keys with a learned linear map. At inference, the map can be absorbed into the query, eliminating the need to materialize content keys in the intended decode path. A small shared decoupled RoPE channel retains positional information through a separately cached positional key. For the configurations studied, this representation reduces persistent cache scalars by approximately 45-47% relative to matched GQA. At the 350M-parameter scale with 30B FineWeb-Edu tokens, the 16-dimensional positional variant reaches 44.18 average accuracy across five tasks, compared with 44.36 for GQA and 43.88 for MLA. These results demonstrate near-GQA benchmark accuracy with a more compact cache representation. To translate this compact representation into faster autoregressive inference, we have developed custom decoding kernels and are currently evaluating their end-to-end inference performance with an open-source release planned soon.

  - MQA 只保留一个共享 KV 头，压缩大但质量/训练稳定性可能受损。
  - GQA 在查询头分组基础上共享 KV 头，质量接近 MHA，但仍需同时缓存 grouped K 和 grouped V。
  - MLA 将 K/V 压缩到联合低秩 latent，进一步缩小缓存，但引入额外投影和更复杂解码路径。
- **论文整体含义**：提出 **Grouped Value Attention, GVA**，只持久缓存分组 Value，并用学习到的线性映射按需重建内容 Key；推理时把该映射吸收进 Query，从而避免物化内容 Key。目标是在保持接近 GQA 精度的同时，将持久缓存标量减少约 **45–47%**。

## 2. 方法论

### 核心思想

- 在 GQA 分组结构上，H 个 query head 共享 G 个 value head。
- 不再缓存独立的 grouped key，而是只缓存 grouped value。
- 每个 query head 使用一个学习到的线性映射，从对应 value group 重建内容 key：
  - \(K_h = V_{g(h)} M_h\)
  - 其中 \(M_h \in \mathbb{R}^{d_h \times d_n}\)，\(d_n\) 为内容 key 宽度。
- 推理时 \(M_h\) 固定，可吸收到 query：
  - \(\tilde{q}_h = q_h M_h^\top\)
  - 内容分数变为 \(\tilde{q}_h v_{j,g(h)}^\top\)，无需显式生成 key。
- 标准 RoPE 会破坏该吸收，因为旋转依赖缓存位置，无法折入单一 query。因此采用 **解耦 RoPE**：内容切片不旋转，位置切片单独旋转并共享缓存。

### 关键技术细节

- **Value-only 内容缓存**：内容路径只存 grouped value，不存内容 key。
- **每 query head 一个重建映射**：GVA 只缓存 G 个 value 流，但可产生 H 个不同的内容 key 表示，恢复头级 key 多样性。
- **共享解耦 RoPE 通道**：
  - 内容 key：\(k^{nope}_{j,h} = v_{j,g(h)} M_h\)
  - 位置 key：\(k^{rope}_j = (x_j W_r) R_j^\top\)
  - 位置 key 跨头共享，宽度为 \(d_r\)，每 token 只增加少量缓存。
- **注意力分数**：
  - \(qk_j^\top = q^{nope}(k^{nope}_j)^\top + q^{rope}(k^{rope}_j)^\top\)
  - 第一项仍可吸收；第二项使用已缓存的旋转位置 key，保持相对位置信息。
- **缓存大小**：
  - GQA：\(N_{GQA} = 2 T G d_h\)
  - GVA + 解耦 RoPE：\(N_{GVA} = T(G d_h + d_r)\)
  - 比例：\(\frac{N_{GVA}}{N_{GQA}} = \frac{1}{2} + \frac{d_r}{2G d_h}\)
- **初始化尺度匹配**：
  - 若默认初始化，\(K = VM\) 的初始尺度可能远低于 Q，导致注意力近似均匀。
  - 论文令 \(M_{ij} \sim \mathcal{N}(0, \sigma_Q^2 / (\sigma_V^2 d_{in}))\)，使 K 与 Q 初始 RMS 大致一致。
  - 可选配合 query RMSNorm。

### 算法流程（文字版）

1. 当前 hidden state 投影得到 query 和 value。
2. 将 query 拆为不旋转内容切片和旋转位置切片。
3. 将当前 value 追加到 grouped value 缓存。
4. 计算当前 token 的旋转位置 key，并追加到共享位置 key 缓存。
5. 对每个 query head：
   - 将内容 query 吸收为 \(\tilde{q}_h = q_h^{nope} M_h^\top\)。
   - 用 \(\tilde{q}_h\) 与缓存 value 做内容打分。
   - 用旋转 query 与共享位置 key 做位置打分。
   - 两项相加后 softmax，再对缓存 value 加权求和得到输出。
6. 整个预期解码路径不需要物化内容 key 张量。

## 6. 主要结论与发现

- **共享 KV 失败**：直接令 \(K=V\) 可将缓存减半，但训练 loss 始终高于 GQA，说明单一向量难以同时承担 key 和 value 角色。
- **线性重建有效**：用 \(K_h = V_{g(h)} M_h\) 重建内容 key，可在接近 GQA 的质量下显著压缩缓存。
- **尺度匹配重要**：默认初始化会使重建 key 尺度偏小，早期注意力接近均匀；尺度匹配初始化可改善早期训练轨迹。
- **解耦 RoPE 兼容吸收**：共享位置 key 只需少量额外缓存，就能在保留位置信息的同时支持解码时吸收 \(M\)。
- **精度结果**：
  - 正文 Table 2 中，GVA + DRoPE \(d_r=16\) 平均准确率 **44.35**。
  - GQA 为 **44.36**。
  - MLA 为 **43.88**。
  - GVA scale-matched + Q-norm 为 **44.41**，是表中最强 GVA 行。
  - 注意：提供的元数据摘要中写 16 维变体为 **44.18**，与正文摘要和 Table 2 的 **44.35** 不一致，可能是提取或版本差异。
- **缓存收益**：
  - 相对 GQA，DRoPE GVA 在 \(d_r=16\) 时约节省 **47%**。
  - 在 \(d_r=24\) 时约节省 **45%**。

## 7. 优点

- **方法简洁**：只改 key 的来源，不改变 GQA 的分组骨架，易于与现有 GQA 模型结构结合。
- **缓存压缩直接**：只缓存 value，内容 key 通过线性映射按需重建，理论缓存减少接近一半。
